# W33 — расход сервера в простое

Томас 10.11: VPS без пользователей занимает около ядра процессора. Пакет согласован Тэнком
10.11 с условиями: сохранить сопоставимый замер до и после, объяснить источники, проверить,
что восстановление, доставка и переключение слотов не ухудшились. Цель 0,3–0,4 ядра —
гипотеза, а не обещанный результат.

## Метод замера

`infra/host/prod-idle-measure.sh` (только чтение; `fifth-test op prod-idle-measure 300`):

- CPU всего VPS из `/proc/stat` за окно: user (user+nice), system (system+irq+softirq), steal;
- запуски проверок здоровья — события Docker `exec_start` за окно, по контейнерам;
- прирост `pg_stat_statements` по каждой базе (ключ — роль, база, запрос).

Окно 300 с. Сравнение до и после — при одинаковом составе запущенных сред (prod, test-1,
test-2, мониторинг: 26 контейнеров).

Проверки здоровья по контейнерам: тестовые postgres/nats/valkey/agent — каждые 3 с
(~94 за 300 с), prod postgres/nats/valkey и ядра — каждые 5 с (~58), web и Garage —
каждые 10 с (~30).

**Почему outbox: 1 выборка в секунду, а не 9,5.** Число 9,5/с в первом сообщении было ошибкой:
накопленный счётчик `pg_stat_statements` делился на время работы сервера, хотя счётчик
копится с неизвестного момента (статистика переживает перезапуски). Замер прироста даёт
ровно 300 выборок outbox за 300 с — одна в секунду. Но пустой проход — это транзакция из
7–8 запросов (BEGIN, SET LOCAL statement_timeout, три set_config контекста, выборка,
захват, COMMIT), а опрашивают четыре задачи: публикация outbox (1 с), повторная рассылка
(1 с), вебхуки (2 с), почта (5 с) — отсюда ~22 запроса в секунду на среду без всякой работы.

**Что известно о причинах.** Время исполнения запросов в базах мало (≈0,4 % ядра);
system-время выше user-времени, а в списке процессов постоянно видны короткоживущие `runc`
— это согласуется с ценой запусков проверок здоровья (процесс в контейнере на каждую, у ядра
ещё и запуск `node`). Доля каждого источника отдельно не измерена: короткий опыт с
остановкой test-1 (1,21 → 0,91 ядра за 60 с) показывает разницу в этом опыте, но не доказывает
одинаковую стоимость трёх сред.

## Что изменено (`ad4dec6`)

- Пустые очереди спят: пауза удваивается до `QUEUE_IDLE_MAX_MS` (10 с), работа, отказ и
  пробуждение возвращают интервал. Сигнал M175 после фиксации вставки будит опрос сразу.
- Проверки здоровья: ядро 10 с, остальные 30 с, retries 3, быстрый старт (`start_interval`
  2 с, `start_period` 60–120 с).
