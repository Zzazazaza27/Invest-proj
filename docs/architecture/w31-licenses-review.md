Черновик Мауса от 10.11.2026 по условию Тэнка: перечень компонентов, условий и спорных
вопросов. Решения Томаса от 10.11 внесены (раздел «Решения»). **Обязательства ещё не проверены
по фактической поставке** — это работа ниже; ничего не объявлено выполненным автоматически.
Юридическую оценку, если понадобится, — в `docs/product/legal-research-task.md`.

Срок: до допуска пользователей (решение Томаса 10.11: не раньше декабря).

## К разбору

### 1. sharp / libvips — LGPL-3.0-or-later (образ ядра)

- Что: `@img/sharp-libvips-*` (10 пакетов в lock) и составные `@img/sharp-*` (4).
- **Фактически в образе ядра** (сверено 10.11 по `fifth/core:pin-check`, `/app/node_modules/@img`):
  `sharp-libvips-linux-x64`, `sharp-libvips-linuxmusl-x64`, `sharp-linux-x64`,
  `sharp-linuxmusl-x64`, `sharp-wasm32`. Варианты musl и wasm32 на Debian, по всей видимости,
  не используются. **Сейчас не удаляются** (Тэнк 10.11): сначала сверка фактической поставки и
  совместимости сборки («Работа по поставке», п. 2), затем отдельное решение.
- Где: ядро, обработка изображений (аватар, медиа проекта).
- Условия LGPL-3.0 для библиотеки, связанной динамически и не изменённой: текст LGPL и GPL,
  уведомление о её использовании, возможность заменить библиотеку своей версией, исходный код
  этой версии (или указание на него) **при передаче** программы.
- По решению 1 серверные сборки никому не передаются: обязанности LGPL при передаче для
  образа ядра не возникают. Подтвердить по фактической поставке, что libvips в браузерную
  статику не попадает («Работа по поставке», п. 2).

### 2. Manrope — OFL-1.1 (статика кабинетов)

- Что: `@fontsource-variable/manrope`, файлы шрифта в собранной статике. Веб-шрифт
  **загружается в браузер каждого пользователя** — это передача копии.
- Условия OFL — обязательные, прямо записаны в
  [официальном тексте](https://openfontlicense.org/open-font-license-official-text/):
  уведомление об авторских правах и текст лицензии сопровождают шрифт (вместе с ним или в
  доступной документации); шрифт не продаётся сам по себе; изменённая версия не носит
  зарезервированное имя.
- Вопроса «выполнять ли» нет. Есть работа по поставке: проверить, что эти сведения
  доходят вместе со статикой, и при отсутствии — добавить (раздел «Работа по поставке»).

### 3. Средства сборки (не поставляются)

- lightningcss — MPL-2.0 (14 пакетов под платформы): только сборка CSS, в образ и статику сам
  не попадает. MPL — файловая копилефт: обязанности при передаче изменённых файлов MPL.
  Предположение «не поставляется» опирается на SBOM — см. «Работа по поставке», п. 2.
- @swc/core — Apache-2.0 AND MIT: разрешительные, только сборка.

## Решения Томаса (10.11.2026)

1. **5Э — онлайн-сервис и таким остаётся.** Установка у клиентов и передача им серверных
   сборок не предусматриваются. Обязанности «при передаче» для серверных образов (LGPL у
   sharp/libvips в ядре, GPL у Knot и т. п.) поэтому не возникают.
   **Браузерная статика разбирается отдельно:** JavaScript кабинетов и веб-шрифт передаются
   пользователю при каждом открытии страницы — это передача копий, и условия их лицензий
   выполняются в поставке.
2. **Отдельное приложение «Сторонние компоненты и лицензии».** Ссылка — внизу «Условий
   использования»; из кабинетов — через «О платформе». Отдельной ссылки на главной нет,
   отдельной галочки при регистрации нет, с уведомлением о cookies не смешивается.
   Необходимые тексты (уведомления об авторстве, тексты лицензий, OFL шрифта) включаются в
   поставку.
3. **Общего запрета менять AGPL-компоненты нет** (Garage, Zabbix). Когда понадобится конкретное
   изменение — тогда разбираются условия и принимается решение. Сейчас компоненты ради этого не
   заменяются и не переделываются.
4. **Сопровождение обновлений** — отдельный процесс (агент сопровождения технологий, F-003;
   требования 11.5). Основа для него — реестр компонентов: этот разбор и SBOM комплекта
   (`sbom/`). Пока процесс не реализован: **Маус** собирает сведения и готовит предложения,
   **Тэнк** проверяет и фиксирует согласованное, **Томас** принимает существенные решения.

## Работа по поставке — Маус

Обязательства ещё надо проверить по **фактической** поставке, а не по lock-файлу.

1. **Статика:** что реально уходит в браузер (состав бандлов кабинетов и шрифты) — и какие из
   поставляемых компонентов в неё попадают. По этому списку собрать тексты для приложения
   «Сторонние компоненты и лицензии» (решение 2): уведомления об авторстве и тексты лицензий
   компонентов в бандлах, OFL шрифта. Сборщик сейчас уведомления не переносит — добавить их в
   поставку.
2. **Сверка фактического состава** образа ядра (`node_modules` после prune) и бандлов статики с
   SBOM; что libvips в статику не попадает; совместимость сборки при возможном исключении
   лишних вариантов libvips — до любых изменений состава.
3. **Опись содержимого образов** (системные пакеты, программы сторонних образов): базовый разбор
   перед открытием — условие Тэнка; выбор сканера можно отложить (идея 109 — сканирование
   образов выпуска).
4. **Приложение «Сторонние компоненты и лицензии»** — экран и ссылки по решению 2: после
   сверки состава (п. 1), отдельной работой с показом Томасу.
