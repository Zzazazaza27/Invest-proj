# W08b — технические журналы: план (на «ок» Томаса)

Блок 8, задание 4 (8.4) и анализ ошибок по журналам из 8.2. Реализация и
испытания — на локальном стенде; изменения VPS — отдельным шагом после них.
Ошибки браузера (8.4 «Ошибки интерфейса») — отдельное задание после W08b,
обязательный незакрытый пункт диагностики MVP.

## Состояние VPS (чтение 2026-11-02)

- journald постоянный, 1,9 ГБ с 2026-08-21; явного лимита нет (системный
  потолок 4 ГБ); подавления частоты за 7 суток нет; время синхронизировано.
- Поток ~59 МиБ/сутки (в формате export), из них SSH ~29 МиБ (перебор
  паролей), ufw ~4 МиБ, ядро ~40 КиБ — **журнала запросов ядра нет**.
- Docker — `json-file` без лимита (postgres 51 МБ); Caddy пишет в journald
  только служебные сообщения, журнала запросов нет; nginx Hestia — выключен;
  exim и dovecot — файлы с ротацией.
- **Найдено:** nginx `web` пишет строку запроса с query (одноразовый токен) и
  referer, в том числе в журнал ошибок; PostgreSQL пишет значения в
  сообщении, DETAIL, CONTEXT, параметрах и тексте запроса. Прекращается
  **отдельной правкой до W08b** — `docs/runbooks/log-secrets-fix.md` (ветка
  `fix/log-secrets-at-source`, проверено локально, VPS — по «ок» Томаса).

## 1. Источники и защита секретов — до первой записи

Один поток — journald. Секрет убирается **в самом источнике**, до записи;
архиватор дополнительно проверяет, но не является основной защитой.

| Источник                    | Риск                                                  | Мера в источнике                                                                                                                                                           |
| --------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Ядро (новый журнал)         | заголовки, тела, query, тексты ошибок библиотек и SQL | только разрешённые поля: метод, шаблон маршрута, статус, длительность, код результата, ID запроса, версия; SQL — код SQLSTATE; маскировка в общем механизме журналирования |
| Caddy (журнал запросов)     | query, cookie, `Authorization`                        | JSON-журнал с фильтрами полей: `query` — удаление параметров, cookie и авторизация — удаление заголовков                                                                   |
| nginx `web`                 | query, referer, строка запроса в журнале ошибок       | отдельная правка: путь без аргументов, без referer; журнал ошибок — `crit`                                                                                                 |
| postgres                    | значения в сообщении, DETAIL, CONTEXT, STATEMENT      | отдельная правка: ERROR/WARNING не пишутся, `terse`, без текста запроса и параметров                                                                                       |
| exim, dovecot               | адреса, темы                                          | адреса — нужны для почтовых проверок (служебные письма); тело и тема не пишутся — подтвердить `log_selector`; ссылки восстановления в журнал не попадают                   |
| MinIO, NATS, Valkey, Zabbix | сообщения библиотек                                   | проверить испытанием, при находке — уровень/фильтр источника                                                                                                               |
| ОС                          | аргументы процессов, DNS                              | не собираем; SSH, sudo, выпуски, ufw — да                                                                                                                                  |

Проверка: искусственный секрет в пароле, cookie, заголовке, теле, query,
ссылке восстановления, SQL-ошибке и исключении библиотеки — отсутствует в
journald, выводе контейнеров и архиве.

**Накопленная история** (до включения мер) — **чувствительный архив**:
отдельный бакет `tech-logs-legacy`, свой ключ шифрования, без доступа у
обычного поиска (чтение — отдельной учёткой и явным флагом). Сохраняется как
есть, не удаляется; её безопасность задним числом не гарантируется — истечение
найденного токена не доказывает безопасность остальных записей. Реальные
значения в отчёты и примеры не выносятся.

## 2. Архив и восстановление после прерванной отправки

- Хранилище — отдельный бакет `tech-logs` в имеющемся MinIO. **Ограничение:**
  тот же VPS — независимой защиты нет; переносится на внешнее S3 по блоку 7.
- Порция — раз в минуту: `journalctl --after-cursor -o export`, сжатие,
  шифрование (пароль `LOGS_ARCHIVE_CRYPT_PASS` в `.env` → входит в комплект
  ключей W07; проверка восстановления W07 расшифровывает выборку порции).
- Имя порции детерминировано: источник + ID журнала + первый и последний
  номер записи (seqnum). Метаданные объекта: интервал, курсоры, число
  записей, **SHA-256 исходной порции до сжатия и шифрования** и SHA-256
  объекта.
- **Повтор.** Курсор сохраняется после подтверждения S3. Перед записью —
  проверка объекта с тем же именем: нет — запись; есть и исходный хеш совпал —
  порция уже в архиве, курсор продвигается (повторное шифрование даёт другие
  байты, поэтому сравнивается исходный хеш, не объект); есть и не совпал —
  **конфликт**: без перезаписи, источник останавливается, тревога.
- **Потеря локального состояния.** Порции перечисляются из S3 и
  выстраиваются по номерам записей; продолжение — с конца **последней
  непрерывной** цепочки от начала архива (следующая порция начинается
  ровно за предыдущей), а не с самого позднего объекта. Порции за разрывом
  отмечаются и сверяются при повторном чтении (совпал исходный хеш —
  пропуск).
- **Версия объекта.** Версии бакета хранят прежнее содержимое, но под тем же
  ключом может появиться новая версия. Каталог фиксирует для каждой порции
  `VersionId` и хеши; поиск, скачивание и восстановление читают **именно эту
  версию**, не «последнюю по ключу». Испытание: повторная запись того же ключа
  не меняет результат чтения ранее подтверждённой порции.
- **Каталог** — производный: суточные части, запись через временный объект и
  подтверждение; незавершённая или испорченная часть пересобирается из
  метаданных порций.
- Доступы MinIO: архиватор — запись и чтение без удаления (версии бакета
  включены, удаление версий запрещено политикой — поддержку версий нынешним
  MinIO на одном диске проверить первым испытанием; у Garage их нет, D-001); поиск — отдельная учётка
  только на чтение.
- Потеря: следующий курсор недоступен в journald (вытеснен) — пробел с
  интервалом, сигнал, запись в каталоге «потеряно», а не успех.
- Файлы exim/dovecot — закрытыми поколениями после ротации (`.1`, `.gz`),
  изменяющийся файл не копируется.
- Накопленное: journald с 2026-08-21 и файловые поколения — разовая выгрузка
  в `tech-logs-legacy` с отчётом о покрытых интервалах и пробелах; локальная
  очистка — только после подтверждённого чтения архива.

## 2а. Ручная копия на ноутбук

**`backup:pull` технические журналы не забирает** — бакеты `tech-logs*` вне
ежечасного комплекта W07; это фиксируется в `docs/runbooks/backup.md`.

- Упаковка: после закрытия суток минутные порции собираются в **суточный
  пакет** (свой объект, исходные хеши порций внутри); минутные порции
  остаются — удаления нет. Пакеты уменьшают число **скачиваемых** объектов
  (~365 в год вместо ~525 тыс.); на VPS объектов не меньше: ~525 тыс.
  минутных порций плюс пакеты.
- `node scripts/logs.mjs pull [--legacy] [--to <каталог>]` — добавочно:
  суточные пакеты, которых нет на ноутбуке, **и все подтверждённые минутные
  порции, ещё не вошедшие в пакет** (текущие сутки и закрытые, чей пакет не
  собран). Копия отстаёт от архива не больше чем на одну порцию; когда пакет
  собран, его минутные порции на ноутбуке сверяются с ним и больше не
  качаются.
- Состав — по **всем** квитанциям из S3, включая квитанции на версии,
  которых в архиве уже нет: это свидетельство утраты. Каждый отрезок до
  последней ожидаемой записи покрыт точной подтверждённой порцией (отдельно
  или внутри исправного пакета) либо учтённой отметкой потери; иначе — «копия
  НЕ сошлась».
- Опись копии (граница, квитанции с хешами и причинами потерь, квитанции
  пакетов) хранится рядом, зашифрованной ключом архива:
  `logs-archive.mjs verify-copy --to <каталог>` проверяет копию без доступа
  к S3 и даёт тот же вердикт. Проверка: SHA-256 каждого файла, расшифровка, исходный хеш и число
  записей каждой порции.
- Вердикт различает «данные сохранены полностью» и «копия сошлась, есть
  учтённые потери». Если порция утрачена на сервере, но лежит в пакете на
  ноутбуке, сервер отметит «утрачено в архиве», а копия — нет; обратной
  заливки с ноутбука в архив нет.
- Ключ: пароль архива — из комплекта ключей W07, открытого закрытым ключом
  Томаса (как `check-backup-restore.mjs`); отдельного хранения ключа нет.

## 3. Наблюдение за сбором (Zabbix)

Файл состояния архиватора, как у W07; нет файла или он устарел — значение
«неизвестно» (не прежние нули).

- свежесть: последняя успешная порция, время файла состояния и счётчиков;
- очередь: записи и байты за курсором; отставание > 5 мин — проблема;
- запас времени до заполнения буфера и лимита journald при текущем притоке;
- пропуски (пробелы курсора), конфликты повторов, ошибки S3;
- подавление journald (`Suppressed N messages`) и занятость journald против
  лимита;
- счётчики ошибок: по компонентам и кодам, доля 5xx, отказ внутри 2xx, OOM,
  аварийные завершения;
- суточный снимок объёма по источникам и прирост за сутки/неделю/месяц —
  отдельным файлом в архиве (не в сокращаемой истории Zabbix); нет снимка
  более 26 ч — проблема; сигнал роста — приток за час втрое выше среднего за
  7 суток и не меньше 100 МиБ.

**Сделано (локально, 03.11.2026).** Архиватор после каждого прохода, в том
числе неудачного, пишет `metrics.json` в `LOGS_STATE_DIR`: код сбоя
(`s3`, `conflict`, `ambiguity`, `journal`, `other`), очередь и отставание,
потери по причинам, пропуски архива, счётчики последнего часа (запросы,
5xx, отказ внутри 2xx, ошибки по компонентам и кодам, OOM, аварии,
подавление journald), приток за час и среднее за 7 суток, занятость journald
и запас до заполнения (лимит — `LOGS_JOURNAL_MAX_BYTES`), снимок объёма.
Счётчики считаются при подтверждении порции и сохраняются вместе с её
курсором — повтор не считает дважды. Снимок объёма суток по источникам
пишется при сборке пакета объектом `volume/<журнал>/<день>.json`.
Проверки и тревоги — `scripts/lib/logs-metrics-zabbix.mjs`, подключены в
`monitoring.mjs`; на VPS агент читает файл через `/rootfs` без нового
монтирования. Текстов ошибок и сообщений журнала в файле нет. Ошибка
предобработки Zabbix показывает начало файла — там только числа и коды.

## 4. Место — после замера

2–3 ГБ/год — предварительно, по потоку без журнала ядра. После включения
журналов на стенде замерить: обычная работа и всплеск
(`scripts/load-test.mjs`), байт на запрос, сжатие. Учесть: минутных порций
~525 тыс./год (объекты и каталог) и суточные пакеты — тот же объём второй
раз (архив на VPS ×2, на ноутбук — ×1); бакеты `tech-logs*` в ежечасный
комплект W07 не входят, его рост от журналов — только ключ в комплекте
ключей. Стартовые лимиты VPS: journald
`SystemMaxUse=4G`, `SystemKeepFree=15G`, без срока по возрасту; буфер 1 ГБ;
окончательные — по замеру, до изменения VPS.

## 5. Поиск

`logs.mjs find --from --to [--source] [--request-id] [--code]`: свежее — из
journald, старое — из архива по каталогу (учётка только на чтение).

**Сделано (локально):** `logs-archive.mjs find`. Каждая порция,
пересекающая интервал, читается своей версией и сверяется по хешу. Свежее
берётся из journald после курсора архиватора. С `--copy <каталог>` поиск
идёт по ручной копии без S3. Учтённые потери в интервале называются. Если
порция не прочиталась или не сошлась, поиск «НЕПОЛОН» (код 1), а не «ничего
не найдено». Накопленная история (`tech-logs-legacy`) в поиск не входит.

## 6. Сборщик

Свой скрипт на `journalctl`. Это отдельный обслуживаемый компонент: journalctl
даёт чтение и курсоры, а подтверждение архива, повторы, каталог и обнаружение
потерь — ответственность нашего кода (испытания ниже). Vector / Fluent Bit
сняли бы часть буферизации, но не каталог и подтверждение в нашем формате —
выбор по этому объёму.

## Испытания (локальный стенд)

1. Запрос, отказ, исключение ядра → структурированные записи, сквозной ID.
2. Искусственные секреты по всем источникам — отсутствуют (п. 1).
3. Падение архиватора посреди порции; падение после «S3 принял» до
   сохранения курсора (повтор с новым шифрованием → совпал исходный хеш,
   пропуск); потеря локального состояния — продолжение с конца непрерывной
   цепочки при искусственном разрыве в S3; незавершённая запись части
   каталога; конфликт — объект с тем же именем и другим исходным хешем → без
   перезаписи, тревога. Итог каждого: без потерь и неразличимых копий.
   3а. Скачивание на ноутбук: добавочный повтор не качает уже скачанное;
   порча байта объекта и подмена порции обнаруживаются проверкой.
4. Остановка MinIO → отставание и тревога; возврат → догоняет порциями.
5. Ротация и вытеснение journald → пробел найден как потеря.
6. Подавление частоты journald → сигнал.
7. Остановка архиватора → «неизвестно» в Zabbix, не нули.
8. Чтение интервала из архива на чистой среде; расшифровка ключом из
   комплекта ключей W07.
9. Замер потока (п. 4).

После испытаний — отдельный план изменений VPS (лимиты journald, драйвер
Docker, Caddy, nginx, postgres, выгрузка накопленного) на «ок» Томаса.
