# W32 — нагрузка и отказы на test-1: план

Блок 6 (6.2–6.6). Разрешение Томаса 09.11 испытывать test-1 на VPS: реальных данных и
пользователей на сервере нет. Условия Тэнка 09.11 — пункты 1–6 ниже. Результат —
характеристика нынешней реализации на синтетическом профиле, **не** подтверждение ёмкости
будущей продуктовой модели и **не** закрытие блока 6.

## 2. Ресурсы и остановка (условие 2)

Бюджет прогона: test-1 в своих лимитах (выше). Генератор k6 — на ноутбуке Томаса, вне VPS;
его CPU и сеть пишутся в отчёт.

**Пороги прекращения** — проверяются раз в 5 с сборщиком на сервере; при срабатывании k6
останавливается и настройки возвращаются:

| Показатель                   | Порог                                            |
| ---------------------------- | ------------------------------------------------ |
| Доступная память VPS         | < 1,0 ГБ                                         |
| Свободный диск `/`           | < 20 ГБ                                          |
| load average 1 мин           | > 8 (вдвое больше числа ядер) 2 мин подряд       |
| prod `/v1/ready`             | не 200 дольше 30 с                               |
| test-2 `/v1/ready`           | не 200 дольше 30 с                               |
| Соединения PostgreSQL test-1 | > 90 % `max_connections`                         |
| 5xx test-1                   | > 5 % за минуту (кроме окна управляемого отказа) |

**Временные изменения test-1** — только переменные среды через шаг `prod-load-limits.sh`:
`apply` сохраняет прежние значения в файл-отметку и поднимает потолок частоты на адрес
(`RATE_LIMIT_IP_CEILING_PER_MIN`) и лимит входа для прогона ёмкости; `restore` возвращает их
и проверяет защиту (429 и `Retry-After`). Если отметка осталась от оборванного прогона,
следующий запуск сначала выполняет `restore`. Изменения test-1 — обычным согласованным
порядком: тот же комплект `2.1-b132.1`, только настройки среды; новая версия ядра этим
пакетом на test-1 не ставится.

## 3. Профиль (условие 3)

Синтетический, версия профиля `p1`. Каждый сеанс входит один раз, затем действует с паузой.

| Параметр                  | Значение                                                                                                                             |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| Сеансы, номинал           | 10; перегрузка — 20                                                                                                                  |
| Пауза между действиями    | 3–7 с, равномерно (в среднем 5 с)                                                                                                    |
| Частота действий, номинал | 2 действия/с (10 сеансов × 1 действие / 5 с)                                                                                         |
| Ступени                   | 2 → 4 → 8 → 16 действий/с, по 10 мин; базовый замер 15 мин; возврат к 2/с — 10 мин                                                   |
| Длительный прогон         | 2 действия/с, 60 мин — после ступеней, отдельным запуском                                                                            |
| Исполнитель k6            | постоянная частота прибытия: замедление сервера не снижает заданную нагрузку; не начатые действия (`dropped_iterations`) учитываются |

Соотношение действий:

| Действие                                                       | Доля |
| -------------------------------------------------------------- | ---- |
| Витрина: список проектов с фильтром                            | 20 % |
| Карточка проекта (разрешённая видимость)                       | 20 % |
| Карточка с запрещённой видимостью — ожидается отказ, не ошибка | 5 %  |
| Свой кабинет: список своих проектов                            | 15 % |
| Поиск по витрине                                               | 10 % |
| Правка своего проекта (с ключом повтора)                       | 10 % |
| Правка профиля                                                 | 5 %  |
| Материал-ссылка                                                | 5 %  |
| Загрузка файла: 64 КиБ — 7 %, 10 МиБ — 3 %                     | 10 % |

Отдельно в каждой ступени: серия из 20 одновременных входов; одна загрузка максимального для
типа размера (`deck` — 50 МиБ). Число запросов на действие измеряется, а не предполагается.

**Данные** (метка probe-run, только этого прогона): 20 участников-основателей, 200 проектов
(половина видима всем, половина — ограничена), у каждого 2 материала-ссылки. Подготовка и
уборка — шагом на сервере, удаляются только объекты с меткой прогона.

**Отдельно показывается:** серверное время API — из журнала ядра test-1 (`durationMs` по шаблону
маршрута, `route`, `status`); полное время с ноутбука — из k6. Заданная и фактическая
интенсивность — по каждой ступени. Перцентили — из общей выборки, не усреднением.

## 4. Проверка последствий отказа (условие 4)

До отказа прогон фиксирует подтверждённые изменения (идентификаторы и ключи повтора). После
восстановления HTTP:

- подтверждённые изменения на месте и совпадают по содержимому;
- повтор с тем же ключом не создал второго объекта и второго события;
- outbox, загрузки и вебхуки: число незавершённых и возраст старейшей записи — до, во время,
  после; очередь сохраняется и затем разгружается до исходного уровня за отведённое время;
- нет ложного успеха: ответ 2xx только для изменений, которые есть в базе.

## 5. Версии (условие 5)

В отчёт: комплект test-1, коммит, число работающих ядер, версии k6 и образа k6, профиль `p1`,
лимиты и все временные изменения с временем применения и возврата.

## 6. Повторяемость (условие 6)

- Короткий контроль перед выпуском: базовый профиль 10 мин одной командой, сравнение с прошлым
  замером.
- Полное испытание — при существенных изменениях; отказы — при изменении затронутых
  компонентов.
- После появления реальных данных даже короткая нагрузка на общем VPS автоматически не
  разрешена — отдельное решение.

## 7. Инструменты

- **k6** — образ `grafana/k6` с закреплённым digest, запуск на ноутбуке. Лицензия AGPL-3.0 —
  локальный инструмент, в поставку не входит; вносится в опись (вид «локальные инструменты»)
  и реестр блока 11 до запуска.
- **Сборщик на сервере** `prod-load-collect.sh`: `docker stats` и ресурсы VPS раз в 5 с,
  пороги прекращения, выгрузка журнала ядра test-1 за окно прогона (только метод, шаблон
  маршрута, статус, длительность), снимок `pg_stat_statements` (нормализованные запросы без
  значений параметров).
- **Задержка цикла событий ядра** в коде не измеряется: в базовом замере — «не измерено»;
  показатель добавляется отдельной правкой и приходит на test-1 только выпуском.

## 8. Порядок

1. Инструменты и шаги сервера; сухой прогон на локальном стенде.
2. Базовый замер на test-1 (2 действия/с, 15 мин) — протокол.
3. Ступени до первой достигнутой границы; возврат к номиналу.
4. Отказы из таблицы раздела 1 под номинальной нагрузкой.
5. Длительный прогон.

Отчёты — `out/suites/load-<run_id>/`, прежние не затираются. Итог по каждому критерию 6.3:
«прошёл», «не прошёл», «не проверено» с причиной.
