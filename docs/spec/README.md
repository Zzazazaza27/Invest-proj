## 3. Правила проработки

1. **Решено / Предложено / Открыто / Зависит от** — у каждого раздела блока явная
   пометка. Предложения не выдаются за решения. Решает Томас.
2. **Маус** готовит исходный материал, **Тэнк** даёт независимый взгляд, Томас
   принимает решения. Если нужна именно независимая проработка, ответы готовятся
   **до** взаимного ознакомления.
3. **Ритм определяется завершённостью вопроса:** блок может занять несколько
   обсуждений; «один блок за сессию» не обязательство.
4. **Кабинеты не ограничиваем заранее одним инвестиционным путём.** Путь «проект →
   раунд → запрос материалов → допуск → решение» обязателен, но у наблюдателя,
   основателя и партнёра есть своя польза, и её выясняем при обсуждении блока.
5. **«Платежей нет» — предложение о границе, а не решение.** Решено: нет
   краудфандинга и проведения инвестиционной сделки. Это не равно решению обо всех
   будущих платных услугах.
6. **Существующий код различаем по трём степеням:** _прочитано_ (читал текст),
   _проверено выполнением_ (запускал и наблюдал), _предполагается_ (вывод без проверки).
   Наличие механизма не означает его совместимость с новой моделью.
7. **Одна формулировка — в одном месте.** В других файлах — ссылка.
8. **Старые черновики** (`docs/product/stage-2-*`, `mvp-readiness-map.md` и т. п.)
   остаются материалами. Заменёнными их помечаем только после переноса нужных решений
   и указания нового источника.
9. Порядок разделов внутри блока: требование → зачем → что предстоит решить → как
   проверить; **способы реализации — отдельно, как варианты.**
