## 0. Коротко

1. **Раунд уже был продуман** (правила видимости, схема в базе, экран в кабинете основателя), но
   строился вокруг «поданной заявки-профиля». Новая модель его не отменяет, а сдвигает:
   проект существует без раунда, раунд — отдельная запись о привлечении. Противоречий пять
   (раздел 1.3), три из них про деньги и публикацию.
2. **Инвестору для MVP нужен тонкий путь:** найти → сохранить → изучить → запросить материалы →
   задать вопросы → решить. Идея 087 целиком в MVP не входит. Учёт состоявшихся вложений **не
   исключён, а вынесен тебе как решение** (раздел 2.2).
3. **ИИ-скоринг уже есть в коде** и по большей части подходит как необязательный запуск основателем.
   Не подходят три вещи: он **удерживает публикацию** при флагах, **не читает содержимое документов**,
   в интерфейсе нет пометки «устарел» (раздел 3.3).
4. **Партнёр и лестница** связываются через одну вещь — «подтверждено партнёром»: этап и степень
   подтверждённости показываются раздельно (раздел 4).

### 1.2. Новое (решения Томаса 2026-10-13) и мои предложения

**Решения Томаса:**

- Заявка = инвестиционный раунд. Различаем: **проект / раунд / запрос материалов и доступ / решение инвестора.**
- Решение принимает инвестор; платформа даёт материалы, доступ, вопросы и ответы, инструменты.
- Проверки аккаунта, компании, полномочий — отдельно от оценки привлекательности проекта.
- Отсутствие проведения денег в MVP ≠ отсутствие раунда и его условий.

**Мои предложения (не решены):**

- Раунд в MVP — **описание условий и приём запросов**, без платежей и без «книги сделок».
- Поля раунда для MVP — только те, что нужны инвестору, чтобы решить «смотреть дальше или нет»:
  цель и сумма (диапазон), что предлагается, чек, срок, на что пойдут деньги, этап. Остальное — позже.
- Запрос материалов — **отдельная запись**, а не статус раунда: у одного раунда много запросов от
  разных инвесторов, у каждого свой допуск и свои вопросы.

## 3. Путь «проект → раунд → рассмотрение → материалы и вопросы → решение»

### 3.1. Шаги

1. **Проект.** Основатель создаёт проект (без суммы, без раунда). Лестница показывает этап.
2. **Раунд.** Основатель открывает раунд: цель, сумма, чек, что предлагает, на что нужны деньги.
   Платформа ничего не проводит. Проверки аккаунта/компании — отдельная колонка «проверено / заявлено».
3. **Скоринг (необязательно).** Основатель может запустить ИИ-скоринг (раздел 3.2). Без него раунд
   публикуется как обычно.
4. **Рассмотрение.** Инвестор находит раунд, сохраняет, при желании — запрашивает материалы.
5. **Материалы.** Основатель выдаёт адресный допуск набору частей; загружает или заменяет документы.
6. **Вопросы и ответы** внутри запроса.
7. **Решение инвестора:** продолжаем / не подходит / нужны ещё материалы. Контакт и переговоры — вне платформы.

### 3.2. ИИ-скоринг в этом пути (предложение; основа — существующий механизм)

| Вопрос                               | Ответ                                                                                                                                                                   |
| ------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Кто и где запускает**              | Основатель (редактор проекта) в карточке проекта или раунда, кнопка «Запустить анализ». Это уже есть: запрос на запуск анализа проекта, доступен владельцу/сооснователю |
| **Какие данные**                     | Проект (карточка), раунд (условия), ответы профиля; **документы — только как перечень (тип, версия), содержимое сейчас не читается**                                    |
| **Выполнение**                       | Состояния: «выполняется» / «готово» / «ошибка»; один активный запуск на проект, суточная квота. Это уже есть                                                            |
| **Ошибка**                           | Сообщение основателю и запись в журнал запусков; результат не создаётся. Инвестору «ошибка» не показывается — для него это «анализ не проводился»                       |
| **Где виден результат инвестору**    | В карточке раунда: блок «Автоматический анализ платформы» с датой и перечнем проанализированных данных. Видимость — по тем же правилам раскрытия, что и остальное       |
| **Что значит «анализа нет»**         | Инвестору: «основатель не запускал анализ». **Не** минус для проекта и не причина скрывать                                                                              |
| **Дата и перечень данных**           | Уже хранятся: версия входа, отпечаток входа, версия модели; в блоке показывать «проанализировано: карточка, раунд от …, документы: названия и версии»                   |
| **После изменения материалов**       | Старый результат остаётся, но помечается «**устарел**: данные изменились после даты анализа». Не показывается как оценка новой версии. Сравнение по отпечатку входа     |
| **Что скоринг не есть**              | Не подтверждение достоверности, не завершённая проверка (due diligence), не решение за инвестора. Подпись на блоке обязательна                                          |
| **Не запрещает публикацию и доступ** | Нужно решение Томаса (см. 3.3, конфликт «А»)                                                                                                                            |

### 3.3. Что в существующем механизме не подходит (проверено чтением кода)

| #   | Что в коде                                                                                   | Почему не подходит                                    | Предложение                                                                                                                 |
| --- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| А   | Непустые флаги соответствия **удерживают публикацию листинга** до решения человека           | Конфликт с «скоринг не блокирует публикацию и доступ» | Решение Томаса: оставить как опцию платформы для открытой публикации, но **не для закрытой группы**                         |
| Б   | Анализируются: карточка и ответы **поданной** версии заявки; документы — только тип и версия | Хочется «проект, раунд, документы»                    | Расширить вход: раунд; чтение содержимого документов — отдельная задача (языковая модель не подключена, разбор по правилам) |
| В   | В интерфейсе основателя пометки «устарел» для паспорта не нашёл                              | После изменения материалов результат выглядит текущим | Пометка по отпечатку входа; вычислять при показе                                                                            |

Не включаем весь старый контур (эксперты, очередь, оценки IRS, карта готовности) — берём запуск,
хранение результата, отпечаток входа и показ.

## 4. Связь с кабинетом партнёра и лестницей

### 4.1. Лестница: этап и подтверждённость — раздельно

В карточке проекта и раунда рядом, но как два разных показателя:

- **Этап:** идея → проверка гипотезы → первый результат → устойчивая деятельность → рост.
- **Подтверждённость:** сколько вех заявлено, сколько подтверждено (партнёром, документом, позже —
  интеграцией). Показывается числом и пометками, а не итоговым баллом.

**Раунд и скоринг лестницу не двигают:** привлечение денег — не этап, анализ — не подтверждение.

### 4.2. Партнёр (предложение, пока не решено)

| Что партнёр делает                      | Как связано с путём и лестницей                                                                                                                                                                                    |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Витрина программы**                   | Подборка проектов, которые согласились; ссылка для инвесторов; инвестор приходит в тот же каталог раундов                                                                                                          |
| **Подтверждает участие и выпуск**       | Это веха «подтверждено партнёром» — питает подтверждённость на лестнице и доверие инвестора                                                                                                                        |
| **Обзор проектов по этапам**            | Естественный результат лестницы: список проектов программы с этапом и подтверждённостью                                                                                                                            |
| **Как проект связывается с программой** | Двустороннее подтверждение: основатель называет программу, партнёр подтверждает. **Подтверждение связи ≠ делегирование доступа:** партнёр не получает права на проект сам собой — только видит и подтверждает вехи |
| **Проверка самого партнёра**            | Вручную при подключении (фальшивый «акселератор» иначе вешает «выпускник» на проекты)                                                                                                                              |

### 4.3. Что видит партнёр про раунд

## 5. Сквозное: статусы материалов, рассмотрения и входящие

- **Статус материалов (у основателя):** запрошено → выдан допуск → загружено/заменено → отозвано.
- **Стадия рассмотрения (у инвестора):** сохранил → запросил → изучаю → вопросы → решение.
- Это **две независимые линии**, не одна цепочка: допуск можно отозвать при любой стадии; инвестор может
  вернуться из «решил» в «изучаю».
- Каждой стороне нужны **входящие** (запрос, допуск, вопрос, ответ). Почта нужна для входа;
  какие события слать письмами — отдельное решение.
- Правовая граница проверяется под точное содержание раунда (вопросы 1–3 списка для Вики) и **не
  останавливает** описание сценариев и прототипы; до ответа публиковать раунды реальных людей нельзя.
