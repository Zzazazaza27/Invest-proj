## 0. Главное за минуту

1. **Hermes Agent** (Nous Research) — не ядро для нашей задачи; возможен позже как
   необязательный слой связи (раздел 1).
2. **Связка Claude Code ↔ Codex уже существует официально:** плагин OpenAI
   `codex-plugin-cc` внутри Claude Code. `codex mcp-server` **удалён** (многие
   гайды ещё его описывают). Обратное направление делается `claude -p`.
3. **Главный риск — не выбор инструмента, а границы.** Публичные инциденты 2026
   года (агент стёр прод-базу) повторяют одну схему: широкие учётные данные в
   окружении агента + барьер «на словах» + бэкапы рядом. **У вас сейчас
   именно такое окружение** (раздел 3).
4. **На вашей машине (Windows 10) нет хорошей локальной песочницы:** у Claude
   Code её нет на нативном Windows, Docker Sandboxes требуют Windows 11. Реальные
   варианты: облачные сессии, WSL2 с отдельной Linux-средой, отдельный
   пользователь ОС (раздел 4).
5. **Защита `main` на бесплатном аккаунте невозможна**; для автономных агентов
   это самая слабая точка. Решение — за вами: платная защита или разделение
   идентичностей (раздел 5).
6. **Польза кросс-вендорного ревью не доказана:** два независимых исследования
   дают противоположные результаты. Строить надо так, чтобы это можно было
   **измерить**, а не предполагать (раздел 6).

## 1. Hermes Agent: ответ на вопрос о нём

**Что это.** Открытый (MIT) универсальный агент-ассистент от Nous Research
(релиз февраль 2026): память, самообучаемые навыки, cron, шлюзы в мессенджеры,
субагенты, Kanban-доска, режим Bots («Pantheon», v0.21.0, 2026-08-31),
десктоп-приложение. «PantheonForge» как продукта не найдено — «Pantheon»
это название релиза. Источники: [документация](https://hermes-agent.nousresearch.com/docs),
[репозиторий](https://github.com/NousResearch/hermes-agent).

**Что для нас важно** (проверено исследователями по репозиторию и документации):

| ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

| Что полезно              | Kanban с блокировкой на человека (`needs_input`) и циклом ревью; cron; доставка уведомлений в мессенджеры                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |

**Оценка применимости.** Hermes создан как личный ассистент, а не как
инструмент разработки кода. Ревью-цикл в его Kanban идёт между его же
агентами, а не между вендорскими CLI. Подписка Claude через него **возможна**
только экспериментальным плагином DirectSDK (через официальный `claude`;
граница условий Anthropic не разобрана — формулировки «third-party apps with
your subscription limits» в справке от 2026-10-07 говорят скорее «да», но
прямого одобрения нет). **Рекомендация: не брать как ядро; не отвергать навсегда**
(решение Томаса 2026-10-13: сейчас не используем).
Возможный будущий сценарий — слой «расписание + уведомления в мессенджер»
вокруг официальных CLI, если встроенные средства Claude Code (раздел 7) окажутся
недостаточными. Решение — после основной связки.

Остальные из той же ниши: OpenClaw (ассистент, хост без песочницы по
умолчанию; отношения с Anthropic по вторичным данным ограничены), Pi
(минималистичный harness, без системы разрешений), T3 Code (пульт, запускает
официальные CLI, «очень рано») — **не берём**.

## 2. Условия подписок (подтверждено мной по первоисточникам)

- **Claude (Max).** Через неизменённый Claude Code: интерактивно, `claude -p`,
  фоновые и облачные сессии, GitHub Action с токеном `claude setup-token`.
  Справка Anthropic от 2026-10-07: «You can still use the Claude Agent SDK,
  `claude -p`, and third-party apps with your subscription limits». Запрещено
  пускать запросы через подписку «on behalf of their users» и собирать токены.
  Для продуктов на SDK нужен API-ключ. Anthropic оставляет принудительные
  меры «без предупреждения». У Max с 2026-10-07 есть ещё API-кредиты ($100/$200
  в месяц), но **только для SDK и `claude -p` по API-ключу**, не для
  интерактивного режима и не для GitHub Action.
- **Codex (ChatGPT).** Codex CLI, IDE, `codex exec` — по подписке; **облако
  Codex только по входу ChatGPT**; **GitHub-Action `codex-action` — только API-
  ключ**. Следствие: ревью Codex **в CI на подписке не выйдет**, только
  локально, из облачной сессии или по API.

## 5. Граница с production и защита `main`

**Принцип.** У агента **нет** ни ключа сервера, ни права вызвать выкат, ни
токена с записью в `main`. Выкат делает человек или отдельный процесс под
другой учётной записью.

**Конкретно для вас:**

1. Ключ `launchbridge_ed25519` — **убрать из доступных агенту путей**:
   вынести в отдельный профиль/пользователя или на отдельную машину. Пока он
   лежит в `~/.ssh` вашего пользователя, любой локальный агент им может
   воспользоваться, какие правила ни поставь.
2. Токен `gh`: для агентов использовать **отдельный fine-grained токен** на
   один репозиторий (`rebel-diesel/fifth-element`): Contents write, **без**
   Workflows, Actions, Administration. Ветвевого ограничения у такого токена
   нет (**не подтверждено документацией**).
3. Резервные копии базы стенда хранить вне зоны, которую агент может менять.

**Защита `main` без Pro (проверено GitHub: недоступна на Free для приватных).**
Три пути:

| Путь                                                                                                                         | Что даёт                                                                                                             | Минусы                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Платная защита** (Pro или Team, цена ≈ $4/мес — по сторонним источникам, **НЕ ПРОВЕРЕНО** первоисточником)                 | Правила веток, обязательные проверки CI, обязательное одобрение владельцем кода — то есть настоящий серверный барьер | деньги (малые)                                                                                                                                               |
| **Разделение идентичностей**: агент работает под отдельной учёткой без записи в основной репозиторий и присылает PR из форка | Агент физически не может писать в `main`; человек сливает                                                            | второй аккаунт GitHub (условия GitHub для «машинных» учёток **НЕ ПРОВЕРЕНЫ**), больше движущихся частей, форк приватного репозитория требует права на чтение |
| **Без защиты**: агент не владеет токеном с записью в `main` вообще (токен у человека)                                        | 0 денег                                                                                                              | агент не может сам публиковать; нужен человек-посредник на каждый пуш                                                                                        |

**Моё мнение:** для автономных агентов платная защита `main` — самое дешёвое
решение по сравнению с инженерным обходом. Но это ваше решение (вы просили
вернуться к вопросу при проектировании); я изложу цену и последствия ещё раз,
когда определимся с местом исполнения (раздел 4).

### Что важно

- **Ревью в CI на подписке не получится для Codex** (только API-ключ); для
  Claude есть `claude-code-action` с токеном подписки.
- **Общие инструкции:** Claude Code читает `AGENTS.md` сам (v2.1.277+), но
  **при наличии `CLAUDE.md` игнорирует `AGENTS.md`**. У вас есть `CLAUDE.md`,
  значит нужна строка `@AGENTS.md` в нём (надёжнее симлинка на Windows).
  **Skills:** Codex ищет в `.agents/skills`, Claude Code в `.claude/skills`;
  один скилл придётся держать в двух местах (копия или скрипт синхронизации).
- **Польза кросс-вендорного ревью не доказана.** Контролируемое исследование
  (arXiv 2607.21656): ревью Claude поднимает код Codex 71,6% → 89,7%, но ревью
  Codex **ухудшает** код Claude 91,4% → 82,8%; у Greptile чужая модель находит
  на 2–3 пункта больше ошибок, но это вендорское измерение. Anthropic сама
  предупреждает, что ревьюер, которого просят искать пробелы, найдёт их всегда
  (риск шума и переусложнения). **Следствие:** ревью чужой моделью ставится как
  эксперимент с измерением (M3, M4 из прежнего документа), а не как догма.
- **Дизайн ревью, который рекомендует Anthropic:** свежая сессия без
  рассуждений автора; ревьюер получает только diff и критерии приёмки; просить
  о том, что влияет на корректность и заявленные требования, а не о стиле.

### Варианты схемы обмена (без решения)

1. **Внутри сессии:** Claude пишет → `/codex:adversarial-review` на diff с
   критериями → Claude правит → человек получает итог. Минимум своего кода,
   но зависит от плагина (Windows, баги, лимиты).
2. **Скриптом:** хук или скилл вызывает `codex exec --sandbox read-only
--output-schema` на diff + карточке задачи, получает JSON-замечания.
   Больше контроля, чуть больше своего кода, не зависит от плагина.
3. **Зеркально:** код пишет Codex (`codex exec`/облако), ревьюит `claude -p
--json-schema`.
4. **Не делать автоматического цикла «до зелёного»:** review gate и подобные
   циклы выжигают лимиты; нужен жёсткий потолок итераций и эскалация человеку.

## 7. Эскалация и правила «кто решает»

**Что поддерживается официально** (проверено исследователями, [П] по
документации Anthropic/OpenAI):

- Правила разрешений вычисляются как deny → ask → allow; **сказанное в чате или
  в `CLAUDE.md` не гарантия** (терется при сжатии контекста), гарантию даёт
  только правило `deny` или хук.
- Хуки: `PreToolUse` (`allow/deny/ask/defer`), `PermissionRequest`,
  `Notification`, `Stop` (не даёт агенту закончить, пока проверка не прошла).
  **Таймаут или падение хука по умолчанию НЕ блокируют вызов** — нужно
  `"onFailure": "block"` (версия 2.1.295+).
- В неинтерактивном `claude -p` без обработчика запроса спросить некого:
  заблокированное действие пропускается, запуск идёт дальше. Режим для
  неприсматриваемых прогонов — `dontAsk` (отклоняет всё, что не разрешено
  явно), либо `defer` + обёртка на SDK.
- Доставка запроса человеку из фона: **Remote Control** (push на телефон),
  **каналы** (Telegram/Discord; research preview; ответ «yes/no <код>», обязателен
  список разрешённых отправителей), **agent view** (статус «Needs input»; **ответ
  на диалог разрешений из peek-панели не действует**, нужно подключиться),
  `Notification`-хук в свой сервис. Единой «очереди решений» в продуктах нет.
- Codex: `approval_policy` (`on-request`, `never`, granular) и `sandbox_mode`
  раздельно; для неинтерактивного CI OpenAI рекомендует `read-only` + `never`.
- Данные Anthropic по усталости от подтверждений (по пересказам): в ручном
  режиме принимается 93–97% запросов — ручное «да» на каждое действие
  контролем не является.

### Черновой список классов (обобщение источников, не решение; для вашего утверждения)

| Кто решает                                                                                                       | Классы                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Агент сам** (на ветке агента, с проверкой, которую он может запустить)                                         | чтение и анализ; правки кода и **новых** тестов; локальные сборки и тесты; коммиты в ветку агента; документация без изменения контрактов                                                                                                                                                    |
| **Агент + независимое ревью** (ревьюер — другая сессия, желательно другая модель; мёрджит не автор и не ревьюер) | общая авторизация, работа с базой (без миграций), общие пакеты; контракты между приложениями; **правки тестов и конфигурации проверок**; зависимости и сборка; любое слияние в `main`                                                                                                       |
| **Человек обязательно** (технически: deny/`ask`/`defer` или недоступность инструмента)                           | применение миграций к реальным данным (особенно `DROP`); удаление данных, force-push, `reset --hard`; секреты, токены, права, изменение хуков/настроек агента; деньги и платёжные режимы; любой выкат на сервер; внешние сообщения от вашего имени; юридические тексты; ослабление проверок |

Для вашего проекта «человек обязательно» привязывается к конкретным путям:
`database/migrations/**`, `apps/core/src/billing/**`, `apps/core/src/auth/**`,
`apps/core/src/crypto/**`, `scripts/deploy.mjs`, `infra/**`, `.github/workflows/**`,
`.claude/**`, `.githooks/**`, `.env*`, `RULES.md`, `CLAUDE.md`.

**Против усталости.** Гейт по политике, а не на всё; механически неверное
отсекают тесты и проверки до человека; запросы ранжируются по риску; низкорисковое
— дайджестом, высокорисковое — сразу и по одному; карточка запроса
самодостаточна (причина, класс, затронутое, предложение, доказательства).
Отдельных источников по дайджестам нет: это мои выводы.

**Защита от «подгонки тестов агентом»:** запрет правки тестов и конфигурации CI
без ревью (deny/хук), тесты пишет отдельная сессия, мутационное тестирование
как дополнительный слой (прямых измерений его пользы против агентов не найдено).

**Откат.** Чекпоинты Claude Code ловят только правки файловыми инструментами и
**не заменяют git**; опора — ветки `agent/*`, атомарные коммиты, теги перед
рискованным шагом; для миграций при «только вперёд» — схема expand → migrate →
contract, где `DROP` отдаётся человеку (источники вторичные).

## 8. Что строить самим, а что нет

**Готовое есть** (не писать): связка Claude↔Codex (плагин или `codex exec`/`claude -p`),
фоновые и облачные сессии, Remote Control и каналы для уведомлений, хуки и
режимы разрешений, worktree, `/code-review`.

**Минимальный собственный слой** (только то, что готовое не закрывает):

1. Файл правил с политикой «кто решает» (раздел 7) в виде `deny`/`ask`-правил и
   хуков с `onFailure: block`.
2. Карточка задачи с критериями приёмки и классом риска.
3. Тонкая обёртка кросс-ревью (скилл или скрипт): diff + критерии → JSON-замечания
   другой модели, с потолком итераций.
4. Скрипт синхронизации skills между `.claude/skills` и `.agents/skills`; единый
   `AGENTS.md` с импортом из `CLAUDE.md`.
5. Журнал внимания и метрики (из прежнего документа).

**Не нужно строить:** оркестратор, собственный harness, очередь решений
(пока достаточно push/каналов), универсальный агентный runtime.

## 9. Решения, которые нужны от Томаса

1. **Где исполнять автономных агентов:** облачные сессии, WSL2 со своим Ubuntu,
   отдельный пользователь ОС, их сочетание, либо переход на Windows 11. (Раздел 4.)
2. **Защита `main`:** платная (Pro/Team), разделение идентичностей или без
   защиты. (Раздел 5.) Вы просили вернуться к этому при проектировании.
3. **Корневой ключ сервера:** согласны вынести его из профиля, под которым
   работает агент (даже если сервер сейчас не трогаем)?
4. **Подписка ChatGPT/Codex:** есть ли, какой план (определяет лимиты, `Fast`-
   множители, доступность облака).
5. **Утвердить или поправить список «кто решает»** (раздел 7), в том числе
   путей «человек обязательно».
6. **Hermes:** оставляем за пределами сейчас (моя рекомендация) или хотите
   отдельно попробовать как слой уведомлений позже.
7. **Нужен ли автоматический цикл «автор → чужая модель → автор»** сразу или
   сначала ручной запуск ревью с измерением пользы.
