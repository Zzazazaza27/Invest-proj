# Market Intelligence — MVP для админ-панели

## 1. Задача

Добавить в существующую админ-панель отдельный внутренний раздел для накопления и первичной обработки информации об инвестиционном рынке.

На первом этапе это **не CRM, не investor matching, не отдельный продукт и не полноценная база инвесторов**.

Цель MVP:

1. начать сохранять найденные в интернете источники;
2. сохранять найденные сущности в простой структурированной форме;
3. видеть всё в одном табличном интерфейсе;
4. иметь возможность вручную добавлять и редактировать данные;
5. иметь возможность импортировать данные из отдельных источников;
6. подготовить основу для дальнейшего автоматизированного сбора информации.

---

## 2. Размещение

Не создавать отдельное приложение.

Добавить отдельный раздел существующей админки:

`/admin/intelligence`

Рабочее название:

**Market Intelligence**

Раздел может визуально ощущаться как отдельный кабинет/рабочая область, но должен использовать:

- существующую авторизацию админки;
- существующий backend;
- существующую PostgreSQL;
- существующий deployment.

Не создавать отдельную БД и отдельную систему авторизации.

---

## 3. Интерфейс MVP

Главный экран — простая таблица.

Пример:

| Type     | Name          | Organization       | Source       | Contact  | Status      | Updated    |
| -------- | ------------- | ------------------ | ------------ | -------- | ----------- | ---------- |
| Investor | Иван Иванов   | XYZ Ventures       | Get-Investor | Telegram | Reviewed    | 23.09.2026 |
| Fund     | ABC Capital   | —                  | Get-Investor | Website  | Raw         | 23.09.2026 |
| Event    | Demo Day 2026 | Unicorn Fellowship | arena...     | —        | Interesting | 23.09.2026 |

Минимально нужны:

- поиск;
- сортировка;
- фильтр по типу;
- фильтр по статусу;
- открытие записи;
- редактирование записи;
- ручное добавление записи.

Без дашбордов, графиков и аналитики.

---

## 4. Типы сущностей

На первом этапе достаточно:

```text
PERSON
INVESTOR
ORGANIZATION
FUND
INVESTOR_CLUB
ACCELERATOR
BOOTCAMP
EVENT
MEDIA
CORPORATION
OTHER
```

Не строить сложную объектную модель заранее.

Если реальные данные покажут, что классификацию нужно изменить — изменить позже.

---

## 5. Основная таблица

Создать таблицу:

`intelligence_entities`

Минимальные поля:

```text
id
type
name
organization_name
description
website_url
email
telegram
linkedin
status
notes
created_at
updated_at
```

Статусы:

```text
RAW
REVIEWED
INTERESTING
CONTACTED
ARCHIVED
```

---

## 6. Источники

Для каждой сущности обязательно хранить источник данных.

Создать таблицу:

`intelligence_sources`

Поля:

```text
id
entity_id
source_url
source_domain
source_title
discovered_at
last_checked_at
notes
```

Одна сущность может иметь несколько источников.

Пример:

Иван Иванов найден:

- на Get-Investor;
- на сайте фонда;
- на странице мероприятия;
- в LinkedIn;
- в статье;
- в списке спикеров конференции.

Все источники сохраняются отдельно.

---

## 7. Ручное добавление

Кнопка:

**Add entity**

Минимальная форма:

```text
Type
Name
Organization
Description
Website
Email
Telegram
LinkedIn
Source URL
Notes
```

После сохранения запись появляется в общей таблице.

---

## 8. Импорт URL

Добавить простую функцию:

**Import source**

Пользователь вставляет URL.

На первом этапе система должна:

1. сохранить URL;
2. получить HTML страницы;
3. сохранить title страницы;
4. сохранить domain;
5. сохранить дату импорта;
6. по возможности извлечь очевидные сущности.

Не пытаться сразу создавать универсальный парсер всего интернета.

---

## 9. Первый специализированный парсер

Первый источник:

`https://get-investor.ru/`

Попробовать импортировать публично доступные данные из разделов:

- инвестиционные фонды;
- бизнес-ангелы;
- инвестиционные клубы;
- акселераторы;
- мероприятия;
- другие явно структурированные каталоги, если они доступны.

Сохранять только те данные, которые реально присутствуют в источнике.

Если поле отсутствует — `NULL`.

Не дополнять данные догадками.

---

## 10. Импортированные записи

Для импортированных записей дополнительно хранить:

```text
import_source
external_url
external_id
imported_at
```

Это нужно для:

- повторного обновления;
- определения происхождения;
- защиты от дублей.

---

## 11. Дубли

На MVP достаточно простой проверки:

1. одинаковый `external_url`;
2. либо одинаковые `name + organization_name`.

Автоматически записи не объединять.

При подозрении на дубль показывать предупреждение.

---

## 12. Карточка сущности

При клике на строку открывается карточка.

### Основное

- имя;
- тип;
- организация;
- описание;
- контакты;
- статус;
- заметки.

### Sources

Список всех источников:

```text
Get-Investor
https://...

Unicorn Fellowship
https://...

Company website
https://...
```

### History

На MVP достаточно:

```text
Created
Last updated
```

Полный audit trail пока не нужен.

---

## 13. Что сейчас НЕ делать

Не разрабатывать:

- investor matching;
- автоматический outreach;
- массовую email-рассылку;
- скоринг инвесторов;
- граф связей;
- сложную CRM;
- sales pipeline;
- AI-профилирование;
- автоматическое определение investment thesis;
- отдельную графовую БД;
- отдельный microservice;
- отдельную PostgreSQL;
- отдельное приложение;
- собственную систему авторизации;
- сложную систему ролей;
- аналитические дашборды.

Сначала нужно начать собирать реальные данные.

---

## 14. Принцип разработки

MVP должен быть максимально простым.

Основной принцип:

> Сначала собираем реальные данные, потом по этим данным уточняем модель.

Не проектировать заранее большую систему.

---

## 15. Возможные следующие этапы

После накопления первых данных отдельно решить, нужны ли:

- связи между людьми и организациями;
- investment focus;
- отрасли;
- стадии инвестирования;
- размеры чеков;
- география;
- участие людей в мероприятиях;
- портфель инвестора;
- автоматический web research;
- outreach;
- сопоставление инвесторов и проектов;
- история взаимодействий;
- граф рынка.

Ничего из этого не входит в текущий MVP.

---

## 16. Acceptance criteria

MVP считается готовым, если:

1. в админке появился раздел `/admin/intelligence`;
2. можно вручную добавить сущность;
3. сущности отображаются таблицей;
4. работают поиск и базовые фильтры;
5. запись можно открыть и отредактировать;
6. для записи можно хранить несколько источников;
7. можно вставить URL и сохранить его как источник;
8. реализован первый импорт публичных данных с `get-investor.ru`;
9. импортированные записи отображаются в общей таблице;
10. существующая админка и остальная платформа продолжают работать без изменений.

---

# 17. Отдельное исследовательское задание: карта российского инвестиционного рынка

После реализации базового кабинета начать наполнять его реальными источниками и сущностями.

Задача — не пытаться сразу собрать «всех инвесторов России».

Нужно найти **источники, в которых уже сконцентрированы участники рынка**, и использовать их как точки входа.

Исследование вести двумя путями.

---

## Путь 1. Прямой поиск

Искать российские и работающие с российским рынком источники по тематике инвестиций и стартапов.

Типы источников:

- венчурные фонды;
- частные инвестиционные фонды;
- бизнес-ангелы;
- клубы инвесторов;
- инвестиционные сообщества;
- акселераторы;
- буткемпы;
- венчурные студии;
- incubator-программы;
- Demo Day;
- pitch day;
- питч-сессии;
- startup competitions;
- форумы;
- конференции;
- инвестиционные мероприятия;
- банки;
- корпоративные акселераторы;
- корпоративные венчурные фонды;
- программы Сбера;
- программы Альфа-Банка;
- программы ВТБ;
- программы МТС;
- программы Ростелекома;
- программы крупных технологических компаний;
- Сколково;
- ФРИИ;
- университетские акселераторы;
- государственные и региональные программы;
- профильные медиа;
- каталоги инвесторов;
- каталоги стартапов;
- платформы поиска инвестиций;
- краудинвестинговые площадки;
- сайты, публикующие списки участников инвестиционных мероприятий.

По каждому найденному источнику сохранить:

```text
Название
Тип
URL
Краткое описание
Какие сущности можно получить
Насколько данные структурированы
Есть ли публичные контакты
Дата проверки
```

Если источник содержит списки людей или организаций — импортировать их в `Market Intelligence`.

---

## Путь 2. Обратный поиск от известных людей

Второй способ — идти не от запроса «инвесторы России», а от конкретных известных участников рынка.

Начать с известных публичных фигур, например:

- Оскар Хартманн;
- другие заметные российские бизнес-ангелы;
- управляющие партнёры фондов;
- организаторы инвестиционных клубов;
- известные участники Demo Day;
- постоянные члены жюри стартап-конкурсов;
- спикеры инвестиционных конференций;
- основатели крупных акселераторов.

Для каждого человека:

1. выполнить обычный web-поиск;
2. посмотреть не только первые результаты;
3. пройти несколько страниц поисковой выдачи;
4. собрать домены, на которых человек упоминается;
5. отдельно выделить:
   - мероприятия;
   - фонды;
   - клубы;
   - интервью;
   - каталоги;
   - конференции;
   - списки участников;
   - партнёрские страницы;
   - медиа;
   - акселераторы;
   - инвестиционные сообщества;
6. из каждого найденного источника вытаскивать новые имена и организации;
7. для новых сущностей повторять процесс.

Идея:

```text
Хартманн
→ страница мероприятия
→ другие инвесторы
→ их фонды
→ другие мероприятия
→ новые люди
→ новые организации
→ новые источники
```

То есть исследование должно идти как расширение сети от уже известных узлов.

---

## 18. Что должно получиться после первого исследовательского прохода

Не нужен идеальный полный каталог.

Нужен первый рабочий слой:

- несколько десятков качественных источников;
- первые сотни сущностей;
- список повторяющихся доменов;
- список наиболее часто встречающихся людей;
- список фондов и инвестиционных клубов;
- список мероприятий и организаторов;
- понимание, какие источники лучше всего подходят для автоматического импорта.

Отдельно составить список:

**Источники для следующего специализированного парсера**

с приоритетами:

```text
HIGH
MEDIUM
LOW
```

Приоритет определяется не известностью сайта, а тем, насколько много качественных структурированных данных он даёт для `Market Intelligence`.
