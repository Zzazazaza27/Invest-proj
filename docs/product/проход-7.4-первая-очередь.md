# Проход 7.4: первая очередь глазами пользователя

Документ на 2026-09-20. Не отчёт о коде, а **сценарий, который человек может
пройти руками** — и честная разметка того, где он упрётся.

Новых возможностей здесь нет: описано только то, что уже работает. Если шаг
помечен **[упор]**, значит дальше человек сам не пройдёт, и почему.

Запуск стенда — `../runbooks/демонстрационный-маршрут.md`. Что именно
работает по-настоящему, а что изображается проверочным сценарием — там же, в
разделе 3.

---

## Кто проходит

Три человека и одна платформа:

- **основатель** — заводит проект, заполняет заявку, покупает запуск раунда;
- **инвестор** — смотрит каталог и карточку, ищет, на что посмотреть;
- **посторонний** — не вошёл вовсе, попал на витрину из поиска;
- **оператор платформы** — администратор: настраивает предложение,
  подтверждает оплату, отмечает выполнение услуг.

**[упор] на шаге 11 — оплата.** Оператор платежей не выбран: платёж создаётся
тестовым адаптером, помечается тестовым, и покупка по нему **в рабочем
окружении раунд не откроет**. На стенде путь проходится целиком; для реальных
денег нужны решения владельца (см. «Что осталось»).

удаляются с телефона; кадрирование — точкой фокуса, без редактора. Формат
проверяется разбором файла, лишние метаданные (включая координаты съёмки) в
опубликованные варианты не попадают.

## Часть 2. Что получает основатель за оплату

| Услуга                                          | Состояние                                                                                                              |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Разбор заявки по правилам (без языковой модели) | работает: читает ответы поданной версии с формулировками вопросов, сохраняет отчёт, фиксирует версию и отпечаток входа |
| ИИ-анализ языковой моделью                      | **не продаётся**: провайдер и ключ не выбраны, база не даёт пометить такую услугу реализованной                        |
| Услуги, выполняемые сотрудником                 | работают: отметка с основанием                                                                                         |

Разбор по правилам **не закрывает** услугу, обещавшую языковую модель, — это
разные услуги и разные результаты. Отчёт не означает ни одобрения проекта, ни
допуска раунда, и это сказано на экране.

Правка заявки после разбора отчёт не отменяет: он остаётся отчётом о прошлой
версии, и экран говорит это прямо. Пересчёт создаёт **новый** отчёт; тот, за
который заплатили, не подменяется.

## Что осталось до первой очереди

**Решения владельца (без них разработка не продолжается):**

1. **Оператор платежей**: кто получатель, какие способы оплаты, что считать
   моментом оплаты. Нужны ли счёт как документ и ручной банковский сценарий —
   решается вместе с этим выбором, а не отдельно.
2. **Языковая модель**: провайдер, ключ, предел расходов и условия передачи
   ответов заявки внешней модели.
3. **Денежная схема сделки**: получатели, число платежей, банковские маршруты,
   подтверждения. Отложено целиком.

**Работа без решений (можно делать хоть завтра):**

- остаток 6.1: `summary` из отрендеренного текста заявки уже сделан, но
  метаданные промпта v2.6 стоит проверить на реальных заявках;
- 6.2: пересчёт сделан как правило; отдельного экрана «пересчитать» нет;
- 7.3: карточка проекта тем же компонентом, что и предпросмотр (сейчас
  страница витрины и предпросмотр — разные компоненты на одних данных);
- экраны для того, что работает только по API: полномочия, назначения,
  кабинет инвестора по возможностям тарифа;
- 6.3: AI-review как платная возможность — на уже созданной модели услуг,
  второго механизма оплаты не нужно.

**Чего в первой очереди не будет:** сезоны (этап 8, отдельная постановка),
инвесторская сторона как deal flow, автоматические возвраты, рекуррентные
списания.

## Как этот проход проверяется

Не глазами — прогонами. Каждая часть закрыта живой проверкой:

| Часть                 | Проверка                                                              |
| --------------------- | --------------------------------------------------------------------- |
| Основатель до раунда  | `render-check-round-purchase` 12, `smoke-round-purchase` 35           |
| Оплата                | `smoke-payments` 64                                                   |
| Услуги за оплату      | `smoke-service-execution` 46                                          |
| Изображения           | `smoke-project-media` 32, `render-check-project-media` 16 (телефон)   |
| Витрина и три зрителя | `render-check-project-page` 12, `render-check-web-public` 13          |
| Оператор              | `render-check-admin-round-packages` 22, `render-check-admin-deals` 11 |
| Правила в базе        | БД 279                                                                |

Прогоны анализа требуют поднятого AI-шлюза и падают с внятным сообщением, если
его нет.
