## Этап 2 — Сущность заявки, ядро (2026-09-14, коммиты `0c283d1` … `2f8b618`)

- **Добавлено:**
  - таблица `lab.investment_applications` — заявка отдельно от проекта:
    статус `draft / submitted / archived`, core-поля (стадия, тип бизнеса,
    предмет финансирования с уточнением, сумма, валюта), ответы и
    подтверждения по ключам, версия схемы; у проекта может быть несколько
    заявок; `lab.projects.current_application_id`;
  - таблица `lab.application_policies` — ограничения основателя, одна
    активная версия; сид версии 1: 3 заявки на проект, лимит на аккаунт
    выключен, до 5 000 000 ₽ на заявку, потолок суммы открытых выключен,
    черновики считаются;
  - флаг `billing.listing_requires_subscription` (выключен) и функция
    `lab.listing_requires_subscription()`; глаголы аудита
    `lab.application.*`, `lab.application_policy.activated` (M072);
  - маршруты `GET/POST /projects/:id/applications`,
    `GET/PATCH /applications/:id`, `POST /applications/:id/submit`,
    `POST /applications/:id/archive`, `GET/POST /admin/application-policies`,
    публичный `GET /features`; группа `applications` и `features` в клиенте API;
  - у версий (`lab.project_versions`): `application_id`, `schema_version`,
    `readiness_config_version`, `completeness_pct`; `season_id` необязателен.
- **Изменено:**
  - подача заявки не требует сезона; старая кнопка «Подать в сезон» —
    обёртка: по-прежнему требует открытый сезон, подаёт текущую заявку
    проекта и проставляет `season_id`;
  - проект стал производным кешем: сумма = максимум по открытым заявкам,
    стадия — последней поданной, текущая заявка — последняя открытая или
    последний черновик; правки суммы и стадии в кабинете v1 переносятся в
    текущую заявку;
  - создание проекта заводит его первую заявку (схема 0);
  - публикация листинга проверяет подписку только при включённом флаге;
    KYC и комплаенс — всегда;
  - карточка «Подписка и счета» в кабинете v1 при выключенном барьере не
    предлагает оплату и говорит, что подача и публикация бесплатны;
  - со-основатель может запускать анализ (код искал несуществующую роль);
    валюта убрана из обновления проекта (раньше принималась и терялась).
- **Отключено / откачено:** платёжный барьер основателя — флагом, по
  умолчанию выключен. Код и данные тарифов не тронуты.
- **Правила, которые перестали действовать** (при выключенном флаге):
  «листинг требует подписку на тариф по сумме»; «рост суммы сверх тарифа у
  опубликованного проекта запрещён»; «подача возможна только в открытый
  сезон» — для новой подачи через заявку. Остаются: KYC для листинга,
  комплаенс-стоп, точное соответствие тарифа при включённом флаге.
- **Миграции:** `M071_investment_applications.sql` (схема, сид политики,
  флаг, перенос: одна заявка на проект из его полей, инварианты в самой
  миграции), `M072_application_verbs.sql`. На стенде: `npm run db:migrate`,
  затем перезапуск ядра. Откат данных не предусмотрен (expand-only; единственный
  contract-шаг — снятие `NOT NULL` с `project_versions.season_id`).
- **Настройки:** флаг `billing.listing_requires_subscription` — выключен по
  умолчанию, включается в админке; политика ограничений — через
  `POST /admin/application-policies` (экран — этап 5). Переменные окружения
  не менялись.
- **Как проверить:** `npm test -w database` (180, из них 16 по заявке),
  `npm test -w apps/core` (293), `npm test -w packages/contracts` (50);
  `node scripts/smoke-lab.mjs` — 130 проверок при выключенном барьере и 128
  при включённом (печатает, какую ветку проверяет), `node scripts/smoke-techdebt.mjs`
  — 29; `LAB_URL=http://127.0.0.1/lab/ node scripts/render-check-lab.mjs` —
  карточка подписки в обоих положениях. Чек-лист сценариев: пункт «листинг
  без подписки невозможен» действует только при включённом барьере.
- **Найдено попутно, не исправлено:** колонка кабинета v1 шире экрана на
  6px при ширине 390px (все карточки, не только подписка) — `TODO.md`;
  рендер-проверка кабинета ждёт dev-сервер на порту 5175, против nginx-стенда
  запускается с `LAB_URL`.
- **Отклонения от плана:** коммит 2.4 отдельно не понадобился (тесты в
  2.1–2.3); колонка `listed_without_subscription_at` не добавлена — ждёт
  решения владельца.
- **Стенд:** не развёрнуто (стенд на `9d63281`).
- **Обновлено в руководстве:** версия 3 — §1, §2 (новый §2.1), §3, §4, §5,
