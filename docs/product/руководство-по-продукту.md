# Руководство по продукту: что действует сейчас

Версия **11** от 2026-09-18. Код: `main` @ этап 5.6.5 (страны обслуживания в админке, регистрация со страной; видимость суммы раунда через настройку вопросов).
Боевой стенд: `https://vgorkakh.ru/` @ `9d63281` (тег `stand-2026-09-13`).

**Назначение.** Единственный документ, который обязан совпадать с кодом и
стендом. Отвечает на вопрос «что действует сейчас» для основателя,
инвестора, администратора и того, кто будет писать руководство по
эксплуатации. Обновляется в том же этапе, где меняется поведение
(`план-этапов-заявки.md`, план 0.2 §13). История — в `журнал-изменений.md`.

**Пометки.** `[код]` — реализовано в `main`; `[стенд]` — развёрнуто на
боевом стенде; `[план N]` — запланировано этапом N и **не действует**.
На дату версии стенд отстаёт от `main` на этапы 1–2 целиком: название
«Пятый элемент», сущность заявки, флаг платёжного барьера, политика
ограничений — всё это **есть в коде и не развёрнуто**. Где поведение
стенда и кода расходится, это сказано явно; `[код+стенд]` означает
совпадение.

**Название.** `[код]` Во всех вкладках, шапках, письмах и в заголовке API —
«Пятый элемент». `[стенд]` UNICORN LAUNCH до следующего выката. Внутренние
идентификаторы (пакеты, имя БД, бакет, realm, адреса) остаются `unicorn-*`
и пользователю не видны. Латинское написание не выбрано.

**Прежние правила не утверждены.** Всё, что ниже помечено `[стенд]`,
описывает, как система работала до этапа 2, а не как должно быть (план 0.2
§0а п.0). Расхождения с решениями владельца и их состояние — §9.

Ссылки вида `файл:строка` ведут в код и миграции; полный разбор — в
`docs/architecture/заявка-01-что-есть-в-коде.md`.

## 2. Путь основателя

### 2.0. Кабинет v1 `[код+стенд]` — то, что видит основатель

1. **Создать проект** — одна форма в кабинете: название, короткое описание
   (≤300), стадия (`idea / mvp / early_revenue / growth`), направление,
   сумма запроса в рублях. Поля «описание» (до 20 000 знаков), страна и
   регион в форме кабинета **отсутствуют**, хотя API их принимает; заполнить
   их можно только через служебную консоль. **Редактирования проекта из
   кабинета нет**. `[код]` Вместе с проектом создаётся его первая заявка
   (схема 0) — кабинет v1 её не показывает.
2. **Материалы** — из кабинета загружается только презентация (`deck`, pdf
   или pptx, до 50 МБ) и ссылка на продукт (только `https`, без внутренних
   адресов). Типы `video` (до 500 МБ) и `doc` (до 25 МБ) API принимает, кабинет
   — нет. Не больше 50 материалов и 5 незавершённых загрузок на проект.
   Видимости у материала нет: кто видит — решает роль (§1).
3. **Подать в сезон** — кнопка «Подать в сезон». **Требует открытого сезона**
   (`applications_open`), иначе «Приём заявок в сезон сейчас закрыт».
   Создаёт неизменяемый снимок; подавать можно повторно из статусов `draft`
   и `submitted`; статус проекта становится `submitted`. Оплаты подача не
   требует. `[код]` Снимок делается по текущей заявке проекта тем же
   механизмом, что подача заявки (§2.1); проект получает `season_id`, как и
   раньше.
4. **Запустить анализ** — кнопка; автоматически после подачи анализ **не
   запускается**. Считается по текущим полям проекта, не по снимку. Вход
   ИИ: название, короткое описание + описание, стадия, сумма, направление,
   страна, типы материалов; содержимое файлов не читается. Не больше 20
   прогонов в сутки на пользователя (`AI_ANALYSIS_DAILY_LIMIT`), один
   активный прогон на проект. Результат: паспорт с 9 осями, балл 1–10,
   карта готовности из 13 направлений, дорожная карта. Балл публикуется
   с дисклеймером «сгенерировано ИИ, сведения не проверялись».
5. **Опубликовать листинг** — условия в §5. После публикации проект виден в
   каталоге; снять можно кнопкой.
6. **Согласия на публичность** — экран есть; флаг `show.publication.enabled`
   выключен, связь флага с экраном в коде не прослеживается.
7. **Подписка и счета** — `[стенд]` карточка показывает тариф по сумме
   запроса и предлагает оформить подписку. `[код]` При выключенном барьере
   (по умолчанию) карточка говорит «Подача и публикация бесплатны: подписка
   для листинга не требуется» и оплату не предлагает; уже оформленные
   подписки и счета показываются. При включённом — прежний вид.

Черновика на клиенте нет: закрытая форма теряет ввод. Роутера в кабинете
нет: адрес страницы не меняется. Колонка кабинета на ширине 390px шире
экрана на 6px (найдено рендер-проверкой этапа 2, в `TODO.md`).

### 2.1. Заявка v2 `[код]` — API и мастер за флагом `lab.ui.application_v2`

`[код]` При включённом флаге на странице проекта появляется карточка
«Инвестиционные заявки» (список, остаток по политике, «Новая заявка») и
пошаговый мастер `/lab/applications/:id`: вводный экран с развилкой «Вы
сейчас привлекаете инвестиции?», 13 разделов профиля с навигацией и
статусами, отдельный экран раунда, автосохранение, подсказки и примеры,
готовность двумя сообщениями (минимум для подачи; заполненность в
процентах), предпросмотр «так увидит инвестор», подача без сезона. По
умолчанию флаг выключен — кабинет v1 (§2.0).

Заявка отделена от проекта (M071): у проекта их может быть несколько,
у каждой — свои версии-снимки и свой архив. Маршруты:
`GET/POST /projects/:id/applications`, `GET/PATCH /applications/:id`,
`POST /applications/:id/submit`, `POST /applications/:id/archive`.

- **Черновик свободен.** Создаётся с пустым телом; сумма, тип бизнеса и
  уточнение направления могут быть пустыми сколь угодно долго. Сохранение
  частичное: `null` очищает поле, отсутствие не трогает; ответы и
  подтверждения сливаются по ключам. Сохранение никогда не отвергается из-за
  пустого обязательного поля.
- **Что мешает подаче** отдаётся заранее (`submission.missing`): сумма,
  уточнение направления при `direction`, сумма выше потолка политики,
  `[код]` незаполненные обязательные вопросы формы (`answers.<ключ>`).
- `[код]` **Форма заявки** (`GET /applications/:id/form`) собирается из
  версии конфигурации вопросов, записанной в самой заявке (план 0.2 §0в):
  разделы, вопросы, состояние на стадии (обязательный / рекомендуемый;
  скрытые не показываются), формулировки, подсказки и примеры на языке
  запроса с запасным `ru-RU`. Новая заявка получает активную опубликованную
  версию и **живёт на ней до подачи** — публикация другой версии её не
  меняет. Стартовая конфигурация — версия 1 из банка вопросов
  (`каталог-вопросов-заявки.md` v2): 14 разделов, 91 вопрос; на стадии
  «Идея» обязательны 10 смысловых вопросов плюс стадия, сумма и предмет
  финансирования. Ответы при сохранении проверяются по типу и вариантам.
- `[код]` **Готовность заявки** (`readiness` в ответе): процент по активным
  весам разделов, статусы разделов, `canSubmit`, недостающие обязательные.
  Это полнота, а не оценка проекта.
- **Подача** не требует сезона. Создаёт неизменяемый снимок версии (core-поля,
  ответы, подтверждения, поля проекта для карточки, `[код]` применимые
  ключи, форма с формулировками на момент подачи, процент и версия весов);
  повторная подача той же заявки — новая версия. Проект получает проекцию:
  сумма = максимум по открытым заявкам, стадия — последней поданной, статус
  `submitted` из `draft`. Проект — производный кеш, история — в заявках и
  снимках.
- **Архив** — терминальный статус: обратно не открывается, освобождает место
  в лимите, снимки сохраняются.
- **Правки суммы и стадии в кабинете v1** переносятся в текущую заявку схемы 0.
- `[код]` **Раунд привлечения отдельно от профиля (5.6.3).** Профиль
  подаётся без суммы и предмета финансирования; подаче мешают только
  обязательные вопросы разделов профиля. Раунд — отдельная сущность с
  черновиком, открытием, паузой, возобновлением, закрытием с причиной и
  сменой основания тем же раундом; одна незавершённая кампания (`open`
  или `paused`) на проект; один черновик на проект — текущее ограничение
  первого интерфейса. Открыть раунд можно только со страной обслуживания
  аккаунта, валютой из её условий и поданной версией профиля как
  основанием.
- `[код]` **Раунд в мастере (5.6.4).** Состояние «привлекает ли проект
  инвестиции» определяется раундом; отдельного флага нет. На вводном экране
  — развилка: «Да — подготовить раунд» создаёт черновик и ведёт на экран
  раунда, «Пока нет — заполнить профиль» ведёт к разделам профиля и ничего
  не отменяет. Экран `/lab/applications/:id/round`: состояние (черновик /
  открыт / приостановлен / закрыт / отменён), готовность раунда отдельно от
  профиля, страна обслуживания аккаунта (первичный выбор; условия страны —
  валюты, потолок суммы, «сейчас бесплатно — пакеты ещё не введены»,
  участие оператора — рядом с суммой, без цен), вопросы разделов раунда
  (предмет финансирования, пояснение, сумма — в раунде), валюта, формат
  сделки, чек, подтверждённое со слов основателя, основание (последняя
  поданная версия; смена — явно, с причиной, с историей). Действия только
  явные, с подтверждением: открыть (после подачи профиля, при готовности и
  выбранной стране), приостановить, возобновить, закрыть с причиной, удалить
  черновик. Существующий раунд нельзя отменить или скрыть переключением
  ответа — такого переключателя нет. Черновик следующего раунда готовится
  рядом с незавершённым. Карточка «Инвестиционные заявки» на проекте
  показывает строку раунда и переход к нему.

  Итоговый доступ — два независимых условия, оба обязательны: (1) доступ к
  объекту — проект опубликован и не удалён; инвестору нужно действующее
  членство; член команды, админ и назначенный рецензент видят всё; раунд —
  только незавершённый; (2) настройка поля не строже аудитории зрителя
  (аноним — `public`, инвестор с членством — `investors`, админ —
  `platform`). Разрешённая аудитория поля не расширяет доступ к закрытому
  объекту. Закрытая группа отдаёт состояние «условия привлечения не
  раскрываются» без суммы: зритель не узнаёт даже того, идёт ли привлечение;
  фильтры и сортировки по сумме такую сумму не видят. Настройка читается из
  активной опубликованной конфигурации, поэтому публикация версии меняет
  выдачу для всех раундов сразу (каталог, тизер, избранное, карточка
  инвестору, Integration API, предпросмотр); откат версии возвращает
  прежнее. Предпросмотр в мастере показывает результат для выбранной
  аудитории теми же функциями. Раскрытие владельцем отдельного раунда не
  реализовано; если появится — только в пределах политики (`TODO.md`).

- `[код]` **Временный режим до пакетов (5.6.4, проверка 2).** Открытие,
  возобновление и увеличение суммы незавершённого раунда проходят одну
  функцию проверки коммерческих условий (`assertCommercialConditions`).
  Режим `free_until_packages`: пока в условиях страны выключены платные
  пакеты и бесплатная граница — действие бесплатно, режим записывается в
  событие перехода. Включённая, но не реализованная настройка — отказ, а не

## 5. Условия публикации листинга

Проверяются при нажатии «Опубликовать листинг» (`projects.service.ts`,
`publishListing`) и дублируются триггером БД (`M009:264-296`, `M071`):

1. Действующий KYC владельца (`kyc.has_valid_kyc(owner, 'identity')`) —
   `[код+стенд]`.
2. Тариф проекта соответствует сумме запроса (пересчитывается заново) —
   `[стенд]` барьер; `[код]` только согласованность данных.
3. **Активная подписка владельца ровно на этот тариф** — `[стенд]` всегда;
   `[код]` **только при включённом флаге** `billing.listing_requires_subscription`
   (по умолчанию выключен). Следствие точного равенства планов при включённом
   барьере: у опубликованного проекта нельзя ни поднять сумму сверх тарифа,
   ни опустить её в нижнюю ступень.
4. У действующего паспорта нет непустых флагов комплаенса (или они
   разрешены администратором) — `[код+стенд]`.

Не требуется: подача в сезон, анализ ИИ, статус проекта.

Истечение подписки листинг **не снимает**: статус `suspended_billing`
объявлен, но никем не проставляется. `[код]` При повторном включении барьера
проекты, опубликованные без подписки, **не снимаются автоматически**;
подача с ростом суммы сверх тарифа у них будет отвергнута триггером до
оформления подписки (план 0.2 §2.9.4). Отдельная отметка «опубликован
бесплатно» пока не ведётся — ждёт решения владельца.
