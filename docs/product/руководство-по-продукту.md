# Руководство по продукту: что действует сейчас

Версия **1** от 2026-09-14. Код: `main` @ `7ce1b1b`. Боевой стенд:
`https://vgorkakh.ru/` @ `9d63281` (тег `stand-2026-09-13`).

**Назначение.** Единственный документ, который обязан совпадать с кодом и
стендом. Отвечает на вопрос «что действует сейчас» для основателя,
инвестора, администратора и того, кто будет писать руководство по
эксплуатации. Обновляется в том же этапе, где меняется поведение
(`план-этапов-заявки.md`, план 0.2 §13). История — в `журнал-изменений.md`.

**Пометки.** `[код]` — реализовано в `main`; `[стенд]` — развёрнуто на
боевом стенде; `[план N]` — запланировано этапом N и **не действует**.
На дату версии стенд отстаёт от `main` только документами и одним
изменением кода: описание API (`/openapi.json`) в `main` закрыто анониму в
любом окружении (`66df3cd`), на стенде — ещё нет. Всё остальное `[код]` =
`[стенд]`, и ниже пометка `[код+стенд]` означает именно это.

**Прежние правила не утверждены.** Всё, что ниже помечено `[код+стенд]`,
описывает, как система работает, а не как должно быть (план 0.2 §0а п.0).
Расхождения с решениями владельца собраны в §9.

Ссылки вида `файл:строка` ведут в код и миграции; полный разбор — в
`docs/architecture/заявка-01-что-есть-в-коде.md`.

## 2. Путь основателя `[код+стенд]`

1. **Создать проект** — одна форма в кабинете: название, короткое описание
   (≤300), стадия (`idea / mvp / early_revenue / growth`), направление,
   сумма запроса в рублях. Поля «описание» (до 20 000 знаков), страна и
   регион в форме кабинета **отсутствуют**, хотя API их принимает; заполнить
   их можно только через служебную консоль. **Редактирования проекта из
   кабинета нет** (`apps/lab/src/pages/ProjectsPage.tsx:178-336`).
2. **Материалы** — из кабинета загружается только презентация (`deck`, pdf
   или pptx, до 50 МБ) и ссылка на продукт (только `https`, без внутренних
   адресов). Типы `video` (до 500 МБ) и `doc` (до 25 МБ) API принимает, кабинет
   — нет. Не больше 50 материалов и 5 незавершённых загрузок на проект.
   Видимости у материала нет: кто видит — решает роль (§1).
3. **Подать в сезон** — кнопка «Подать в сезон». **Требует открытого сезона**
   (`applications_open`), иначе «Приём заявок в сезон сейчас закрыт»
   (`projects.service.ts:278-287`). Создаёт неизменяемый снимок девяти полей
   проекта; материалы в снимок не входят. Подавать можно повторно из
   статусов `draft` и `submitted`; статус проекта становится `submitted`.
   Оплаты подача не требует.
4. **Запустить анализ** — кнопка; автоматически после подачи анализ **не
   запускается**. Считается по текущим полям проекта, не по снимку. Вход
   ИИ: название, короткое описание + описание, стадия, сумма, направление,
   страна, типы материалов; содержимое файлов не читается. Не больше 20
   прогонов в сутки на пользователя (`AI_ANALYSIS_DAILY_LIMIT`), один
   активный прогон на проект. Результат: паспорт с 9 осями, балл 1–10,
   карта готовности из 13 направлений, дорожная карта. Балл публикуется
   с дисклеймером «сгенерировано ИИ, сведения не проверялись».
5. **Опубликовать листинг** — условия в §5. После публикации проект виден в
   каталоге; снять можно кнопкой.
6. **Согласия на публичность** — экран есть; флаг `show.publication.enabled`
   выключен, связь флага с экраном в коде не прослеживается.
7. **Подписка и счета** — карточка тарифа показывает тариф, который требует
   сумма запроса, и предлагает оформить подписку; счёт оплачивается по
   реквизитам, приём карт выключен (`billing.payments.enabled = false`).

Черновика на клиенте нет: закрытая форма теряет ввод. Роутера в кабинете
нет: адрес страницы не меняется.

## 3. Путь инвестора `[код+стенд]`

1. Регистрация, KYC по правилам платформы.
2. Каталог опубликованных проектов: тизеры, фильтры по направлению, стадии,
   стране, сумме; сортировка по дате, сумме, релевантности; избранное.
3. Подписка инвестора `investor_membership` — 100 000 ₽/мес по сиду
   (`M011_seeds.sql:92`), создаётся в `pending_payment`, активируется
   администратором вручную (приём платежей выключен).
4. С активной подпиской — полная карточка, оценка платформы, материалы.
   Страницы проекта на публичной витрине нет; карточка — в кабинете
   инвестора.

Инвестиционные предложения, договоры, транши: контур `investments.*`
реализован, но выключен флагом `investments.enabled = false` — сделки на
платформе сейчас **заключить нельзя**.

## 5. Условия публикации листинга `[код+стенд]`

Проверяются при нажатии «Опубликовать листинг» (`projects.service.ts:703-801`)
и дублируются триггером БД (`M009:264-296`):

1. Действующий KYC владельца (`kyc.has_valid_kyc(owner, 'identity')`).
2. Тариф проекта соответствует сумме запроса (пересчитывается заново).
3. **Активная подписка владельца ровно на этот тариф** на этот проект.
   Следствие: у опубликованного проекта нельзя ни поднять сумму сверх
   тарифа, ни опустить её в нижнюю ступень — листинг ломается в обоих
   случаях (`M009:246-262`, точное равенство планов).
4. У действующего паспорта нет непустых флагов комплаенса (или они
   разрешены администратором).

Не требуется: подача в сезон, анализ ИИ, статус проекта.

Истечение подписки листинг **не снимает**: статус `suspended_billing`
объявлен, но никем не проставляется.

`[план 2]` Пункты 2–3 выключаются флагом `billing.listing_requires_subscription`
(по умолчанию выключен); KYC и комплаенс остаются (план 0.2 §2.9.2).

### 6.3. Данные, которые правит администратор `[код+стенд]`

- Тарифы (`billing.subscription_plans`): версии, цена, `ask_limit`; экран
  «Тарифы». Поле `features_jsonb` заполняется, но нигде не читается.
- Шаблоны уведомлений (`comms.notification_templates`): экран «Уведомления».

— на экране «Настройки инвестиционной заявки».

## 7. Проверки, которые выполняет система `[код+стенд]`

- Строгий разбор входа: неизвестные поля отвергаются; клиент не может
  передать тариф (`validation.ts:17-36`).
- Материалы: тип и размер по контракту до выдачи билета, сигнатура первых
  байт файла при подтверждении, только `https` и не внутренние адреса для
  ссылок.
- Подача: только из `draft` / `submitted`; версии append-only (триггер БД).
- Листинг: §5.
- Анализ: право запуска (владелец или админ), суточная квота, один активный
  прогон; перед публикацией результата проверяется, что проект и материалы
  не изменились с момента снимка входа; закрытые списки кодов и арифметика
  IRS пересчитываются кодом, а не моделью; egress-фильтр на ссылки, разметку
  и персональные данные.
- Этапы сезона: вперёд ровно на один шаг, назад нельзя; квоты и расписание.
- Аудит: каждое действие — зарегистрированный глагол в журнале с hash-chain;
  незарегистрированный глагол роняет операцию.
