## 2. Путь основателя

### 2.0. Кабинет v1 `[код+стенд]` — то, что видит основатель

1. **Создать проект** — одна форма в кабинете: название, короткое описание
   (≤300), стадия (`idea / mvp / early_revenue / growth`), направление,
   сумма запроса в рублях. Поля «описание» (до 20 000 знаков), страна и
   регион в форме кабинета **отсутствуют**, хотя API их принимает; заполнить
   их можно только через служебную консоль. **Редактирования проекта из
   кабинета нет**. `[код]` Вместе с проектом создаётся его первая заявка
   (схема 0) — кабинет v1 её не показывает.
2. **Материалы** — из кабинета загружается только презентация (`deck`, pdf
   или pptx, до 50 МБ) и ссылка на продукт (только `https`, без внутренних
   адресов). Типы `video` (до 500 МБ) и `doc` (до 25 МБ) API принимает, кабинет
   — нет. Не больше 50 материалов и 5 незавершённых загрузок на проект.
   `[стенд]` Видимости у материала нет: кто видит — решает роль (§1).
   `[код]` **С 5.7.4** у каждого материала отметка «Только команда» /
   «Инвесторам» — кнопка в карточке материалов; открывается допущенным
   инвесторам только отметкой, привязка к ответу файл не открывает.
   `[код]` **«Кто может видеть проект» (5.7.4)** — карточка на странице
   проекта вместо кнопок листинга: режим, кто увидит, состояние согласия,
   что станет видно после применения новых условий, конфликты «ответ виден
   — подтверждение закрыто», «Применить новые условия», предпросмотр по
   аудиториям. На экране раунда перед открытием — блок «Что увидят после
   открытия» с проекциями для анонима и инвестора; открытие подтверждает
   именно показанный предпросмотр.
3. **Подать в сезон** — `[код]` **убрано (M088, 2026-09-18): сезоны
   отложены.** Кнопки в кабинете нет; маршрут `POST /projects/:id/submit`
   отвечает «функция недоступна» (503 `feature_disabled`), пока флаг
   `seasons.enabled` выключен. Профиль подаётся мастером заявки без сезона
   (§2.1). `[стенд]` Прежнее поведение: кнопка «Подать в сезон», **требует
   открытого сезона** (`applications_open`), иначе «Приём заявок в сезон
   сейчас закрыт». Создаёт неизменяемый снимок; подавать можно повторно из
   статусов `draft` и `submitted`; статус проекта становится `submitted`.
   Оплаты подача не требует. `[код]` Снимок делается по текущей заявке проекта тем же
   механизмом, что подача заявки (§2.1); проект получает `season_id`, как и
   раньше.
4. **Запустить анализ** — кнопка; автоматически после подачи анализ **не
   запускается**. Считается по текущим полям проекта, не по снимку. Вход
   ИИ: название, короткое описание + описание, стадия, сумма, направление,
   страна, типы материалов; содержимое файлов не читается. Не больше 20
   прогонов в сутки на пользователя (`AI_ANALYSIS_DAILY_LIMIT`), один
   активный прогон на проект. Результат: паспорт с 9 осями, балл 1–10,
   карта готовности из 13 направлений, дорожная карта. Балл публикуется
   с дисклеймером «сгенерировано ИИ, сведения не проверялись».
5. **Опубликовать листинг** — условия в §5. После публикации проект виден в
   каталоге; снять можно кнопкой.
6. **Согласия на публичность** — экран есть; флаг `show.publication.enabled`
   выключен, связь флага с экраном в коде не прослеживается.
7. **Подписки основателя больше нет.** `[стенд]` карточка «Подписка и
   счета» показывала тариф по сумме запроса и предлагала оформить подписку.
   `[код]` С M094 карточка удалена вместе с моделью: публикация проекта
   бесплатна, а запуск конкретного раунда будет оплачиваться разово (5.9).
   Подписки инвесторов не затронуты.

Черновика на клиенте нет: закрытая форма теряет ввод. Роутера в кабинете
нет: адрес страницы не меняется. Колонка кабинета на ширине 390px шире
экрана на 6px (найдено рендер-проверкой этапа 2, в `TODO.md`).

### 2.1. Заявка v2 `[код]` — API и мастер за флагом `lab.ui.application_v2`

`[код]` При включённом флаге на странице проекта появляется карточка
«Инвестиционные заявки» (список, остаток по политике, «Новая заявка») и
пошаговый мастер `/lab/applications/:id`: вводный экран с развилкой «Вы
сейчас привлекаете инвестиции?», 13 разделов профиля с навигацией и
статусами, отдельный экран раунда, автосохранение, подсказки и примеры,
готовность двумя сообщениями (минимум для подачи; заполненность в
процентах), предпросмотр «так увидит инвестор», подача без сезона. По
умолчанию флаг выключен — кабинет v1 (§2.0).

Заявка отделена от проекта (M071): у проекта их может быть несколько,
у каждой — свои версии-снимки и свой архив. Маршруты:
`GET/POST /projects/:id/applications`, `GET/PATCH /applications/:id`,
`POST /applications/:id/submit`, `POST /applications/:id/archive`.

- **Черновик свободен.** Создаётся с пустым телом; сумма, тип бизнеса и
  уточнение направления могут быть пустыми сколь угодно долго. Сохранение
  частичное: `null` очищает поле, отсутствие не трогает; ответы и
  подтверждения сливаются по ключам. Сохранение никогда не отвергается из-за
  пустого обязательного поля.
- **Что мешает подаче** отдаётся заранее (`submission.missing`): сумма,
  уточнение направления при `direction`, сумма выше потолка политики,
  `[код]` незаполненные обязательные вопросы формы (`answers.<ключ>`).
- `[код]` **Форма заявки** (`GET /applications/:id/form`) собирается из
  версии конфигурации вопросов, записанной в самой заявке (план 0.2 §0в):
  разделы, вопросы, состояние на стадии (обязательный / рекомендуемый;
  скрытые не показываются), формулировки, подсказки и примеры на языке
  запроса с запасным `ru-RU`. Новая заявка получает активную опубликованную
  версию и **живёт на ней до подачи** — публикация другой версии её не
  меняет. Стартовая конфигурация — версия 1 из банка вопросов
  (`каталог-вопросов-заявки.md` v2): 14 разделов, 91 вопрос; на стадии
  «Идея» обязательны 10 смысловых вопросов плюс стадия, сумма и предмет
  финансирования. Ответы при сохранении проверяются по типу и вариантам.
- `[код]` **Готовность заявки** (`readiness` в ответе): процент по активным
  весам разделов, статусы разделов, `canSubmit`, недостающие обязательные.
  Это полнота, а не оценка проекта.
- **Подача** не требует сезона. Создаёт неизменяемый снимок версии (core-поля,
  ответы, подтверждения, поля проекта для карточки, `[код]` применимые
  ключи, форма с формулировками на момент подачи, процент и версия весов);
  повторная подача той же заявки — новая версия. Проект получает проекцию:
  сумма = максимум по открытым заявкам, стадия — последней поданной, статус
  `submitted` из `draft`. Проект — производный кеш, история — в заявках и
  снимках.
- **Архив** — терминальный статус: обратно не открывается, освобождает место
  в лимите, снимки сохраняются.
- **Правки суммы и стадии в кабинете v1** переносятся в текущую заявку схемы 0.
- `[код]` **Раунд привлечения отдельно от профиля (5.6.3).** Профиль
  подаётся без суммы и предмета финансирования; подаче мешают только
  обязательные вопросы разделов профиля. Раунд — отдельная сущность с
  черновиком, открытием, паузой, возобновлением, закрытием с причиной и
  сменой основания тем же раундом; одна незавершённая кампания (`open`
  или `paused`) на проект; один черновик на проект — текущее ограничение
  первого интерфейса. Открыть раунд можно только со страной обслуживания
  аккаунта, валютой из её условий и поданной версией профиля как
  основанием.
- `[код]` **Раунд в мастере (5.6.4).** Состояние «привлекает ли проект
  инвестиции» определяется раундом; отдельного флага нет. На вводном экране
  — развилка: «Да — подготовить раунд» создаёт черновик и ведёт на экран
  раунда, «Пока нет — заполнить профиль» ведёт к разделам профиля и ничего
  не отменяет. Экран `/lab/applications/:id/round`: состояние (черновик /
  открыт / приостановлен / закрыт / отменён), готовность раунда отдельно от
  профиля, страна обслуживания аккаунта (первичный выбор; условия страны —
  валюты, потолок суммы, «сейчас бесплатно — пакеты ещё не введены»,
  участие оператора — рядом с суммой, без цен), вопросы разделов раунда
  (предмет финансирования, пояснение, сумма — в раунде), валюта, формат
  сделки, чек, подтверждённое со слов основателя, основание (последняя
  поданная версия; смена — явно, с причиной, с историей). Действия только
  явные, с подтверждением: открыть (после подачи профиля, при готовности и
  выбранной стране), приостановить, возобновить, закрыть с причиной, удалить
  черновик. Существующий раунд нельзя отменить или скрыть переключением
  ответа — такого переключателя нет. `[код]` **Ввод денежных полей**
  (сумма, чеки, подтверждённое): принимается привычная запись — пробелы
  между разрядами и запятая как разделитель копеек; разобранное значение
  показывается в поле в нормализованном виде, чтобы замена была видна.

  ошибке стоит у поля, введённое остаётся на месте и прежней суммой не
  подменяется. Значение уходит по уходу из поля; сумму всё равно
  проверяет сервер. Черновик следующего раунда готовится
  рядом с незавершённым. Карточка «Инвестиционные заявки» на проекте
  показывает строку раунда и переход к нему.

  Итоговый доступ — два независимых условия, оба обязательны: (1) доступ к
  объекту — проект опубликован и не удалён; инвестору нужно действующее
  членство; член команды, админ и назначенный рецензент видят всё; раунд —
  только незавершённый; (2) настройка поля не строже аудитории зрителя
  (аноним — `public`, инвестор с членством — `investors`, админ —
  `platform`). Разрешённая аудитория поля не расширяет доступ к закрытому
  объекту. Закрытая группа отдаёт состояние «условия привлечения не
  раскрываются» без суммы: зритель не узнаёт даже того, идёт ли привлечение;
  фильтры и сортировки по сумме такую сумму не видят. Состояние можно
  показывать, скрывая сумму; сумма без состояния не показывается.

  **Версия условий и последствия изменений (5.6.6, M086).** У раунда при
  открытии фиксируется версия условий раскрытия. Эффективная видимость
  поля — **строже** из активной конфигурации и версии условий раунда.
  Поэтому: ограничение (например, public → investors) действует сразу на
  все раунды, включая открытые, — прежняя утечка не сохраняется;
  расширение (investors → public) касается только раундов, открытых после
  публикации, — ранее закрытые данные не раскрываются задним числом. Так
  действовало до 5.7. `[код]` **С 5.7 (M087–M090)** к этому добавлено
  разрешение владельца: расширение условий существующего раунда — действие
  «Применить новые условия» (профиль и раунд, без нового раунда), шире
  политики раскрыть нельзя. Все пути выдачи (каталог, тизер, избранное, карточка
  инвестору, Integration API, предпросмотр) читают одну функцию.
  Integration API — публичная аудитория по построению: сессия интеграции
  без пользователя; инвесторскую проекцию по интеграционному маршруту
  получить нельзя; доступ к маршруту — ключ сервисного аккаунта с областью
  `graduates:read`.

- `[код]` **Временный режим до пакетов (5.6.4, проверка 2).** Открытие,

- `[код]` **Страна аккаунта (5.6.4, проверка 3).** Первичный выбор и

2. Каталог опубликованных проектов: тизеры, фильтры по направлению, стадии,

4. С активной подпиской — полная карточка, оценка платформы, материалы.
   `[код]` Состояние и сумма раунда, предмет финансирования — по настройке

registered_investors | selected_investors`) с проверками листинга;

   открывает. В закрытых режимах посторонний не получает даже названия:
   ответ 404.
   `[код]` **Кабинет инвестора (5.7.4)** показывает карточку проекта из

   «Выбранные инвесторы» сам по себе ничего не раскрывает: проект видит
   только тот, кому владелец выдал разрешение (`GET|POST
/projects/:id/access`, `DELETE /projects/:id/access/grants/:id`).
   Разрешение — НАБОР частей (ответы анкеты, раунд, материалы, оценка
   платформы, расширенные данные); тизер отдельно не выдаётся и
   открывается вместе с любым разрешением. Получатель называется точным
   адресом почты — поиска по людям у владельца нет; в ответах и журнале

   любое разрешение; в режиме `public` оно надёжно только против входа под
   учётной записью, и кабинет говорит это прямо. Коммерческий допуск
   выбранному получателю не требуется: его допустил владелец лично.
   Получателю в карточке сказано, что доступ открыл владелец проекта и
   какого числа; внутренняя причина выдачи или исключения ему не
   показывается. Сужение набора закрывает прежние права сразу — вместе со
   списком материалов и прямой выдачей файла; отзыв закрывает и карточку,

   учитывает, а триггер БД не даёт их создать — недоступно и через API, и

   сохранены: возврат — вместе с настоящим членством (`TODO.md`,
   направление «Организации и участники»).
   `[код]` **Старые пути закрыты (5.7.5, M090).** `GET /projects/:id`,

## 5. Условия публикации листинга

`[код]` С 5.7.3 листинг — следствие режима «кто может видеть проект»
(`PUT /projects/:id/visibility`): открытые режимы проходят проверки ниже,
`private` снимает листинг; кнопки «Опубликовать листинг» / «Снять листинг» —
обёртки над режимами `public` / `private`.

Проверяются действием «Кто может видеть проект» (`projects.service.ts`,
`publishAs`; листинг — следствие режима, 5.7.3):

1. Действующий KYC владельца (`kyc.has_valid_kyc(owner, 'identity')`) —
   `[код+стенд]`.
2. У действующего паспорта нет непустых флагов комплаенса (или они
   разрешены администратором) — `[код+стенд]`.

Тарифа и подписки среди условий больше нет: ежемесячная подписка основателя
по сумме отменена (M094), барьер листинга и его триггер удалены. `[стенд]`
до выката действует прежнее правило с подпиской.

Не требуется: подача в сезон, анализ ИИ, статус проекта.

Статус `suspended_billing` объявлен в схеме, но никем не проставляется:
снимать листинг за неоплату нечему — оплаты за публикацию нет. Что будет
происходить с раундом при неоплаченном пакете, решается в 5.9.

## 7. Проверки, которые выполняет система

- Строгий разбор входа: неизвестные поля отвергаются; клиент не может
  передать тариф (`validation.ts:17-36`). `[код]` Валюта из обновления
  проекта убрана: раньше принималась и молча терялась.
- Материалы: тип и размер по контракту до выдачи билета, сигнатура первых
  байт файла при подтверждении, только `https` и не внутренние адреса для
  ссылок.
- Подача проекта в сезон: только из `draft` / `submitted`; версии
  append-only (триггер БД). `[код]` Подача заявки: сумма и уточнение
  направления обязательны (сервис, функция готовности и условные CHECK в
  таблице), обязательные вопросы формы версии заявки заполнены, потолок
  суммы по политике, потолок суммы открытых заявок, проект не
  `rejected`/`archived`.
- `[код]` Ответы заявки: по форме её версии — тип, ограничения, коды
  вариантов, только ключи документа; ссылки только `https://`. Схема 0 —
  свободна. Опубликованная версия конфигурации неизменяема (триггер БД);
  черновик и публикация — под одним локом.
- `[код]` Создание заявки: остаток по политике под advisory-локом проекта;
  отказ называет остаток и способ освободить место.
- Листинг: §5.
- Анализ: право запуска (владелец, `[код]` со-основатель, админ), суточная
  квота, один активный прогон; перед публикацией результата проверяется, что
  проект и материалы не изменились с момента снимка входа; закрытые списки
  кодов и арифметика IRS пересчитываются кодом, а не моделью; egress-фильтр
  на ссылки, разметку и персональные данные.
- Этапы сезона: вперёд ровно на один шаг, назад нельзя; квоты и расписание.
- Аудит: каждое действие — зарегистрированный глагол в журнале с hash-chain;
  незарегистрированный глагол роняет операцию. `[код]` Новые глаголы:
  `lab.application.created/updated/submitted/archived`,
  `lab.application_policy.activated`,
  `lab.application_form.draft_saved/published/activated`,
  `lab.readiness_config.activated`.
- `[код]` Подтверждение ответа принимается только материалами того же
  проекта, уже загруженными; иначе ошибка у поля `evidence.<ключ>` (5.6.0).
- `[код]` Публичный рейтинг сезона показывает только проекты из публичного
  каталога; позиции не пересчитываются (5.6.0). **С M088 маршрут рейтинга
  закрыт целиком** (503), пока сезоны отложены.
