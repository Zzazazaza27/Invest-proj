## 1. Терминология и что нам реально нужно

| Понятие                | Что это                                                                                                   | Примеры                                                                                        |
| ---------------------- | --------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| **Coding agent**       | модель + цикл «думает → вызывает инструменты → правит код»                                                | Claude Code, Codex CLI, Gemini CLI                                                             |
| **Harness**            | обвязка вокруг модели: промпты, инструменты, права, управление контекстом, цикл                           | Claude Code и Codex — это и агент, и harness; Cline, OpenCode, Goose — самостоятельные harness |
| **Agent runtime**      | где и как агент исполняется: процесс, песочница, виртуальная машина, облако                               | облачные сессии Claude Code, Docker Sandboxes, Claude Managed Agents                           |
| **Orchestrator**       | управляет многими сессиями агентов: раздаёт задачи, изолирует (worktree), показывает статусы, собирает PR | Orca, Emdash, Orchestrator.inc, Symphony                                                       |
| **Workflow engine**    | надёжное выполнение шагов с повторами и состоянием, не про ИИ                                             | GitHub Actions, Temporal, Inngest                                                              |
| **Multi-agent system** | несколько агентов с ролями, общающиеся друг с другом                                                      | agent teams в Claude Code, Gas Town                                                            |

**Где понятия пересекаются.** Вендоры склеивают слои: Claude Code одновременно
агент, harness, оркестратор (фоновые сессии, субагенты), runtime (облачные
сессии) и планировщик (routines). Поэтому вопрос «какой оркестратор» часто
снимается: часть слоёв уже есть в продукте, который у нас оплачен.

**Что нам реально требуется** — не «много агентов», а конвейер:
`задача с критериями приёмки → работа в изоляции → автоматическая проверка →
независимое ревью → человек решает только критичное → слияние с доказательствами
→ воспроизводимый откат`, плюс наблюдаемость. Параллельность вторична: её
выгода упирается в конфликты слияния и в лимиты подписки (раздел 2).

## 2. Условия использования подписок — главное ограничение

### Claude (Pro/Max)

Проверено мной по первоисточникам (Legal and compliance; справка 2026-10-07).

**Разрешено на подписке** (всё через **неизменённый** бинарник Claude Code,
вход под своим аккаунтом):

- интерактивный Claude Code; фоновые сессии (`claude --bg`, `claude agents`),
  субагенты, worktree;
- облачные сессии (`claude --cloud`, веб) и **routines** (по расписанию, API,
  событию GitHub);
- `claude -p` в скриптах и **GitHub Action** `claude-code-action` с токеном
  `CLAUDE_CODE_OAUTH_TOKEN` (`claude setup-token`) — документация пишет, что
  запуски идут за счёт подписки;
- Agent SDK для **личного** использования: справка от 2026-10-07 — «You can
  still use the Claude Agent SDK, `claude -p`, and third-party apps with your
  subscription limits».

**Запрещено** (формулировки Anthropic, кратко): использовать подписочные
OAuth-данные «on behalf of their users» в своих продуктах; предлагать
claude.ai-вход в чужих приложениях; «collect, store, or intermediate»
подписочные токены. Разработчикам, строящим продукты на Agent SDK, велено
использовать API-ключ. Лимиты «assume ordinary, individual usage», и
Anthropic оставляет за собой принудительные меры «without prior notice».

**Сторонние harness.** Если harness сам ходит в API с подписочным токеном
(OpenCode, Cline, самописные) — запрещено; по вторичным источникам в январе–
апреле 2026 это блокировалось (OpenCode убрал вход по подписке). Если
оркестратор лишь запускает **настоящий `claude`** (Emdash, Orchestrator.inc,
Orca, Claude Squad), а вход делаете вы — это попадает под формулировку
«unmodified binary», **но отдельного списка разрешённых оркестраторов у
Anthropic нет**: это моя интерпретация текста, не гарантия.

**Новое от 2026-10-07:** Max 5x/20x получают **$100 / $200 в месяц API-кредитов**
(Team — $20/$100 на место). Они покрывают Agent SDK и `claude -p`, **только если
вызов идёт по API-ключу Console**; интерактивный Claude Code, GitHub Action,
IDE и десктоп не покрывают. Не накапливаются, нужно 7 дней на тарифе.

**Лимиты.** Пятичасовое окно и недельный лимит; Claude Code и чат делят пул;
**каждая параллельная сессия расходует квоту независимо** (10 агентов — примерно
в 10 раз быстрее выгорание), agent teams тратят заметно больше. Числа лимитов
Anthropic не публикует; цена Max 5x/20x на странице тарифов указана как «from
$100» — **точные цены НЕ ПРОВЕРЕНЫ**.

### OpenAI (ChatGPT)

- Codex CLI, IDE, десктоп и `codex exec` официально работают по входу через
  ChatGPT; **облако Codex требует входа через ChatGPT** (developers.openai.com/codex/auth).
- GitHub-Action Codex описан только с **API-ключом**; вход через ChatGPT там не
  подтверждён. Для CI OpenAI рекомендует API-ключ.
- Для сторонних harness у OpenAI есть **программа «Sign in with ChatGPT»**
  (запросы по лимитам плана Plus/Pro; партнёры по вторичному источнику —
  OpenCode, Warp, Amp, Conductor и др.). Повторное использование
  `~/.codex/auth.json` сторонними инструментами — **серая зона**, прямого
  разрешения или запрета не найдено. Тексты Terms of Use не получены.

### Экономика API отдельно (иллюстрация, не измерение)

Допущение на час одной активной сессии: ~5 млн токенов чтения кэша, ~0,3 млн
записи кэша, ~0,1 млн выхода. Цены Anthropic — со страницы платформы.

| Модель               | Цена за 1 млн (вход / запись кэша / чтение кэша / выход) | ≈ за час сессии             |
| -------------------- | -------------------------------------------------------- | --------------------------- |
| Sonnet 5.5           | $2 / $2,5 / $0,10 / $10                                  | $2–3                        |
| Opus 5.5             | $4 / $5 / $0,20 / $20                                    | $4–5                        |
| Fable 5.1            | $10 / $12,5 / $0,25 / $50                                | $10–11                      |
| GPT-6.1 Sol (OpenAI) | $2 / — / $0,10 / $10                                     | ≈ $3 (оценка исследователя) |

3–5 параллельных агентов по 6–8 часов в день на Opus/Fable — порядка
**$20–100 и более в день**. Реальный расход зависит от размера контекста; чтобы
получить свои числа, нужен замер (`/cost` в API-режиме или логи). Подписка
фиксирует цену, но упирается в недельный лимит. Побочное правило: **подписку
для автоматизации можно использовать только в официальных путях выше;
API-ключ нужен для всего, что строим сами на SDK.**

## 5. Покупать или строить

Лестница: готовое → конфигурация готового → небольшой собственный слой →
собственный harness. **Предлагается остановиться на третьей ступени**:
конфигурируем Claude Code и GitHub (возможности есть), собственный слой —
небольшой набор файлов и скриптов; **собственный harness не нужен**, и
Symphony не нужен как программа (только как образец конвейера).

### Что придётся сделать самим при любом готовом harness

1. **Карточка задачи**: цель, критерии приёмки, **класс риска** — до работы агента.
2. **Политика критичного**: список путей и действий (миграции, billing/auth,
   `deploy.mjs`, секреты, юридически значимое), для которых агент **не решает
   сам** — hooks `PreToolUse` + `CODEOWNERS` + правила ветки.
3. **Граница окружения агента**: у агента **не должно быть доступа к
   боевому серверу и секретам**. Наш `deploy.mjs` использует корневой SSH-ключ
   с вашей машины: любой локальный агент им воспользуется, если разрешить.
   Это не теория: публичные инциденты 2026 года — агент стёр прод-базу с
   бэкапами (PocketOS, апрель; токен нашёлся в постороннем файле) и
   DataTalks.Club (март, через Terraform).
4. **Селектор проверок** по diff (из матрицы изменений).
5. **Шаблон PR с доказательствами** (что запущено, что не запущено).
6. **Сбор метрик внимания** (раздел 7).
7. **Решение для Windows:** у Claude Code нет песочницы на нативном Windows;
   варианты — облачные сессии (VM Anthropic), WSL2, контейнер, Docker Sandboxes
   или VM. Windows 10 Enterprise: нативная песочница Codex — Windows 11.

## 6. Что мы могли не учитывать (по важности для нас)

1. **Нет песочницы на нативном Windows** (Claude Code; у Codex — Windows 11).
   Автономная работа без присмотра безопаснее в облачных сессиях или WSL2.
2. **`CLAUDE.md` — контекст, а не принуждение** (документация говорит это
   прямо). Ворота — только `PreToolUse`-хуки, причём таймаут хука по умолчанию
   **не блокирует** вызов; нужен `onFailure: "block"` (с версии 2.1.295).
3. **Локальные ворота не действуют на облачных агентов.** `pre-push` стоит
   только у вас; всё важное — в CI и правилах ветки нового репозитория.
4. **Управляемое ревью Claude не блокирует слияние** и доступно только на
   Team/Enterprise; нужен разбор JSON чек-рана или свой скрипт. Локальный
   `/code-review` и Codex-ревью доступны вам сейчас.
5. **Независимые ревьюеры ловят примерно половину дефектов**; «два ревьюера» —
   разумная защита, не гарантия; оценить их надо на наших исторических
   дефектах (у нас есть история `fix:`-коммитов).
6. **Routines работают без запросов разрешений и пишут от вашего имени
   GitHub**; зелёный статус значит «сессия отработала», а не «задача решена».
7. **`AGENTS.md` и Agent Skills — переносимые открытые стандарты** (Linux
   Foundation / открытый формат): правила в них не привязывают нас к Claude.
8. **Постоянная память-плагины (claude-mem, mem0, Graphiti)** не нужны: у нас
   память — это Git и Markdown; независимых доказательств выигрыша нет.
9. **Spec Kit / OpenSpec / BMAD** — спецификации как процесс; у нас уже есть
   документы. Для нас полезнее другое: критерии приёмки как исполняемые
   проверки.
10. **Мутационное тестирование (Stryker)** как слой проверки тестов, которые
    пишет сам агент (иначе агент подгоняет тесты под код).
11. **Claude Managed Agents** (хостинг harness по API, токены + около $0,08 за
    час сессии, по вторичным источникам) — это про агентов **внутри продукта**,
    не про нашу разработку; пригодится для дорожки «агентная организация», не
    сейчас.
12. **Люди плохо оценивают собственную скорость с ИИ:** исследование METR 2025
    — участники ждали ускорения на 20%, фактически замедление ≈19% (вторичный
    пересказ); повтор 2026 года не удался методически. Вывод: **нужно мерить
    своё, а не доверять ощущениям.**

## 7. Метрики: «качественный законченный результат на час внимания владельца»

Главная: **M1 = принятые задачи / часы внимания владельца.** Остальные —
чтобы понять, из чего она складывается. «Принята» = слита в `main`, критерии
приёмки выполнены, CI зелёный.

| #   | Метрика                                                                                   | Как измерять                          | Базовое значение сейчас                                     |
| --- | ----------------------------------------------------------------------------------------- | ------------------------------------- | ----------------------------------------------------------- |
| M1  | принятых задач на час внимания                                                            | журнал внимания + список слитых задач | **нет** (внимание не записывалось)                          |
| M2  | минуты внимания на принятую задачу                                                        | запись: постановка + решения + ревью  | нет                                                         |
| M3  | доля задач, принятых с первого раза (без возврата на доработку)                           | отметка при слиянии                   | нет                                                         |
| M4  | дефекты, ушедшие дальше: `fix:`-коммиты и откаты по той же области за 14/30 дней          | `git log` по областям                 | косвенно: за 6 недель 89 `feat` и 68 `fix` (отношение 0,76) |
| M5  | доля задач с зелёным CI с первого пуша; сколько дефектов поймали ворота до человека       | CI + PR                               | нет                                                         |
| M6  | автономность: доля задач без вопросов человеку; число эскалаций и доля обоснованных       | журнал                                | нет                                                         |
| M7  | стоимость на принятую задачу: доля недельного лимита (или $ по API)                       | счётчик лимита / OTel                 | нет                                                         |
| M8  | время на обслуживание самой системы                                                       | журнал внимания                       | нет                                                         |
| M9  | целостность архитектуры: нарушения `gate:boundary`, дубли, замечания ревью по архитектуре | ворота + ревью                        | частично (есть `gate:boundary`)                             |

**База из Git** (2026-09-02 … 10-12, один человек + Claude): 421 коммит;
из них 222 `docs`, 89 `feat`, 68 `fix`; код (без документов) +107,9 тыс. /
−10,7 тыс. строк; пик 134 коммита в неделю. Это **объём**, а не результат на
час внимания: внимание в Git не видно. Поэтому с первого дня эксперимента
нужен простой **журнал внимания** (запись на задачу: сколько минут ушло на
постановку, решения, ревью).

## 8. Что попробовать первым

**Первым:** родной стек Claude Code + GitHub, **без установки сторонних
оркестраторов**. Почему: он уже оплачен, использует только официальные пути
(низкий риск условий), закрывает почти все нужные слои (фоновые сессии,
worktree, hooks-ворота, Auto-fix PR, ревью), а недостающее мы строим малым
собственным слоем.

### Минимальный эксперимент (около 2 недель, 8–12 реальных небольших задач)

**Предусловия** (не часть эксперимента): новый репозиторий с CI на нём
(защита `main`: обязательные проверки); решение по границе окружения агента
(нет боевых ключей и SSH).

**Подготовка (небольшой собственный слой):**

1. Шаблон карточки задачи (цель, критерии приёмки, класс риска).
2. Список критичных путей + `CODEOWNERS` + правила разрешений/хуки
   `PreToolUse` на них (миграции, billing/auth, `deploy.mjs`, секреты).
3. Шаблон PR с блоком «что проверено / что не запускалось».
4. Журнал внимания (таблица, минуты).
5. Скрипт-селектор проверок по diff (из матрицы изменений) — только если
   без него задачи не проходят ворота.

**Две ветки сравнения на одних и тех же типах задач** (из `TODO.md`, не
критичных, чередуя):

- **A, как сейчас:** интерактивная сессия, владелец ведёт и принимает.
- **B, конвейер:** задача по шаблону → `claude --bg` в worktree (или облачная
  сессия) → PR → CI + локальный `/code-review` (+ Codex-ревью как второй
  взгляд) → владелец смотрит **только PR и доказательства**; критичное
  останавливается хуком/`CODEOWNERS`.

**Ограничения:** не более 2–3 задач в работе одновременно (иначе очередь
ревью съест выигрыш); критичные области не трогаются; лимит расходов
фиксирован заранее.

**Что сравниваем:** M1–M9. **Решение после эксперимента:** конвейер B становится
основным только если M1 заметно выше при не худшем M4; тогда — второй шаг
(routines и Auto-fix PR; затем, возможно, пробный UI-оркестратор на 3 дня).

### Расходы и риски

|               |                                                                                                                                                                                             |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Деньги        | подписки уже есть; Codex-ревью — ChatGPT-подписка (если нет — $20 Plus); резерв на API по расчётам раздела 2. Ограничитель — недельный лимит Max                                            |
| Лимиты        | параллельные сессии выжигают недельный лимит; планировать по числу одновременных сессий, не по часам                                                                                        |
| Условия       | лежим в официальных путях; риск остаётся у «ordinary, individual usage» при тяжёлой автоматизации (Anthropic оставляет принудительные меры без предупреждения); запасной вариант — API-ключ |
| Безопасность  | нет песочницы на нативном Windows → агент не получает боевых доступов; критичное — ворота                                                                                                   |
| Стабильность  | routines, agent view, Agent HQ — preview; правила меняются, нельзя строить на них единственный путь                                                                                         |
| Время         | подготовка ≈ 1–2 дня; обслуживание фиксируем как M8                                                                                                                                         |
| Ложный сигнал | малая выборка, одна команда из одного человека: это наблюдение, не статистика                                                                                                               |
