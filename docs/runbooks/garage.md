# Garage: отказы узлов и восстановление копий

Работа № 4 раздела 01 (2.1.2, 4.9). Поведение подтверждено в изолированной среде
`scripts/check-garage-faults.mjs` (CHK-GARAGE-FAULTS): три узла, `replication_factor = 3`,
`consistent`, конфигурация `infra/garage/garage.toml` как на VPS. Команды `garage` — внутри
контейнера узла: `docker exec fifth-garage-1 /garage …` (у образа нет оболочки).

## Что видит платформа

| Случай                       | Запись (загрузки)                                                                                                                                | Чтение                                              | Что делать                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------- | --------------------------------------------------------------- |
| Один узел из трёх остановлен | идёт (кворум 2 из 3)                                                                                                                             | идёт                                                | вернуть узел; копии догонят сами, при сомнении — ремонт ниже    |
| Два узла остановлены         | передача висит до предела, материал не становится готовым; «Файлы» — запись закрыта (`dependency_failure`), новые загрузки — `group_unavailable` | 503: в режиме `consistent` чтению тоже нужен кворум | вернуть узлы; начатые загрузки завершаются повтором «завершить» |
| Узел отрезан от сети «молча» | первые ~60–75 с запись ждёт отрезанный узел, «Файлы» закрываются; после того как Garage пометит узел отключённым — запись идёт через большинство | идёт                                                | вернуть связь, затем ремонт                                     |
| Остановлен `garage-1`        | «Файлы» отказывают, хотя кворум есть: ядро ходит в Garage только через него (`S3_ENDPOINT`)                                                      | отказ                                               | вернуть `garage-1`; это свойство нынешней конфигурации          |

Ложной готовности нет: материал становится готовым только после того, как хранилище
подтвердило объект. Объект, переданный до отказа, после возврата узлов завершается штатно.

## Ремонт после возврата узла или связи

```
docker exec fifth-garage-1 /garage repair -a --yes tables
docker exec fifth-garage-1 /garage repair -a --yes blocks
docker exec fifth-garage-1 /garage stats -a
```

Готово, когда у всех узлов одинаковое «number of RC entries» и `blocks with resync errors: 0`.
Пустой «resync queue» не ждать: Garage держит там блоки на плановую повторную проверку.
Ремонт — разовый проход: если блоки не сравнялись за пару минут (запущен сразу после возврата
узла), повторить `repair -a --yes blocks` и `block retry-now --all` на отстающем узле.

## Замена диска узла (данные потеряны, метаданные целы)

Garage **не запускается** на пустом каталоге данных: «Could not find expected marker file
`garage-marker`». Это защита от работы с неподключённым диском; создать метку вручную нельзя —
у неё своё содержимое («Mismatched content»). Порядок (подтверждён 12.11 в CHK-GARAGE-FAULTS):

1. Убедиться, что новый диск смонтирован в каталог данных узла.
2. Удалить файл `data_layout` в каталоге **метаданных** узла (`/var/lib/garage/meta/data_layout`).
   Garage заново разметит новый каталог данных и сам запишет метку.
3. Запустить узел, дождаться `GetClusterHealth` = `healthy`.
4. Ремонт (выше); проверка — одинаковое число блоков у всех узлов, ошибок нет.

Шаг 2 делает только человек после проверки шага 1 — автоматизировать нельзя, иначе защита
теряет смысл.

## Срок подписанной формы

Garage проверяет срок формы **в начале** запроса: передача, начатая до срока, принимается целиком,
даже если длится дольше (опыт 12.11: форма 60 с, передача 103 с — 204, объект целый; у прежнего
MinIO в том же опыте 30.10 — «Policy expired»). Передача, начатая после срока, — `400
InvalidRequest`, объекта нет. Форма материалов ядра — `MATERIAL_UPLOAD_FORM_TTL_SECONDS`
(по умолчанию 5700 с).

## Lifecycle

`scripts/garage-init.mjs` ставит бакету файлов одно правило: незавершённые multipart-загрузки —
удалять через 1 день (`AbortIncompleteMultipartUpload`). Объекты правило не удаляет (нет
`Expiration`). Ядро грузит формой одним запросом; multipart может начать только клиент с ключом
записи. Garage применяет правило раз в сутки. Вручную:
`garage bucket cleanup-incomplete-uploads --older-than 1d <бакет>`.

На серверах правило появится при следующем запуске `garage-init` (общая приёмка).
