## Выпуск во время отказа DNS

Пока имена 5espace.com не разрешаются, проверки по имени дадут отказ из-за
уже известной причины, и выпуск откатится зря. Поэтому на время выпуска
проверкам задаётся **закреплённый IP** (`scripts/lib/pinned-fetch.mjs`):

```
PUBLIC_PIN=5espace.com=193.233.217.210,files.5espace.com=193.233.217.210
```

Соединение идёт на этот IP, но адрес в запросе — имя. Поэтому **Host и SNI
— имя, сертификат проверяется по имени**. Опыт 2026-11-02: имя example.com,
закреплённое на наш IP, не прошло — сертификат не совпал.

| Проверка                                                                      | Где                       | Как во время отказа DNS                                      | Как помечена                                                                 |
| ----------------------------------------------------------------------------- | ------------------------- | ------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| Маршруты после выкладки (`deploy-release`: `/`, `/login/` и др., `/console/`) | машина разработчика       | `PUBLIC_PIN` в окружении `npm run deploy`                    | deploy печатает: «доступность по имени (DNS) этим выкатом НЕ подтверждается» |
| Прикладной путь (`monitor-app-probe`)                                         | VPS, таймер               | `PUBLIC_PIN` в `.env` VPS — **только до восстановления DNS** | итог `pinned: true`, в причине «[IP закреплён — имя (DNS) не проверялось]»   |
| Отключение учётки (`monitor-probe-disable`)                                   | VPS                       | `PUBLIC_PIN` из `.env`                                       | —                                                                            |
| Доступность по имени                                                          | GitHub Actions (5e_watch) | **не закрепляется**                                          | остаётся красной, пока DNS лежит                                             |

Доступность по имени зелёной не отмечается: её показывает только 5e_watch.
После восстановления DNS `PUBLIC_PIN` из `.env` VPS убирается. Это
отдельный пункт проверки после инцидента: app-probe снова идёт по имени,
`pinned: false`.

## Откат

- **Наблюдение (шаги 3–10):**
  - `systemctl disable --now fifth-monitor-*.timer`;
  - остановить и удалить контейнеры Zabbix;
  - убрать `MONITOR_PULSE_PUBLIC_DIR` и пересоздать `web`;
  - удалить переменную `FIVE_E_PULSE_URL`.

  База `zabbix` остаётся. Удалять её или нет — решение Томаса.

- **Код (шаг 1):** выкладка прежнего `f5757ad`. Миграции forward-only:
  M152–M156 остаются, прежний код их не использует.
  **В прежнем коде нет ограничения служебной учётки мониторинга**: после
  отката она получила бы права обычного участника. Поэтому, если шаг 4
  выполнялся, **до** выкладки прежнего кода:
  1. `systemctl disable --now fifth-monitor-app-probe.timer` — проба не
     войдёт снова сама;
  2. `node scripts/monitor-probe-disable.mjs`:
     - учётка заблокирована (`suspended`);
     - рубеж сессий сдвинут — живые токены недействительны, как при
       блокировке из админки;
     - **отказ проверен**: сохранённая сессия → 401, вход паролем → 403;
     - сохранённая сессия удалена.

     При любом несовпадении скрипт завершается отказом, и код не
     откатывается, пока причина не устранена.

  3. только затем — выкладка прежнего кода.

  Проверено на стенде 2026-11-02: блокировка → 401 и 403, проба честно
  проваливается; `monitor-probe-init.mjs` возвращает учётку в работу.

- **Критерий отката кода:** сайт или вход не работают после шага 1 и
  причина не устраняется за 15 минут.

## Что не входит

- Healthchecks.io — не используется. Вместо него пульс читает внешняя
  проверка (шаг 9). Регистрацию можно повторить позже как второй пульс.
- DNS: схема скрытого первичного — отдельный план. Выпуск W08a от DNS не
  зависит.
- Подкачка — не нужна при текущей памяти.

## Решения Томаса

1. «Да» на этот план целиком или по шагам: 0–8 наблюдение, 9–10 пульс.
2. Время выпуска. Шаг 1 перезапускает ядро; входящих пользователей сейчас
   нет — DNS лежит.
