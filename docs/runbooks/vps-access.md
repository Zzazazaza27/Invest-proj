# Вход на VPS: личные учётки вместо общего root

Блок 5, задание 1. Выполняет Томас: это настройки безопасности сервера. Значения паролей и закрытые
ключи в чат не передаются.

## Что сейчас

- Вход по паролю и root-вход разрешены, в `root` два ключа: `SERG` и `rebel_diesel`.
- `sudo` пуст, личных учёток нет.
- Закрыто снаружи: 4300, 4400, 5433, 9000, 10051, 8083. Открыто: 22, почта, сайт.

## Порядок

Первую сессию root держи открытой до конца. Перед шагом 4 убедись, что аварийная консоль хостера
открывается.

1. Создай ключи: свой и отдельный для Мауса, на ноутбуке. Закрытые остаются у владельца.

2. На сервере заведи учётки:

   ```bash
   adduser --disabled-password --gecos "" thomas
   adduser --disabled-password --gecos "" maus
   usermod -aG sudo thomas
   usermod -aG sudo maus
   ```

   Положи открытые ключи в `/home/<учётка>/.ssh/authorized_keys`, права `700` на каталог и `600` на
   файл, владелец — учётка. Для `sudo` без пароля у Мауса: файл в `/etc/sudoers.d/` с `visudo -cf`.

3. Во второй сессии проверь обе учётки: вход по ключу и `sudo -n true`.

4. Только после этого закрой прежний вход:

   ```bash
   printf 'PermitRootLogin no\nPasswordAuthentication no\n' > /etc/ssh/sshd_config.d/10-personal-login.conf
   sshd -t && systemctl reload ssh
   ```

5. Проверь в третьей сессии, что новый вход работает, а root и пароль отказаны. Если нет — верни файл
   из первой сессии: `rm /etc/ssh/sshd_config.d/10-personal-login.conf && systemctl reload ssh`.

6. Удали ключ `SERG` из `/root/.ssh/authorized_keys`.

7. Смени раскрытый пароль root через KeePassXC. Он остаётся для аварийной консоли.

Маусу после шага 5 нужно сказать новый адрес входа: его скрипты ходят под `root`.
