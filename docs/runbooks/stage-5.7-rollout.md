# Выкат этапа 5.7 (видимость) — порядок по фактическому результату

Инструкция к решению владельца о выкате; сама по себе выкат не запускает.
Обычный путь — `npm run deploy` (`scripts/deploy.mjs`): код, `npm ci`,
сборка, `check:front-builds`, `db:migrate` (**все** ожидающие миграции одной
командой), рестарт ядра, проверка маршрутов. Выкат 5.7 идёт **поверх
runbook 5.6** (`stage-5.6-rollout.md`): его шаги «до», «скрипты переводов
конфигурации после миграций» и «после» остаются обязательными.

## Порядок исполнения

Раннер применяет все ожидающие миграции разом, поэтому «порядок» здесь —
это порядок **релизов**, а не флагов раннера.

1. **Один прогон `npm run deploy` на коммит ≥ 5.7.5.** Последовательность
   внутри прогона: сборка → `check:front-builds` → `db:migrate`
   (M087…M090 подряд) → рестарт ядра. Окно «старое ядро над M090» — секунды
   между миграцией и рестартом; в нём инвестор получает пустые ответы и
   ошибки кабинета, но не строки данных. Стенд сейчас на `9d63281` (до
   этапов 1–5): все миграции 2–5.7 применяются одним разом, промежуточные
   состояния значения не имеют.
2. **После миграций** — скрипты переводов конфигурации из runbook 5.6
   (`migrate-form-round-scope`, `migrate-form-round-visibility`,
   `migrate-form-round-disclosure`) — по одному разу, идемпотентны. Новых
   скриптов 5.7 не добавляет.
3. **Флаги после выката:** `seasons.enabled` — выключен и остаётся
   выключенным (включение не поддерживается, см. руководство §6.1);
   `billing.investor_access_requires_subscription` — включён: временное
   состояние до решения о матрице бесплатного и платного доступа инвестора
   (принимается перед запуском). Права на данные от флага не зависят;
   переключение — в админке, без выката.
4. **Существующие данные:** `listed → public` как тизер; согласий на показ
   ответов нет — Public View и Investor View отдают тизер и раунд, пока
   владелец не подаст профиль через мастер (подача с предпросмотром = согласие)
   или не применит условия; все материалы `private` до отметки владельца.
   Тестовые данные стенда допустимо сбросить (`reset-test-db.mjs`, план 0.2
   §0г.6) — тогда переноса нет вовсе.

## После выката — проверки

- `node scripts/smoke-lab.mjs` против стенда (блоки 5.7.2–5.7.5), `smoke-favorites`,
  `smoke-integration` (выпускники только public), `smoke-experts`.
- Вручную: аноним открывает `GET /v1/catalog/:id` опубликованного проекта —
  тизер и раунд без ответов (согласия нет); инвестор без членства —
  `GET /v1/projects/:id` → 403, `investor-view` → тизер с
  `access.profile = "public"`; инвестор с членством — Investor View.
- Админка: «Функции платформы» — оба флага в ожидаемом положении.

## Откат

**Главное правило: база после M090 не откатывается, и защита с неё не
снимается.** Отсутствие утечки при старом коде — это не работоспособность
старого интерфейса: миграция удалила инвесторские ветки RLS, поэтому любое
ядро, которое рассчитывало читать данные напрямую, получает пустые ответы
и ошибки экранов. Возвращать эти ветки вручную ради оживления старого
интерфейса **нельзя** — это вернуло бы доступ мимо режима проекта,
исключений и отметок материалов, то есть отменило бы весь этап.

**Совместимая версия для отката кода — `2dfe943`** (5.7.5, та же, что
добавила M090) **или любой более поздний коммит**. Это единственный
безопасный откат: база и код одной модели доступа, ограничений нет.

Что будет при откате на более ранние версии (сведено по фактическому
поведению после M090):

| Версия кода                        | Основатель и админ                               | Инвестор                                                                                       | Партнёр (Integration)               | Пригодность                                        |
| ---------------------------------- | ------------------------------------------------ | ---------------------------------------------------------------------------------------------- | ----------------------------------- | -------------------------------------------------- |
| `2dfe943` и новее (5.7.5+)         | полностью                                        | полностью: Investor View, каталог, избранное                                                   | выпускники и профиль по видимости   | **штатная версия отката**                          |
| `7a4a07f`…`ed20bab` (5.7.4)        | кабинет работает                                 | кабинет работает (Investor View уже есть), но старые маршруты в коде ещё открыты — БД их гасит | так же                              | допустимо как аварийная мера на часы, не как режим |
| `c708b8c`…`1408546` (5.7.3)        | карточки режима нет, листинг — прежними кнопками | кабинет инвестора сломан: три старых вызова отвечают 403/пусто                                 | так же                              | не годится                                         |
| `2dc2d20` и старше (5.6.7 и ранее) | работает; про режим, согласие и отметки не знает | кабинет инвестора пуст; каталог отдаёт тизеры без ответов                                      | выдача сужена базой, код этого ждёт | **не откатывать**                                  |

Если нужно вернуться к состоянию до 5.7 целиком — это не откат кода, а
восстановление стенда: `pg_dump`, снятый до выката (шаг «До выката» в
runbook 5.6), плюс код `2dc2d20`. Иначе база и код разойдутся.

Флаг барьера подписки инвестора при откате не трогать: старое ядро его не
читает, новое — читает сразу при возврате.
