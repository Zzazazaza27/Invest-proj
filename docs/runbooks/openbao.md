# OpenBao на VPS

Блок 5, задание 3. Значения не выводятся на экран и не передаются в чат. После установки OpenBao
работает, но рабочие ключи в него ещё не перенесены: это задание 5.

## Размещение

| Что               | Где                                                 |
| ----------------- | --------------------------------------------------- |
| Контейнер         | `fifth-openbao`, проект `fifth-openbao`             |
| Адрес             | `https://127.0.0.1:8200`, снаружи закрыт            |
| Данные и аудит    | тома `fifth_openbaodata`, `fifth_openbaoaudit`      |
| Static seal key   | `/etc/fifth-openbao/seal/static.key`, вне копий     |
| Сертификат        | `/etc/fifth-openbao/tls`                            |
| Входы компонентов | `/etc/fifth-openbao/approle/<роль>`, только root    |
| Снимок            | `sets/<комплект>/openbao.snap`, без Static seal key |

Выпуск платформы OpenBao не перезапускает.

## Установка

Одна команда под `thomas`. Вопросов нет, повтор после обрыва безопасен:

```bash
sudo bash /opt/fifth-element/infra/host/apply-openbao-auto.sh
```

Команда ставит обёртку чтения, запускает OpenBao, создаёт ключи и шифрует их на GPG-ключ Томаса
(отпечаток задан в `setup-vps.sh`). Затем настраивает хранилища и входы, проверяет личный вход,
отзывает root-токен и включает наблюдение. Обрыв не теряет значений: они лежат в
`/etc/fifth-openbao/auto` только у root до конца шага.

Затем с ноутбука, без терминала на сервере:

```bash
node scripts/backup.mjs openbao-keys --secret-key <файл> --passphrase-file <файл>
```

Операция забирает комплект, сверяет получателя, открывает его ключом Томаса и сверяет значения с
описанием установки. Пока она не прошла, сохранность ключей не подтверждена. Копия лежит в
`.local/keys-openbao`. На отдельный носитель её кладёт Томас, один раз.

Новый root-токен при необходимости выпускается по ключу восстановления из комплекта.

Повтор команды заканчивается словом `готово` только у открытого OpenBao: запечатанный или упавший
даёт ошибку. Наблюдение подтверждает `sudo -n /usr/local/sbin/fifth-diag zabbix-openbao`.

## Переход ядра на Transit и возврат

Блок 5, задание 4. Код готов, на рабочем стенде не включён: это задание 5. Импортируемым ключам
задаётся `allow_rotation`, иначе новую версию создать нельзя. Импортированный ключ — версия 1: запись
без версии всегда читается именно им.

Порядок, каждый шаг отдельным выпуском:

1. **Читает оба формата, пишет прежний.** `KMS_MODE=kms`, `CRYPTO_WRITE_FORMAT=legacy`. Записи
   понимает и старое ядро, возврат свободный, нужен только прежний ключ в окружении старого выпуска.
2. **Версии подписей заведены, не включены.** `*_VERSIONS` заданы, `*_ACTIVE` пусты. Токены прежнего
   формата, kid уже принимается. Возврат свободный.
3. **Новые токены с kid.** `*_ACTIVE` и `*_LEGACY_UNTIL`. Граница возврата для токенов: старый выпуск
   таких токенов не поймёт, люди войдут заново, интеграции получат новый токен, формы получат новый
   CSRF. Данные не страдают.
4. **Новые записи в формате vault.** `CRYPTO_WRITE_FORMAT=vault`. Граница возврата для данных: с
   первой такой записи старый выпуск её не прочитает. Возврат только на выпуск шага 1 или через
   согласованную копию.

Отказ OpenBao: затронутая операция отказывает с кодом 503, ничего не сохраняется, перехода к ключам
из окружения нет. Доставка вебхука откладывается, попытка не расходуется.

Ключ поиска: версия задана `OPENBAO_SEARCH_INDEX_VERSION`. Новая версия индексы не меняет, переход на
неё означает полный пересчёт.

## Если OpenBao запечатан

- **Файл ключа цел:** перезапусти контейнер, он откроется сам.
- **Файл утрачен:** верни его из аварийного комплекта: `OPENBAO_STATIC_SEAL_B64` декодируется в файл, 32 байта, владелец
  uid 1990, права 400. Затем перезапусти контейнер. Ключ восстановления файл не заменяет.
- **Снимок без верного Static seal key не читается,** поэтому ключ и снимок хранятся раздельно.

## Смена Static seal key и миграция

Перед любой из этих работ сними снимок. Порядок проверен на искусственных ключах в
`scripts/check-openbao-ops.mjs`.

- **Смена ключа:** новый ключ в `current_key` с новым `current_key_id`, прежний в `previous_key`.
  Перезапуск, затем `previous_key` можно убрать.
- **Переход на ручную разблокировку:** в блоке seal `disabled = "true"`, перезапуск, `sys/unseal` с
  ключом восстановления и `migrate: true`, затем блок seal убрать.
- **Обратно:** блок seal с новым `current_key_id`, перезапуск, `sys/unseal` с `migrate: true`.
