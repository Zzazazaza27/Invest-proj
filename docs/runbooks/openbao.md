# OpenBao на VPS

Блок 5, задание 3. Значения не выводятся на экран и не передаются в чат. После установки OpenBao
работает, но рабочие ключи в него ещё не перенесены: это задание 5.

## Размещение

| Что               | Где                                                 |
| ----------------- | --------------------------------------------------- |
| Контейнер         | `fifth-openbao`, проект `fifth-openbao`             |
| Адрес             | `https://127.0.0.1:8200`, снаружи закрыт            |
| Данные и аудит    | тома `fifth_openbaodata`, `fifth_openbaoaudit`      |
| Static seal key   | `/etc/fifth-openbao/seal/static.key`, вне копий     |
| Сертификат        | `/etc/fifth-openbao/tls`                            |
| Входы компонентов | `/etc/fifth-openbao/approle/<роль>`, только root    |
| Снимок            | `sets/<комплект>/openbao.snap`, без Static seal key |

Выпуск платформы OpenBao не перезапускает.

## Установка

Одна команда под `thomas`. Вопросов нет, повтор после обрыва безопасен:

```bash
sudo bash /opt/fifth-element/infra/host/apply-openbao-auto.sh
```

Команда ставит обёртку чтения, запускает OpenBao, создаёт ключи и шифрует их на GPG-ключ Томаса
(отпечаток задан в `setup-vps.sh`). Затем настраивает хранилища и входы, проверяет личный вход,
отзывает root-токен и включает наблюдение. Обрыв не теряет значений: они лежат в
`/etc/fifth-openbao/auto` только у root до конца шага.

Затем с ноутбука, без терминала на сервере:

```bash
node scripts/backup.mjs openbao-keys --secret-key <файл> --passphrase-file <файл>
```

Операция забирает комплект, сверяет получателя, открывает его ключом Томаса и сверяет значения с
описанием установки. Пока она не прошла, сохранность ключей не подтверждена. Копия лежит в
`.local/keys-openbao`. На отдельный носитель её кладёт Томас, один раз.

Новый root-токен при необходимости выпускается по ключу восстановления из комплекта. В OpenBao 2.7 этот путь закрыт по умолчанию: на время работы в `listener` задаётся `disable_unauthed_generate_root_endpoints = false` и контейнер перезапускается, затем настройка убирается.

Повтор команды заканчивается словом `готово` только у открытого OpenBao: запечатанный или упавший
даёт ошибку. Наблюдение подтверждает `sudo -n /usr/local/sbin/fifth-diag zabbix-openbao`.

## Переход ядра на Transit и возврат

Блок 5, задание 4. Код готов, на рабочем стенде не включён: это задание 5. Импортируемым ключам
задаётся `allow_rotation`, иначе новую версию создать нельзя. Импортированный ключ — версия 1: запись
без версии всегда читается именно им.

Порядок, каждый шаг отдельным выпуском:

1. **Читает оба формата, пишет прежний.** `KMS_MODE=kms`, `CRYPTO_WRITE_FORMAT=legacy`. Записи
   понимает и старое ядро, но сам режим kms к местным ключам не откатывается: возврат идёт через
   переходный комплект, см. ниже.
2. **Версии подписей заведены, не включены.** `*_VERSIONS` заданы, `*_ACTIVE` пусты. Токены прежнего
   формата, kid уже принимается.
3. **Новые токены с kid.** `*_ACTIVE` и `*_LEGACY_UNTIL`. Граница возврата для токенов: старый выпуск
   таких токенов не поймёт, люди войдут заново, интеграции получат новый токен, формы получат новый
   CSRF. Данные не страдают.
4. **Новые записи в формате vault.** `CRYPTO_WRITE_FORMAT=vault`. Граница возврата для данных: с
   первой такой записи старый выпуск её не прочитает. Возврат только на выпуск шага 1 или через
   согласованную копию.

`NODE_ENV=production` включается до шагов 3 и 4 и требует отдельного решения по `AUTH_MODE`.

**Срок приёма старых подписей.** `*_LEGACY_UNTIL` считается от последней выдачи старым ключом: момент
включения `*_ACTIVE` плюс наибольший срок жизни токена или сессии этого вида. При компрометации
переходного окна нет: версия снимается сразу, все её токены перестают приниматься.

### Переходный комплект

Прежнего `.env` для возврата мало: в нём только пути `<ИМЯ>_FILE`, а KEK лежат файлами в
`.local/secrets` со своими владельцами и правами. Комплект хранит `.env`, весь каталог и опись с
хешами и правами. Он шифруется на ключ Томаса и снимается до включения kms:

```bash
sudo /usr/local/sbin/fifth-transition-kit create
```

С ноутбука `fifth-backup-read transition-kit` забирает его вместе с описанием. Возврат к местным
ключам:

1. Открыть комплект ключом Томаса и передать поток на сервер:
   `gpg --decrypt transition.gpg | ssh thomas@… sudo /usr/local/sbin/fifth-transition-kit restore`.
   Опись сверяется до изменений. Текущие `.env` и каталог откладываются в `.local/before-restore-*`.
2. Поставить прежний выпуск штатно: `release.mjs` с меткой из `pins/prod.json`.
3. Проверить вход и чтение контактов.

Комплект проверен на искусственных значениях. Возврат на настоящем сервере не проверялся, поэтому
«возврат свободный» не считается подтверждённым до пробы на отдельной копии.

### Импорт ключей

С ноутбука, под управлением Томаса. Спрашивает только фразу SSH-ключа:

```bash
node scripts/openbao-keys-import.mjs --kit <transition.gpg> --bundle <emergency.gpg> --secret-key <файл> --passphrase-file <файл>
```

Комплекты открываются в памяти, OpenBao получает пароль внутри TLS через SSH-туннель, сертификат
закреплён. Токен отзывается при любом исходе. Занятое имя не перезаписывается: версия 1 сверяется с
комплектом, несовпадение останавливает импорт. Ключ поиска импортируется как HMAC.

Той же командой секреты среды из комплекта ложатся в KV: совпавшее значение не пишется заново,
другое останавливает загрузку, KEK в KV не попадают. `--agent-out <файл>` сохраняет шаблоны Agent: в
них только имена, файл кладётся в `/etc/fifth-openbao/agent/templates.hcl`.

### Agent

Запуск: `docker compose -p fifth-openbao -f infra/openbao/docker-compose.yml --profile agent up -d`.
Секреты лежат в томе `fifth_secrets_mem`, он в памяти. Ядро подключает его через
`infra/docker-compose.agent.yml`, токен Transit берёт из `/run/fifth-secrets/openbao-token`.

### Смена версии ключа

Токен с политикой `prod-rotate` выдаётся на время работы. Все команды идут с `OPENBAO_TOKEN_PATH`:

```bash
node scripts/rotate-kek.mjs --transit --domain passport_sensitive
```

`--rotate` создаёт версию с контрольной записью и чтением. `--rewrap` переводит записи на неё порциями:
встроенный `rewrap` не принимает AAD, поэтому ключ данных на миг проходит через команду и обнуляется.
Параллельно изменённая строка не перезаписывается, код 0 значит, что отставших нет. Старые версии остаются для чтения и копий. Записи прежнего формата останавливают
переупаковку: сначала перенос. Ключ поиска так не меняется.

### Перенос записей

После шага 4, на сервере: `node scripts/crypto-migrate.mjs run`, затем `verify`. Импортированный ключ —
версия 1, поэтому перенос только меняет порядок байтов. Каждая запись подтверждается через Transit.
Параллельно изменённая строка не перезаписывается. Завершение подтверждает только `verify` с кодом 0:
он просматривает всю таблицу, а позиция обработки ничего не доказывает.

Отказ OpenBao: затронутая операция отказывает с кодом 503, ничего не сохраняется, перехода к ключам
из окружения нет. Доставка вебхука откладывается, попытка не расходуется. Правка имени и аватара
проходит, контакты в ответе помечаются недоступными.

Ключ поиска: версия задана `OPENBAO_SEARCH_INDEX_VERSION`. Новая версия индексы не меняет, переход на
неё означает полный пересчёт.

## Если OpenBao запечатан

- **Файл ключа цел:** перезапусти контейнер, он откроется сам.
- **Файл утрачен:** верни его из аварийного комплекта: `OPENBAO_STATIC_SEAL_B64` декодируется в файл, 32 байта, владелец
  uid 1990, права 400. Затем перезапусти контейнер. Ключ восстановления файл не заменяет.
- **Снимок без верного Static seal key не читается,** поэтому ключ и снимок хранятся раздельно.

## Смена Static seal key и миграция

Перед любой из этих работ сними снимок. Порядок проверен на искусственных ключах в
`scripts/check-openbao-ops.mjs`.

- **Смена ключа:** новый ключ в `current_key` с новым `current_key_id`, прежний в `previous_key`.
  Перезапуск, затем `previous_key` можно убрать.
- **Переход на ручную разблокировку:** в блоке seal `disabled = "true"`, перезапуск, `sys/unseal` с
  ключом восстановления и `migrate: true`, затем блок seal убрать.
- **Обратно:** блок seal с новым `current_key_id`, перезапуск, `sys/unseal` с `migrate: true`.
