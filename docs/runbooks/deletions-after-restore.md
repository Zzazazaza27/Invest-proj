## Порядок

1. **Источник событий** — по таблице постановки 2.1.5:
   - текущая база доступна — снять её копию и брать события из неё (`--source-db`);
   - текущая база потеряна — поднять в закрытой среде самое позднее состояние через
     pgBackRest и WAL (`--source-db`);
   - дополнительно или при потере всего — вынесенная выгрузка (`--source-export`, ключ
     Томаса для расшифровки).
2. **Восстановить** рабочие данные (2.1.3 / 2.1.4). Внешние действия выключены: почта и
   вебхуки не уходят.
3. **Применить**:

   ```bash
   node scripts/deletions-apply.mjs apply --db <URL владельца восстановленной базы> \
     --restore-id <метка> --source-export <каталог>/series \
     --secret-key <ключ Томаса> --passphrase-file <файл> --report <отчёт.json>
   ```

   Применяется итоговое состояние каждой идентичности после последнего общего звена
   цепочки. Повтор безопасен. В отчёте «закрыто» — неоднозначные объекты (скрыты, доступ
   снят) и замены, чей новый файл недоступен (прежний скрыт, слот пуст). «Не воссоздано» —
   подписки и устройства, созданные после копии: их секреты в журнал не пишутся.

4. **Проверить**: `node scripts/deletions-apply.mjs verify …те же аргументы…`.
5. **Открыть** — только после проверки и с явным подтверждением конца покрытия источника:

   ```bash
   node scripts/deletions-apply.mjs open …те же аргументы… --coverage-ack <покрыто до>
   ```

   Ворота открываются для текущего отпечатка базы. Все сессии требуют нового входа:
   отзывы токенов после копии в ней не сохранились.

6. Зафиксировать отчёт и покрытие в инциденте. Неполный источник — инцидент; затронутые
   данные не открываются без проверки.

## Граница

Пакет делает только логическое удаление и учёт. Физическая очистка хранилища — процедура
3.3. Хранение комплектов копий — правило блока 7. Журнал и выгрузки автоматически не
очищаются: сроков ещё нет. Ни выгрузка, ни применение не удаляют объекты хранилища и
комплекты.

Смена кластера при крупном обновлении PostgreSQL и переключение на реплику тоже закрывают
ворота. Открытие — тем же шагом проверки: событий после общего звена не будет.

Избранное в первом пакете не учитывается (ограничение, решение Тэнка 09.11).
