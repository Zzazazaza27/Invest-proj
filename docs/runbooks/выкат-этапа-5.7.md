# Выкат этапа 5.7 (видимость) — порядок по фактическому результату

Инструкция к решению владельца о выкате; сама по себе выкат не запускает.
Обычный путь — `npm run deploy` (`scripts/deploy.mjs`): код, `npm ci`,
сборка, `check:front-builds`, `db:migrate` (**все** ожидающие миграции одной
командой), рестарт ядра, проверка маршрутов. Выкат 5.7 идёт **поверх
runbook 5.6** (`выкат-этапа-5.6.md`): его шаги «до», «скрипты переводов
конфигурации после миграций» и «после» остаются обязательными.

## Порядок исполнения

Раннер применяет все ожидающие миграции разом, поэтому «порядок» здесь —
это порядок **релизов**, а не флагов раннера.

1. **Один прогон `npm run deploy` на коммит ≥ 5.7.5.** Последовательность
   внутри прогона: сборка → `check:front-builds` → `db:migrate`
   (M087…M090 подряд) → рестарт ядра. Окно «старое ядро над M090» — секунды
   между миграцией и рестартом; в нём инвестор получает пустые ответы и
   ошибки кабинета, но не строки данных. Стенд сейчас на `9d63281` (до
   этапов 1–5): все миграции 2–5.7 применяются одним разом, промежуточные
   состояния значения не имеют.
2. **После миграций** — скрипты переводов конфигурации из runbook 5.6
   (`migrate-form-round-scope`, `migrate-form-round-visibility`,
   `migrate-form-round-disclosure`) — по одному разу, идемпотентны. Новых
   скриптов 5.7 не добавляет.
3. **Флаги после выката:** `seasons.enabled` — выключен и остаётся
   выключенным (включение не поддерживается, см. руководство §6.1);
   `billing.investor_access_requires_subscription` — включён (сегодняшнее
   поведение); переключение — решение владельца (`заявка-04` §6),
   меняется в админке без выката.
4. **Существующие данные:** `listed → public` как тизер; согласий на показ
   ответов нет — Public View и Investor View отдают тизер и раунд, пока
   владелец не подаст профиль через мастер (подача с предпросмотром = согласие)
   или не применит условия; все материалы `private` до отметки владельца.
   Тестовые данные стенда допустимо сбросить (`reset-test-db.mjs`, план 0.2
   §0г.6) — тогда переноса нет вовсе.

## После выката — проверки

- `node scripts/smoke-lab.mjs` против стенда (блоки 5.7.2–5.7.5), `smoke-favorites`,
  `smoke-integration` (выпускники только public), `smoke-experts`.
- Вручную: аноним открывает `GET /v1/catalog/:id` опубликованного проекта —
  тизер и раунд без ответов (согласия нет); инвестор без членства —
  `GET /v1/projects/:id` → 403, `investor-view` → тизер с
  `access.profile = "public"`; инвестор с членством — Investor View.
- Админка: «Функции платформы» — оба флага в ожидаемом положении.

## Откат

- **Откат кода** (`deploy.mjs` делает сам при неудаче): старое ядро над
  M090 работоспособно для основателя и админа; инвесторские экраны отвечают
  пусто/403 — не утечка. Допустимо как временная мера.
- **Откат миграций** M087–M090 не предусмотрен: M090 удаляет инвесторские
  ветки RLS, возвращение их вручную вернуло бы доступ мимо режима проекта и
  отметок материалов. Если откат базы всё же нужен — только вместе с
  откатом кода до 5.6.7 и восстановлением из `pg_dump`, снятого до выката.
- Флаг барьера подписки после отката кода не трогать: старое ядро его не
  читает, а новое — читает при возврате.
