# Выпуск 2.1-W05 (удаление «под корень») — порядок на сервере

Инструкция к решению владельца о выпуске. Сама по себе выпуск не запускает:
на сервер — только по отдельному слову Томаса.

## Что особенного

M150 — contract-миграция: удаляет схемы сезонов, анализа ИИ, сделок и
экспертизы, инвестпроцесс и биллинг, кроме стран обслуживания. Прежний код
обращается к этим таблицам. Отсюда два правила, которые теперь держит сам
`npm run deploy` (`scripts/lib/deploy-release.mjs`, проверка
`npm run check:deploy-release`):

1. **Старые обработчики остановлены до миграции.** Если среди ожидающих есть
   миграция с меткой `-- migrate:contract`, ядро вместе с фоновыми
   обработчиками (`background/` живёт в его процессе) останавливается до
   `db:migrate` и запускается уже на новом коде. AI-шлюз
   (`unicorn-ai-gateway`) останавливается и **отключается**
   (`systemctl disable`), чтобы не подняться после перезагрузки.
2. **Несовместимый откат запрещён.** Если M150 применена, а дальше что-то не
   прошло (ядро не поднялось, маршруты не отвечают, следующая миграция
   упала), код НЕ откатывается: выпуск останавливается с отчётом. Если M150
   сама упала, она не применена (своя транзакция): тогда прежний откат кода,
   и шлюз включается обратно. Не удалось прочитать реестр миграций — считаем
   M150 применённой.

Выкат коммита, который старее схемы базы, отменяется до миграции.

## После остановки с запретом отката

Решает человек, автоматики нет:

- **исправить вперёд** — новый коммит, `npm run deploy`;
- **или вернуть всё вместе** — восстановить базу из дампа, путь печатает
  выпуск, затем `git reset --hard <прежний коммит>`, сборка, запуск ядра и
  шлюза. По отдельности код и базу не возвращать.

## Вручную после успешного выпуска

Скрипт этого не делает.

- Снять роли базы `app_billing` и `app_investments`: права у них M150 уже
  отозвала, логин-роли из `bootstrap:roles` ушли.
- Убрать из `.env` сервера переменные AI-шлюза, платежей и KEK удалённых
  доменов. Ядро их больше не читает.
- Удалить юнит `/etc/systemd/system/unicorn-ai-gateway.service` и
  неотслеживаемый `apps/ai-gateway/.venv`, затем `systemctl daemon-reload`.
- Переключение VPS с Redis на Valkey (W02) — отдельное действие.
