## Состав выпуска

Код `cc1fa05` → `<R>` (`main`, CI этого коммита зелёный). Только добавления,
существующее поведение меняется в двух местах:

- **ядро** пишет структурный журнал запросов в journald (`f76f5de`, без
  query, тел, заголовков и текстов ошибок; перезапуск ядра при выкладке);
- **`files.caddy`** получает блок журнала запросов — действует только после
  перезагрузки Caddy в шаге 8.

Не меняет работающего: архиватор `scripts/logs-archive.mjs`; юниты
`infra/systemd/fifth-logs-*`; `infra/journald/50-fifth.conf`;
`infra/caddy/access-log.caddy`; `infra/docker-compose.journald.yml` и
`scripts/infra.mjs` (дополнение подключается **только** при
`DOCKER_LOG_DRIVER=journald`; без переменной определения сервисов прежние —
выкладка `web` не пересоздаёт, проверено пробным запуском compose); политики
и шаг `minio-init` для бакетов журналов (без переменных пропускается);
мониторинг — 24 проверки и 17 тревог журналов.

### MinIO (шаг 7)

После остановки MinIO приёмник архива недоступен, поэтому снимок сначала
локальный (замечание Тэнка):

1. `docker stop unicorn-minio`.
2. `LOGS_PROFILE=legacy LOGS_LEGACY_FILES=<LogPath> LOGS_LEGACY_SNAPSHOT_DIR=/root/w08b-minio-1 node scripts/logs-archive.mjs legacy-snapshot` — «локальный снимок проверен, источники остановлены», код 0. Иначе — `docker start`, разбор.
3. `docker start unicorn-minio` — прежний контейнер, прежний драйвер.
4. `legacy-export` с `LOGS_LEGACY_SNAPSHOT_DIR=/root/w08b-minio-1` — «в архиве, хеш сверен», итог «покрыта полностью»; `verify` истории.
5. Пересоздание: `docker stop unicorn-minio` → второй локальный снимок в
   `/root/w08b-minio-2` (покрывает и то, что записано после шага 3; начало
   совпадает с первым — `cmp -n`) → `infra.mjs compose up -d --no-deps minio`
   → `legacy-export` второго снимка → `verify`.
6. Локальные снимки удаляются только после копии истории на ноутбук,
   которая сошлась.

## После применения

- Локальная история на VPS (journald, журналы остановленных контейнеров)
  этим планом **не очищается** — отдельным решением после подтверждённого
  покрытия и копии.
- `fifth-dns-primary` (свой compose `/opt/fifth-dns`) остаётся на
  `json-file` — в TODO сейфа.
- Ручные команды compose на VPS — только через `node scripts/infra.mjs
compose …`: прямой `docker compose -f infra/docker-compose.yml` не видит
  дополнения journald и вернул бы контейнер на json-file.
- Интервал порций — минута (рекомендация Тэнка); другой — правка таймера
  `fifth-logs-run.timer`.

## Возврат

| Что                | Как                                                                                                           |
| ------------------ | ------------------------------------------------------------------------------------------------------------- |
| Код                | откат выкладки на `cc1fa05` (миграций нет)                                                                    |
| Архив              | `systemctl disable --now fifth-logs-{run,files,pack}.timer`; бакеты остаются (удаление — нет)                 |
| journald           | удалить `50-fifth.conf`, перезапуск journald                                                                  |
| Драйвер контейнера | убрать `DOCKER_LOG_DRIVER`, `infra.mjs compose up -d --no-deps <сервис>`; записи в journald и архиве остаются |
| Caddy              | вернуть копию Caddyfile, `systemctl reload caddy`                                                             |
| Zabbix             | `monitoring.mjs configure` прежнего кода                                                                      |

Журналы json-file, удалённые пересозданием в шаге 7, не возвращаются — поэтому
пересоздание только после «покрыт целиком» по этому контейнеру.
