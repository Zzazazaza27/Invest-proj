# Применение W08b на VPS — план (на согласование Томаса)

Подготовлен 2026-11-03. На VPS ничего не меняется до «да» Томаса на этот
план. Устройство архива — `docs/architecture/w08b-logs-plan.md`.

## Состояние VPS (чтение 2026-11-03)

- Код `cc1fa05`. С него 17 коммитов W08b, среди них структурный журнал ядра
  (`f76f5de`): журнала запросов ядра на VPS пока нет.
- journald 2,0 ГБ, своих настроек нет (`journald.conf.d` нет), нумераций
  записей 7. Свободно 102 ГБ.
- Docker — `json-file` по умолчанию, `daemon.json` нет. Журналы контейнеров
  вместе ~17 МБ. У `unicorn-postgres` 12,7 МБ: контейнер пересоздан правкой
  секретов 02.11, журнал до этого удалён вместе с ним — эта часть истории
  уже недоступна.
- Почта: у exim только `mainlog` (`rejectlog` нет), у dovecot
  `/var/log/dovecot.log`, оба с ротацией. В `LOGS_FILES` — только эти два.
- Caddy журнала запросов не пишет.
- Упавшие юниты: `run-u1793` — мой временный от диагностики W07;
  `fwupd`, `fwupd-refresh` — системные, не наши, не трогаются.

## Подготовить локально до применения

Этого ещё нет в репозитории; каждое — с испытанием на стенде.

1. Юниты `fifth-logs-run` (раз в минуту), `fifth-logs-files` (раз в час),
   `fifth-logs-pack` (раз в сутки) в `infra/systemd` и их установка.
2. Лимиты journald: `SystemMaxUse=4G`, `SystemKeepFree=15G`.
3. Драйвер `journald` для сервисов compose (метка — имя контейнера).
4. JSON-журнал запросов Caddy с фильтрами: без query, cookie и
   `Authorization`.
5. Переменные `LOGS_*` и ключи архивов. Новые ключи генерируются в файл вне
   Git с пометкой «не применён» и входят в комплект ключей W07.

Интервал порций — минута, по рекомендации Тэнка. Если ты выберешь другой,
меняется только таймер.

выгрузки его журнала, секунды; postgres — до ~20 с.

**не очищается**. Очистка — отдельным решением, после подтверждённого
покрытия и копии.
