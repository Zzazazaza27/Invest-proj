# Выкат этапа 5.6 (раунды, страны, видимость) — порядок

> **Статус после 2.1-W05 (29.10.2026):** раунды и условия стран удалены из кода и базы (миграция M150). Документ — история выката этапа 5.6.

Инструкция к решению владельца о выкате; сама по себе выкат не запускает.
Обычный путь — `npm run deploy` (`scripts/deploy.mjs`): код, `npm ci`,
сборка, `db:migrate`, рестарт, проверка маршрутов, откат при неудаче. Этап
5.6 добавляет шаги **после миграций** и **проверки до/после**, которых в
скрипте нет — они ниже.

## До выката

1. `npm run deploy:dry` — убедиться, что цель, ветка и коммит те.
2. Проверить совместимость nginx боевого стенда с `infra/nginx/default.conf`
   (резолвер Docker и `host.docker.internal` только по IPv4 — правка
   локального стенда 2026-09-18; на сервере схема раздачи другая, не
   переносить вслепую).
3. На сервере `.env`: `NODE_ENV=production` у ядра; фронты собираются
   через `scripts/vite-build.mjs` в любом случае, но проверка
   `npm run check:front-builds` обязана быть зелёной после сборки — иначе
   выкат отложить.
4. Снимок базы (`pg_dump`) — миграции M081–M086 только расширяют, но
   скрипты переводов конфигурации публикуют новые версии.

## Выкат

`npm run deploy` делает: `git reset` на выбранный коммит → `npm ci` →
`npm run build` + `build:console` → `npm run check:front-builds` (добавлено
5.6.6) → `npm run db:migrate` (M081…M086) → рестарт служб → проверка
маршрутов.

## После миграций — обязательные скрипты (по порядку, один раз)

Все три идемпотентны: повторный запуск ничего не меняет. Каждый читает
**живую** активную версию конфигурации вопросов (с правками
администратора), а не сид, и публикует следующую версию с основанием.

```bash
node scripts/migrate-form-round-scope.mjs
```

Раздел «Инвестиционный запрос» получает `scope: round`, остальные —
`profile`; `previous_funding` переезжает в «Результаты и динамика» (5.6.2).

```bash
node scripts/migrate-form-round-visibility.mjs
```

Сумма, предмет и пояснение — `investors`, если стояло `public` (5.6.4д).

```bash
node scripts/migrate-form-round-disclosure.mjs
```

Блок `disclosure.raising_status` — наследует видимость `investment_ask`
той же версии (5.6.6).

Без этих шагов: мастер покажет раздел раунда среди разделов профиля; сумма
раундов будет публична для анонима; статус будет считаться по правилу
«как у суммы» (это и есть fail-safe умолчание, но настройка в админке не
появится).

## После выката

1. `node scripts/check-front-builds.mjs` — на сервере (production-сборки).
2. Смоуков против боевого стенда без записи в данные сейчас нет
   (`check-stand*` удалены 2026-09-24 вместе с учётками `stand-*`). Смоуки
   `smoke-lab`, `smoke-demo`, `smoke-favorites` и рендер-проверки создают
   пользователей, проекты, страны и версии конфигурации — **на боевом стенде
   не запускать**.
3. В админке: «Вопросы заявки» — проверить, что активна версия,
   опубликованная скриптами (основания видны в истории); «Страны
   обслуживания» — RU включена, условия версии 1.
4. Флаг `lab.ui.application_v2` остаётся выключенным до решения владельца:
   мастер v2, раунды и экран страны основателю не видны, пока флаг выключен;
   API раундов и стран работает независимо от флага.

## Что меняется для уже существующих данных

| Данные                                 | Что происходит                                                                                                                                         |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Проекты без раунда                     | в каталоге и карточках — «сейчас не привлекает» или «условия не раскрываются» (по настройке статуса); сумма старой формы текущим запросом не считается |
| Черновики заявок v1 (раздел `funding`) | остаются на своей версии; при подготовке раунда сумма, предмет и ответы раздела читаются как предзаполнение; профиль подаётся без них                  |
| Поданные заявки и снимки               | неизменны; раунд из них автоматически не создаётся                                                                                                     |
| Кеш `lab.projects.investment_ask`      | остаётся колонкой совместимости (кабинет v1, триггер тарифа, скоринг, событие листинга) — руководство §2.1                                             |
| Аккаунты без страны обслуживания       | работают; страну попросят перед открытием раунда; при регистрации новые аккаунты выбирают страну (обе роли)                                            |
| Версии конфигурации                    | скрипты публикуют три новые версии с основаниями; прежние остаются в истории; заявки, начатые на прежних версиях, на них и остаются                    |

## Откат

`scripts/deploy.mjs` откатывает код и пересобирает при неудаче проверки
маршрутов. Миграции 5.6 не откатываются (expand-only): столбцы и функции
остаются, прежний код их не читает. Опубликованные скриптами версии
конфигурации можно вернуть в админке «Вернуть версию N» — это тоже новая
версия с основанием.
