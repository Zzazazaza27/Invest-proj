# Чистое локальное развёртывание: сброс данных и восстановление

Порядок, по которому локальные базы и хранилище приводятся к чистому
состоянию, а стенд — к рабочему. Проверен 2026-09-19 (обе базы пересозданы с
нуля, все проверки зелёные).

**Область.** Только локальные базы проекта `unicorn_launch` и `unicorn_test`
на `localhost:5433` (контейнер `unicorn-postgres`) и бакет `unicorn-launch`
локального MinIO. Базы `postgres` и `keycloak`, роли, расширения, секреты,
конфигурация подключения и удалённый стенд **не трогаются**. Если строка
подключения указывает не на localhost или ведёт в другую базу — скрипт
отказывается работать до первого DROP.

**Когда нужно.** Схема изменилась несовместимо; данные перестали
соответствовать текущей модели; нужно проверить, что схема и фикстуры
собираются с нуля. Повторять после каждой мелкой правки не нужно.

---

## 1. Перед сбросом

1. Остановить ядро, чтобы оно не писало в сбрасываемую базу: закрыть окно с
   `dev-core` или остановить процесс, слушающий порт 4300 (в PowerShell —
   `Get-NetTCPConnection -LocalPort 4300 -State Listen`, затем
   `Stop-Process -Id <pid>`). Отдельного ключа остановки у скрипта нет.

2. Остановить параллельные прогоны тестов и фоновые задания, работающие с
   этими базами.

3. Проверить, что конфигурация — та самая:

```bash
node scripts/reset-test-db.mjs --db unicorn_test
```

Пробный запуск без `--yes` печатает базу, хост, порт и перечень схем к
удалению и ничего не меняет.

## 2. Что считается конфигурацией, а что мусором

**Воспроизводится из репозитория** (сохранять отдельно не нужно):

- вопросы заявки — `packages/contracts` (документ версии 1) +
  `scripts/seed-application-form.mjs` и миграции формы;
- политики заявок, страны обслуживания и их условия, шаблоны уведомлений,
  таксономия, флаги платформы — миграции;
- тексты витрины и словарь/ЧАВО — на 2026-09-19 в базе лежали только записи
  прогонов (`*_probe_*`), продуктовых текстов не было.

**Мусор прогонов** (не переносить): тестовые пользователи, проекты, заявки,
раунды, разрешения, материалы, подписки, счета, платежи, начисления, лишние
версии конфигурации и страны, созданные проверками.

Если в базе появится редакция, которой нет в репозитории (например, вопросы,
изменённые владельцем в админке), её нужно выгрузить и превратить в сид ДО
сброса — устаревшим генератором такую редакцию подменять нельзя.

## 3. Сброс и восстановление

```bash
# 1. Базы
node scripts/reset-test-db.mjs --db unicorn_test   --yes
node scripts/reset-test-db.mjs --db unicorn_launch --yes
NODE_ENV=test npm run db:migrate
npm run db:migrate

# 2. Конфигурация (идемпотентно, порядок важен)
node scripts/seed-application-form.mjs
node scripts/migrate-form-round-scope.mjs
node scripts/migrate-form-round-visibility.mjs
node scripts/migrate-form-round-disclosure.mjs
# то же для тестовой базы:
NODE_ENV=test node scripts/seed-application-form.mjs
NODE_ENV=test node scripts/migrate-form-round-scope.mjs

# 3. Учётные записи и сценарии стенда
node scripts/dev-seed-test-user.mjs
node scripts/dev-stand.mjs
node scripts/dev-core.mjs --detached      # сценарии создаются через API
node scripts/seed-local-scenarios.mjs
```

`seed-local-scenarios.mjs` создаёт шесть состояний: профиль без раунда,
черновик раунда, открытый раунд, публичный проект, закрытый проект и проект
«для выбранных инвесторов» с адресным разрешением и закрытым материалом.
Повторный запуск ничего не дублирует. Пароль берётся из
`DEV_TEST_USER_PASSWORD` и нигде не печатается.

Скрипт сброса возвращает умолчания привилегий базы (`pg_default_acl`) —
без этого повторные миграции создавали функции, которые приложение не может
вызвать, и ошибка всплывала далеко от причины.

## 4. Хранилище

Очищаются только объекты проекта; бакет, ключи и роли остаются.

```bash
export MC_HOST_local="http://$MINIO_ROOT_USER:$MINIO_ROOT_PASSWORD@127.0.0.1:9000"
docker exec -e MC_HOST_local="$MC_HOST_local" unicorn-minio \
  sh -lc 'mc ls --recursive local/unicorn-launch | wc -l;
          mc rm --recursive --force local/unicorn-launch/projects/;
          mc rm --recursive --force local/unicorn-launch/investments/'
```

Перед удалением проверить endpoint, бакет и префикс. Если хранилище делится с
другим окружением и принадлежность объектов неоднозначна — не чистить бакет
целиком, а ограничить область или сообщить об ограничении.


Прогоны «стоимость запуска» временно включают платные пакеты в условиях
страны и возвращают прежнее состояние новой версией с основанием; версии
условий не удаляются. Прогоны «пакеты раунда» и «страны обслуживания» пишут в настройку, а не
только в тестовые данные: свои версии пакетов они закрывают в конце и
закрывают остатки прошлого прогона в начале. Версии не удаляются — история
цены такой же факт, как и сама цена.

Фронты после изменения кода пересобрать (`npm run build`) — nginx раздаёт
собранные файлы, а не dev-сервер.

## 6. Чего этот порядок не делает

- не трогает удалённый стенд и его данные;
- не удаляет учётные записи в Keycloak (если тестовые записи остались во
  внешнем провайдере — это учитывается при создании фикстур, realm не
  чистится);
- не является командой выката: выкат описан в `docs/runbooks/выкат-этапа-*.md`.
