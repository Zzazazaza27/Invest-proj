# Выпуск без остановки: два слота ядра (блок 09, задание 3)

План и решения — `docs/architecture/w09-task3-two-cores.md` (согласован Тэнком 09.11).
Рабочую выкладку запускает Томас по действующему порядку.

## Как устроено

- Два слота: `core-a` и `core-b`. Обслуживает один, второй поднимается кандидатом на время
  выпуска и становится активным после подтверждения; прежний останавливается.
- **Файл маршрута** (`.local/release/nginx/route.conf` и `core-route.json`) — какой слот
  получает запросы и из какой сборки отдаётся статика. Пишет только установщик; nginx
  перечитывает его мягкой перезагрузкой.
- **Разрешение фона** (`.local/release/grant/background-grant.json`) — какому слоту можно
  выполнять фоновые задачи. Отдельно от маршрута: выдаётся кандидату только после
  подтверждения переключения запросом. Пауза фона переживает перезапуск.
- **Статика по сборкам** (`.local/release/static/<сборка>`): web не пересоздаётся на каждом
  выпуске; открытым вкладкам недостающие файлы отдаются из прежней сборки.
- **Журнал шагов** — `.local/release/journal.jsonl`.

|                            | рабочая среда                                                   | тестовая среда                                                             |
| -------------------------- | --------------------------------------------------------------- | -------------------------------------------------------------------------- |
| файлы запуска              | `infra/docker-compose.slots.yml` (при `FIFTH_SLOTS=1` в `.env`) | `infra/docker-compose.env-slots.yml` (при `FIFTH_SLOTS=1` в `compose.env`) |
| core-a                     | `fifth-core`, 4300 / служебный 4401                             | `<проект>-core`, 4300 / 4400                                               |
| core-b                     | `fifth-core-b`, 4310 / 4411                                     | `<проект>-core-b`, 4300 / 4400                                             |
| служебный адрес наблюдения | `:4400` на шлюзе Docker через nginx                             | —                                                                          |

## Переход на слоты (разово, короткий перерыв)

Рабочая среда:

```bash
node scripts/release.mjs slots-enable prod --actor <кто> --approved-by <кто>
```

Ядро пересоздаётся раньше web (освобождает 4400), затем web подключает маршрут и статику.
Не подтвердилось через nginx — возврат сам. Ручной возврат:

```bash
node scripts/release.mjs slots-disable prod --actor <кто> --approved-by <кто>
```

Тестовая среда: `node scripts/env.mjs slots-enable <среда>` (пилотная — с `--pilot-confirm`).

## Выпуск

Рабочая среда — обычной командой установщика (`release.mjs install prod …`): при
`FIFTH_SLOTS=1` она идёт переключением слотов. Тестовая — `env.mjs slots-update <среда> --kit <сборка>`.

Порядок:

1. расширение схемы образом кандидата (кроме «только образы»);
2. кандидат без фона; готовность, контрольная операция, вход — в его порт, мимо nginx;
3. разрешение фона снимается, фон старого — на паузу до окончания проходов;
4. маршрут → `nginx -t` → мягкая перезагрузка;
5. подтверждение: 5 ответов подряд от кандидата по новым соединениям (до 15 с);
6. разрешение и фон — кандидату;
7. наблюдение (по умолчанию 10 мин, `--observe-ms`);
8. старый останавливается, когда старые обработчики nginx его не используют и активных
   запросов нет; срок (`--drain-ms`, 5 мин) вышел — число оборванных в журнал, затем SIGTERM.

Отказ на шагах 2–5 — всё возвращается старому слоту, кандидат остановлен. Отказ в
наблюдении — возврат только с `--auto-rollback`, иначе остановка с решением за Томасом.

## После обрыва команды

```bash
node scripts/env.mjs slots-state <среда>
```

показывает файл маршрута, разрешение, кто отвечает через nginx и фон каждого слота;
`consistent: false` — разбирать по журналу, вслепую не повторять.

## Ограничения

- Раскладка рабочей среды (ядро в сети узла, свои порты) на ноутбуке не испытывается:
  логика и действия испытаны на временной среде (`scripts/check-slots-env.mjs`), первый
  настоящий запуск — переходный выпуск со своим возвратом.
- Изменение конфигурации nginx в новой сборке web установщик только записывает в журнал:
  пересоздание web — отдельный шаг с коротким перерывом.
- Сохранение полей формы после «Обновить» не обещается (не реализовано).
