# Привязки к домену платформы — отчёт по местам использования

Блок 13 «Домены и среды», пункт «жёсткие привязки». Составлен 2026-11-09 по фактическим
вхождениям `5espace` в репозитории (без документации и lock-файла):
`git grep -n -I 5espace -- . ':!docs' ':!*.md' ':!package-lock.json'`.

Домен сейчас — `5espace.com` (с 2026-10-28). Смена домена — процедура конфигурации; этот
отчёт перечисляет, что она затрагивает.

## Правило совместимости: идентификатор вида ошибки

`type` в ответе об ошибке (`https://5espace.com/problems/<код>`) — **постоянный
идентификатор, а не адрес площадки**. Выбрано явно (Тэнк 09.11): при смене домена он не
меняется, клиенты сравнивают его как строку. Изменить его можно только отдельным
решением с переходным периодом, не попутно со сменой настроек домена.

- Источник — `PROBLEM_TYPE_BASE` в `packages/contracts/src/common/problem.ts`.
- Ядро берёт значение из него (`problemTypeUri`); прежние литералы в
  `apps/core/src/cache/ip-ceiling.ts` и `apps/core/src/main.ts` сведены к нему 09.11 без
  изменения значения.
- Ответы не от ядра пишут строку сами: `infra/nginx/default.conf` (502, 504) и
  `infra/caddy/unavailable.caddy`. Совпадение с константой проверяет
  `packages/contracts/tests/problem-type-base.test.ts`.
- Прогоны `render-check-guarded-send`, `render-check-retry-keys` и тесты подставляют тот же
  идентификатор — менять вместе с ним, а не с доменом.

## Что меняется при смене домена

### Настройки среды — уже переменные, кода не трогают

Ядро получает адреса из окружения: `CORE_PUBLIC_URL`, `PUBLIC_BASE_URL`,
`CORS_ALLOWED_ORIGINS`, `S3_PUBLIC_ENDPOINT`, `MAIL_FROM`, `MAIL_SMTP_*`. Значения
задаются при установке среды:

| Где задаётся                          | Что                                                                |
| ------------------------------------- | ------------------------------------------------------------------ |
| `infra/host/prod-production.sh:68–78` | prod: адрес, CORS, почтовый сервер и отправитель                   |
| `scripts/env.mjs:302–308`             | тестовые среды: `no-reply-<среда>@5espace.com`, `mail.5espace.com` |
| `scripts/garage-init.mjs:72`          | CORS бакета prod (`S3_CORS_ALLOW_ORIGIN`)                          |
| `.env.example:150, 263, 400`          | примеры значений                                                   |

Эти места — первые кандидаты вынести домен в одну переменную площадки
(`FIFTH_DOMAIN`), от которой выводятся остальные. Пока не сделано.

### Вход на площадку — Caddy

| Файл                      | Что                                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------------------- |
| `infra/caddy/Caddyfile`   | основные сайты: `5espace.com`, `www`, `panel`, `mail`, `test-1`, `test-2` (копия с сервера, см. ниже) |
| `infra/caddy/files.caddy` | `files.5espace.com` и разрешённые Origin трёх сред                                                    |

Сертификаты Caddy получает сам по именам сайтов; новый домен требует DNS-записей до
переключения.

### DNS

`infra/dns/zones/dnspilot.5espace.com.zone` — пробная зона скрытого первичного сервера.
Основная зона ведётся у регистратора; опись — `infra/dns/5espace.com.inventory.md`.

### Скрипты сервера — домен строкой

`infra/host/prod-*.sh`, `test-probe-*.sh` (около 20 файлов) содержат адрес строкой: проверки
`curl`, правки блоков Caddyfile по имени сайта, почтовые ящики HestiaCP (`5espace.com`).
Это одноразовые шаги выпусков; при смене домена — заменить в тех, что ещё используются
(`prod-control`, `prod-gate*`, `prod-test2-*`, `prod-caddy-unavailable`).

### Средства наблюдения и разработчика

| Файл                                                   | Что                                                                                      |
| ------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `scripts/monitoring.mjs:58–65, 175, 1304`              | адреса проверки и сертификата для Zabbix                                                 |
| `scripts/stand-status.mjs:28`, `scripts/deploy.mjs:58` | адрес по умолчанию, перекрывается `STAND_PUBLIC_URL`                                     |
| `scripts/lib/pinned-fetch.mjs:5`                       | пример в комментарии                                                                     |
| `scripts/probe-account-path.mjs:16`                    | адрес test-1                                                                             |
| `scripts/backup.mjs:161`                               | метка ключа резервных копий `backup@5espace.com` — только имя ключа, не адрес; не менять |

### Не привязки

- `*@5espace.invalid` (`scripts/monitor-probe-init.mjs`) — зарезервированный домен для
  служебных учётных записей, письма туда не уходят.
- Тесты (`apps/core/tests`, `packages/*/tests`, `scripts/check-*`) — образцы значений.
