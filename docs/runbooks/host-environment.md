# Окружение узла

Пакет «окружение узла» (план согласован Тэнком 15.11.2026). Один механизм для новой установки,
выпуска и восстановления: что стоит на хосте, описано; описание проверяемо; критичные пакеты
сохранены и ставятся без репозиториев. Обновление версий сюда не входит: закрепить текущее
проверенное окружение и обновить компоненты — разные действия.

## Части

| Что                               | Где                                                                  |
| --------------------------------- | -------------------------------------------------------------------- |
| Описание (утверждённое)           | `infra/host/environment.json`                                        |
| Закрепление архива для комплектов | `infra/host/environment.lock.json` (появляется после первого архива) |
| Опись, сверка, сборка архива      | `scripts/host-env.mjs`, `scripts/lib/host-env.mjs`                   |
| Архив окружения                   | `scripts/lib/host-env-archive.mjs`                                   |
| Сборка подписанного архива в CI   | `.github/workflows/hostenv.yml` (только по команде)                  |
| Применение на узле и возврат      | `scripts/host-env-apply.mjs`                                         |
| Периодическая сверка → Zabbix     | `scripts/monitor-host-env.mjs`, таймер `fifth-monitor-host-env`      |
| Установка на площадке без сети    | `restore-site-wsl.mjs hostenv` / `prepare --set`, `site.sh hostenv`  |
| Метка происхождения               | `/etc/fifth-install/host-env-origin.json` (пишет `site.sh hostenv`)  |
| Проверка правил                   | `scripts/check-host-env.mjs` (CHK-HOST-ENV)                          |

## Описание

ОС (`id`, `versionId`) и архитектура, источники пакетов (адрес, набор, компоненты, файл ключа,
адрес ключа у поставщика, **отпечаток** ключа), управляемые компоненты с версиями и правилом
совпадения, политика автообновлений. `status: draft` — черновик; `approved` — утверждено
владельцем (`approved: {by, at}`), и тогда пустых значений быть не может.

**Правила сверки:**

- ОС и архитектура — точно.
- Ядро не сравнивается: площадка WSL не обязана иметь ядро VPS. Записывается для протокола.
- `exact` — пакет поставщика (Docker, Caddy, NodeSource): ровно версия описания и источник
  поставщика.
- `ubuntu-security` — пакет Ubuntu: та же версия программы, ревизия та же или новее. Так
  допускаются обновления безопасности Ubuntu.
- Итоги: `ok`, `differ`, `missing`, `unverified`. «Не удалось определить» — `unverified`, это не
  совпадение; общий итог с ним — «не проверено» (код 3).
- Сверка ничего не исправляет.

## Опись → утверждение

```bash
node scripts/host-env.mjs inventory --set .local/backup-pull/<копия> --write infra/host/environment.json
```

Опись берёт фактические значения из записи узла в копии и **ничего не угадывает**: чего в записи
нет — `null` и строка в «неполных сведениях». Это исходная опись, а не утверждённое описание.

Копии до 15.11 не записывали архитектуру, полный список пакетов, закрепления, политику
автообновлений и ключи Caddy и NodeSource (ключ Docker лежал в секретной части). Съём узла
дополнен (`scripts/lib/host-config.mjs`): эти сведения будут в первой копии, снятой обновлённым
инструментом на узле.

## Архив окружения

Неизменяемый tar `hostenv/<id>/`: `environment.json` (описание байт в байт), `debs/` — пакеты с
**полным замыканием зависимостей** (не полагаясь на состав образа сборки), `archive.json` (суммы
пакетов, сумма описания, отпечатки ключей, образ сборки) и `archive.json.sig` — подпись ключом
комплектов, домен `fifth-hostenv-v1`. Идентификатор: `<id описания>.<12 знаков sha256(archive.json)>`.

Сборка — в чистом контейнере Ubuntu той же версии и архитектуры; ключ каждого источника
скачивается у поставщика и принимается, только если отпечаток совпал с описанием. Пакет Ubuntu
берётся точной версией, если архив Ubuntu её ещё держит, иначе — последней ревизией той же версии
программы (то же правило, что у сверки).

```bash
gh workflow run hostenv.yml --ref main          # подписанный архив (CI, только утверждённое описание)
node scripts/host-env.mjs archive verify <архив.tar> --pub <ключ комплектов>
```

**Путь архива:** артефакт CI → ноутбук (`.local/host-env/`) → узел `/opt/fifth-element/.local/host-env/`
→ `environment.lock.json` (id, sha256) в Git → комплект выпуска получает `hostEnv` (входит в
`kitId`) → установщик отказывает, если архива на узле нет или подпись и сумма не сошлись → копия
кладёт архивы закреплённых комплектов в `hostenv/<id>.tar` (по содержимому, один раз, как
образы) → `backup pull` увозит их на ноутбук.

## Восстановление

`restore-site-wsl prepare --set <копия> --pub <ключ комплектов>`: архив копии проверяется на
ноутбуке, затем на площадке — локальный репозиторий из файлов архива, `unshare --net`, пустые
источники и пустой кеш списков apt. Ставится только недостающее и более старое; управляемые
пакеты закрепляются; затем общая сверка с описанием **из архива копии**, а не из main.
`restore-full` сверяет площадку тем же модулем. Копия без архива — прежний путь из сети и
ограничение в протоколе.

**Доверие к подписи (Тэнк 16.11).** Подпись проверяется ключом, известным **независимо от
копии**: явный `--pub` или закреплённый в Git `infra/host/kit-signing.pub` (закреплён 16.11: SHA-256 файла
`239f3515…e440a` Томас сверил с `/etc/fifth-install/kit-signing.pub` на узле; при замене ключа
через `prod-install-key.sh` файл в Git меняется тем же решением). Ключ из самой копии доверенный не заменяет: подменённые архив и
ключ согласуются между собой. Нет независимого ключа — отказ. Только явно, `--origin-unconfirmed`:
проверка ключом копии, метка «не подтверждено», сверка даёт «не проверено», а не совпадение.

**Происхождение после установки из архива.** Установка пишет метку
`/etc/fifth-install/host-env-origin.json`: идентификатор архива, полная сумма `archive.json`,
описание, подтверждено ли происхождение, отпечаток ключа и версии пакетов, которые поставил
архив. Сверка (на узле, на площадке и по копии — съём узла читает метку) принимает пакет
поставщика как совпадение, если источник — поставщик **или** метка сходится: идентификатор = описание

- сумма, описание то же, версия та, что поставил архив, других источников этой версии нет. Не
  сходится — расхождение с причиной; происхождение не подтверждено — «не проверено».

**Возврат к сопровождению** — отдельный шаг, не часть восстановления: подключить источники
поставщиков (файлы и ключи из описания, отпечаток сверяется). Закрепление управляемых пакетов
остаётся, поэтому пакеты не обновляются; сверка после подключения видит источник поставщика.
Метка остаётся как запись, из какого архива поставлен узел.

## Работающий узел — план применения и возврата

Узел общий для prod, test-1 и test-2. Каждый шаг — отдельной командой Томасу, по его решению.

1. **Инструменты на узел** (обычная синхронизация) — чтобы копия снимала полные сведения.
2. **Внеочередная копия и `backup pull`**, затем `host-env inventory` — опись без пробелов
   (или с перечнем того, что определить не удалось).
3. **Утверждение описания** владельцем (`status: approved`), коммит.
4. **Архив**: `gh workflow run hostenv.yml`; скачать артефакт на ноутбук, сверить
   `archive verify --pub`.
5. **Доставка на узел**: `.local/host-env/<id>.tar`, сумма — как в выводе сборки.
6. **Закрепление**: `environment.lock.json` в Git; следующий выпуск несёт `hostEnv`.
7. **Применение** — после выпуска:

   ```bash
   node scripts/host-env-apply.mjs plan          # только чтение: что изменится
   node scripts/host-env-apply.mjs apply --yes
   ```

   Делает четыре обратимые вещи:
   - `apt-mark hold` — **только** управляемых пакетов поставщиков (не вся ОС и не ядро);
   - `/etc/apt/apt.conf.d/90fifth-unattended-upgrades` — политика описания
     (`security.autoUpdates`). `security-only`: только источники безопасности Ubuntu, управляемые
     пакеты исключены, без автоматической перезагрузки. Файл идёт после
     `60unattended-upgrades-hestia-*` и снимает их шаблоны источников: программы Hestia (nginx,
     php, mariadb, postgresql) сами не обновляются — как и до сих пор. `off`: выключено;
   - при `security-only` — пакет `unattended-upgrades` из Ubuntu, если его нет (16.11 на узле его
     не было: обновления безопасности не ставились вовсе);
   - таймер `fifth-monitor-host-env`.

   Другие пакеты не ставятся и не удаляются, службы не перезапускаются. Прежнее состояние —
   `/var/backups/fifth-element/host-env-apply/<отметка>.json`.

8. **Возврат**: `node scripts/host-env-apply.mjs rollback <отметка>` — снимает только
   поставленные этим `apply` закрепления, удаляет `unattended-upgrades`, если его поставил этот
   `apply`, возвращает прежнюю политику (или удаляет файл), таймер — как был.

Zabbix (`monitoring.mjs configure`): `host.env.verdict` (0 совпадает, 1 расходится, 2 не
проверено), тревоги «расходится» (2), «не проверено» (1), «сверка не работает» (> 2 суток).

**Кто следит за обновлениями (Томас 16.11).** Ставит их `unattended-upgrades`, следит Zabbix:
сверка пишет в `host-env.json` раздел `updates` (установлен ли, последний запуск и его итог,
сколько обновлений безопасности ждут, нужна ли перезагрузка и из-за каких пакетов). Тревоги уровня
«предупреждение» — в Telegram:

- автообновления выключены (`unattended-upgrades` нет);
- обновления безопасности ждут больше 3 суток;
- последний запуск завершился ошибкой;
- автообновления не запускались больше 3 суток;
- узел ждёт перезагрузки.

Перезагрузку автомат не делает: узел общий для prod, test-1 и test-2, время выбирает владелец.

Узел, восстановленный из архива, сверка считает совпадающим по метке происхождения (см.
«Восстановление»), а не ошибочным.
