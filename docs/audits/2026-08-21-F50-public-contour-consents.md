# SESSION AUDIT REPORT — Ф50: согласия на публичный контур

Дата: 2026-08-21. Повод: решение владельца по единственной открытой находке
Ф48 — `POST /v1/publication-consents` есть в клиенте, контроллера в ядре нет
(подтверждено вызовом: 404).

## Решение и его основание

Маршрут **реализован**, а не удалён из клиента. Основание — не вкус, а состав
уже существующего:

| Что уже было в проекте                                    | Где                                          |
| --------------------------------------------------------- | -------------------------------------------- |
| таблица `identity.publication_consents` с RLS и индексами | M002 (2026-08-10)                            |
| внешний ключ на проект                                    | M004                                         |
| функция чтения для медиаконтура                           | M010, `active_publication_consent`           |
| событие отзыва и срок удаления проекции (15 мин)          | `packages/contracts/events.ts`               |
| требование «согласия собираются УЖЕ СЕЙЧАС»               | `docs/architecture/Architect_Launch.md` §6.4 |
| вызов в клиенте                                           | `packages/api-client`                        |

Отсутствовал ровно один слой — контроллер. Удаление метода из клиента
означало бы, что собранная под задачу схема данных, событие с обязательством
по сроку и пункт архитектуры остались без исполнителя.

## Что сделано

**M059** — документ и граница проекта:

- заведена действующая версия документа `pdn_biometric v1 ru-RU`. Съёмка
  отбора, буткемпа и финала раскрывает изображение и голос (биометрические
  ПДн), публичный топ-100 распространяет изображение и имя; документ на все
  четыре области один, различает их поле `scope` самого согласия;
- политика `publication_consents_own` (`FOR ALL`) разбита на три по цели.
  **Найденная дыра:** прежняя `WITH CHECK` требовала только «согласие выдано от
  себя», но не членства в проекте — строку согласия на ЧУЖОЙ проект мог
  оставить любой пользователь, а медиаконтур читает эти строки как разрешение
  снимать. Требование членства теперь в самой политике, а не только в коде;
- требование членства стоит **только на выдаче**: человек, выбывший из
  проекта, обязан иметь возможность отозвать собственное согласие (152-ФЗ ст. 9).

**Ядро** — `PublicationConsentsController` + `PublicationConsentsService`:
`GET/POST /v1/publication-consents`, `DELETE /v1/publication-consents/:id`.
Версия документа сверяется с действующим шаблоном, **отпечаток текста берётся с
сервера** и в теле запроса не принимается. Отзыв идемпотентен: повтор отвечает
тем же состоянием и не публикует второе событие.

**Контракты**: `disclosedFields` переведён со свободного текста (50 строк по 64
символа) на закрытый словарь из 12 значений; добавлены `PublicationConsentSchema`
и схема полезной нагрузки события выдачи — реестр `EVENT_PAYLOAD_SCHEMAS`
объявляет «verb без схемы не публикуется», а выдача согласия жила в
перечислении verb'ов без схемы.

**Клиент**: `publication.list/grant/revoke` с разбором ответа схемой;
`auth.consentTemplates()` — типизированный метод вместо сырого запроса в
`apps/auth`.

**Интерфейс**: карточка «Согласия на публичный контур» в кабинете основателя —
области выдаются по одной, состав раскрытия виден до нажатия, отзыв рядом с
выдачей, после отзыва назван крайний срок удаления проекции.

**Консоль**: операция выдачи перестала быть «ожидается 404», добавлены список и
отзыв (операций 109 → 111).

### Про утечку в чекпоинтах (единственное OPEN)

`node scripts/check-checkpoint-secrets.mjs` → **ПРОВАЛ**: фактическое значение
`DEV_TEST_USER_PASSWORD` найдено в объекте `4bc882a740` ветки чекпоинтов.

Причина известна и записана после Ф47: **пересборка пака редакции не
перезагружает живую сессию**, поэтому значения, ротированные после старта
сессии, продолжают уходить в транскрипт открытыми. Пак пересобран в этой фазе
(46 правил, `gate:redactors` зелёный) — это закрывает ПРИЧИНУ будущих утечек.

Оставшееся требует решения владельца, потому что необратимо и выходит за грант:

1. **ротация `DEV_TEST_USER_PASSWORD`** — `npm run rotate:stand-secrets`
   ротирует ВСЕ секреты стенда разом, пересоздаёт контейнеры и требует
   повторного сида; посреди сессии это ломает базу доказательств;
2. **перезапись истории ветки чекпоинтов на origin** — необратимая операция
   над удалённым репозиторием.

Оценка масштаба: пароль действует только для учётных записей `stand-*` на
локальном стенде; репозиторий приватный (`api.github.com` отвечает 404 на
анонимный запрос). Поэтому severity MEDIUM, а не HIGH.

## Ограничения

- **Графа проекта эта фаза не перестраивала.** Последний прогон `graphify` —
  2026-08-12, то есть он отстал ещё с Ф48. Перестройка вынесена на конец
  сессии одним инкрементальным прогоном; помечать этот пункт пройденным без
  прогона было бы ложным зелёным.
- **Живая проверка периметра AI-шлюза не выполнялась** — шлюз не запущен
  (LOW сетевого гейта). Это ограничение прогона, а не зелёный статус.
- **Согласие проверено ролью `founder`.** Соучредитель с иной основной ролью
  в `founders_projects` возможен схемой, но маршрут требует роль `founder`;
  случай не воспроизводился.
- **Тексты документов — плейсхолдеры.** `body_sha256` документа
  `pdn_biometric` считается от строки-заглушки, как и у пяти документов из
  M011. До production тексты утверждает юрист, хеши пересчитываются.
