## 2. Что сделано и зачем

**SEC-22 — строгий разбор токена.** Раньше принималось: `sub` — любая непустая
строка, роли — любые строки, `acr` — любая строка.

- `sub` уходит в `app.current_user_id`, на котором построены ВСЕ политики RLS.
  Произвольная строка превращалась там в ошибку приведения типа уже внутри
  запроса — то есть в 500 вместо честного отказа на входе.
- Имя роли из claim'а попадало в `app.current_roles` без проверки. Само по себе
  это не давало прав — политик с такими именами нет. Но это отложенная мина:
  политика с новым именем роли, добавленная когда угодно позже, задним числом
  расширила бы права уже выданных токенов.
- `acr` сравнивается с `'mfa'`; произвольное значение в этом поле смысла не
  имеет и теперь приравнивается к отсутствию признака.

**SEC-21 — реконнесанс-поверхность.**

- Заголовки `x-ratelimit-limit/remaining/reset` сообщали точный порог и остаток
  по каждому классу операций на КАЖДОМ успешном ответе: это позволяет подобрать
  темп перебора, оставаясь под лимитом, и заранее увидеть, какие маршруты
  ограничены жёстче. Выключены; на 429 остаётся `retry-after`.
- `GET /v1/openapi.json` отдавал анониму 175 КБ описания всех маршрутов, включая
  административные и интеграционные, с требованиями доступа. В production теперь
  требуется сессия; отказ — 404, потому что 403 подтвердил бы существование
  документа. Вне production документ остаётся открытым: он нужен разработке и
  живым прогонам.

**Дефект, найденный по ходу (M040).** M037 пометил существующие ссылки на
продукт загруженными, но правило осталось разовым UPDATE'ом: каждая НОВАЯ
ссылка создавалась без `uploaded_at` и потому не показывалась ни владельцу, ни
рецензенту. API отвечал 201 и не делал ничего видимого.

## 5. CODE-AUDIT (Шаг 2)

- **Вход:** значения из токена приведены к строгим типам и allowlist'ам до
  того, как попадут в SQL-контекст.
- **AuthN/AuthZ:** сужение ролей может только УБАВИТЬ права; проверка
  `acr === 'mfa'` от allowlist не ослабла — контрольный тест на настоящий `mfa`
  включён.
- **Раскрытие информации:** отказ описания API — 404, а не 403; заголовки
  лимита выключены; текст 429 не изменился и деталей не добавляет.
- **Инварианты данных:** правило «ссылка загружена в момент создания»
  продублировано в БД (триггер) и в сервисе — сервисный слой не единственная
  защита.
- **Зависимости:** новых пакетов не добавлено.

## 6. Ограничения (что НЕ проверено)

- **Production-поведение описания API проверено юнит-тестом контроллера**, а не
  живым production-контуром: локально `NODE_ENV=production` требует OIDC и KMS,
  которых нет.
- **OIDC-токены** по-прежнему не проверялись против реального IdP: allowlist
  ролей и требование UUID проверены на локальном адаптере и разборе полезной
  нагрузки.
- Пентест не заменяется ни статическим аудитом, ни живыми прогонами.
