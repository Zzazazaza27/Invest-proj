## 4. Что проверено живьём

Живой сценарий (`scripts/smoke-lab.mjs`) идёт через HTTP как настоящий клиент.
Напрямую в БД создаются только предусловия, для которых ещё нет API: роль
администратора и подписки (биллинг — Ф5).

Ключевые подтверждения:

- **Изоляция.** Чужой проект не читается и не изменяется (404, не 403 — статус
  не подтверждает существование объекта). Инвестор без подписки не видит
  непубличную карточку; с подпиской — видит, включая описание.
- **Тариф резолвит сервер.** Запросу 5 млн ₽ соответствует `founder_t2`;
  попытка передать `requiredPlanId` отвергается (400).
- **Условия публикации.** Без KYC — `kyc_required`; без подписки —
  `subscription_required`; рост `investment_ask` сверх лимита оплаченного
  тарифа блокирует опубликованный листинг, сумма откатывается.
- **Комплаенс.** Пользователь не одобряет себя (403), администратор не одобряет
  собственную заявку (403), повторное решение по закрытой заявке — 409.
- **Границы каталога.** Тизер не содержит ни описания, ни внутреннего статуса;
  поиск находит по заголовку и **не** находит по описанию; keyset-пагинация
  не повторяет строки; повреждённый курсор отвергается.
- **Загрузка.** Файл принят MinIO по подписанной форме (204); подмена
  Content-Type в форме отвергнута хранилищем (403); посторонний не получает
  билет на чужой проект (404); секрет хранилища в билет не попадает.
- **Журнал.** Создание, подача, публикация и снятие листинга записаны;
  hash-chain цел (0 разрывов); события выложены в outbox.
- **Партиции.** Плановое обслуживание отработало: 10 партиций журнала.

## 5. Ограничения — что НЕ проверено и почему

- **`gitleaks` локально не установлен** — секрет-скан только в CI. Прошлый
  прогон (Ф1) через Docker дал `no leaks found`; в этой сессии не повторялся.
- **Разбор материалов не реализован**: `parse_status` остаётся `queued`. Факт
  загрузки в хранилище проверен живьём, извлечение содержимого — нет (Ф7).
- **Подписки создаются фикстурой**: биллинга нет (Ф5). Отказ публикации без
  подписки при этом проверен по-настоящему — и сервисом, и триггером БД.
- **Производительность каталога не измерялась.** Индексы созданы (`GIN` по
  публичному вектору, частичные индексы каталога), но `EXPLAIN ANALYZE` на
  синтетическом объёме не прогонялся — заявлять p95 нечем.
- **OIDC против Keycloak, step-up MFA, outbox→NATS** — по-прежнему не работали
  живьём (Ф9/Ф11).
- **Статический аудит не заменяет пентест и runtime-анализ.** Пентест периметра
  и проверенное восстановление из бэкапа остаются условиями гейта A.

  `npm run gate:sast`, чтобы прогон не зависел от локали разработчика.

## 7. Рекомендации к следующей фазе (Ф5 — биллинг)

1. Начать с подписок: они уже являются условием публикации листинга, и сейчас
   это единственное место, где живой сценарий опирается на фикстуру.
2. Тарифная сетка версионируется — резолвер уже в БД; сервисный слой не должен
   дублировать пороги в TypeScript.
3. Денежные мутации — с `Idempotency-Key` и rate-limit класса `money` (лимит
   уже разведён по путям в `main.ts`).
4. Проверять биллинг тем же способом: живой прогон против запущенного сервера,
   а не только юнит-тесты.
