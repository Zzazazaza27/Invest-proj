роль, ни попасть в свой кабинет; адреса кабинетов состоят из номеров портов,

## Scope

**Единая точка входа:** `infra/nginx/default.conf`, сервис `web` (профиль `web`)
в `infra/docker-compose.yml`, команды `web:up` / `web:down`, `base` в четырёх
конфигах Vite, `basename` роутера админки, `publicUrl()` в `scripts/lib/ports.mjs`.

**Вход и регистрация:** новое приложение `apps/auth` (10 файлов),
`scripts/render-check-auth.mjs`, кнопки «Войти» и «Регистрация» на витрине.

**Ядро:** публичный `GET /v1/auth/consents/templates`, проверка версии акцепта
до вставки в `identity.service.ts`.

**Клиент:** относительный базовый адрес в `packages/api-client` и во всех семи
приложениях.

### Про 500 при регистрации

Найдено не чтением кода, а прогоном формы: браузер показал «Сервер недоступен»,
в ответе — `HTTP 500 internal_error`, в `core.log` —
`insert or update on table "consents" violates foreign key constraint
"consents_template_fk"`. Действующая версия документов в базе — `v1`, а клиент
(и консоль из Ф48) подставлял `1.0.0`, потому что узнать правильную было негде.

**Проверено на падение:** до исправления — `HTTP 500`, после — `HTTP 400
validation_failed` с перечислением всех четырёх документов и текстом «версия
1.0.0 (ru-RU) не является действующей».

## Решения и их причины

- **Вход вынесен в отдельное приложение, а не добавлен на витрину.** Витрина
  анонимна по построению (`auth: { kind: 'none' }`): сессия на публичной
  странице означала бы, что она начала работать с чужими данными. Заодно ушли
  четыре копии формы входа.
- **Роль не выбирается пользователем при входе.** Кабинет определяется ролями
  из `/v1/auth/me`; обратный порядок означал бы, что доступ решает браузер.
- **В регистрации только `founder` и `investor`.** Это контракт
  (`SelfServiceRoleSchema`), а не упрощение: рецензент, выдавший себе роль сам,
  обессмысливает экспертизу.
- **Версии документов запрашиваются перед отправкой**, а не при открытии формы:
  между открытием и нажатием кнопки условия могли обновиться.
- **Консоль через прокси не публикуется.** Маршрут к ней в конфиге означал бы,
  что однажды её выложат наружу вместе со всем остальным.

## Ограничения и принятый риск

- **HTTPS нет**: прокси слушает http на 127.0.0.1, поэтому cookie с префиксом
  `__Host-` по-прежнему невозможна — она требует Secure. Одно из трёх
  преимуществ единого origin (упрощение CSRF и снятие CORS-списка) получено,
  третье ждёт TLS.
- **CORS-список не сокращён.** За прокси он не нужен, но прогоны и прямой
  запуск по портам всё ещё им пользуются; сносить рано.
- **Регистрация проверена для роли `investor`**; путь основателя пройден
  входом существующей учётной записью, а не регистрацией.
- **Восстановление пароля и подтверждение почты не делались** — их нет ни в
  API, ни в интерфейсе.
- Прокси раздаёт `dist`: **забыв пересобрать, увидишь прошлую сборку**. Именно
  так в этой сессии кабинет открывался пустым, пока dev-серверы не перезапустили
  после смены `base`.

## Дополнение: консоль не уезжает в боевой контур

Вопрос владельца: код консоли лежит в репозитории и попадёт на VPS вместе с
`git pull` — как гарантировать, что она там не откроется.

Ответ конструкцией, а не дисциплиной: попадёт КОД, но не ПУБЛИКАЦИЯ. Она
выключена тремя независимыми способами, любого одного достаточно:

| Слой         | Механизм                                                                                                                                                                |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| сборка       | консоль убрана из `npm run build`; для неё отдельная `npm run build:console` — на сервере `apps/console/dist` не появляется                                             |
| маршрут      | `location /console/` вынесен в `infra/nginx/local/console.conf`, основной конфиг подключает его шаблоном `include /etc/nginx/local/*.conf` (пустой include — не ошибка) |
| монтирование | каталог монтирует только `infra/docker-compose.local.yml`; `scripts/infra.mjs` добавляет его вторым `-f`, если `APP_ENV`/`NODE_ENV` не боевые                           |

Неизвестное значение переменной трактуется как боевое: забытая настройка не
должна открывать наружу то, что открывать не собирались.

**Доказательства:**

| Проверка                                           | Результат                                                                      |
| -------------------------------------------------- | ------------------------------------------------------------------------------ |
| `APP_ENV=production node scripts/infra.mjs web-up` | `/console/` отдаёт витрину («LaunchBridge»), кабинеты и вход работают          |
| локальный запуск                                   | `/console/` отдаёт консоль, 109 операций отрисовано                            |
| `gate:console-private` локально                    | 6/6, exit 0                                                                    |
| `gate:console-private` **на падение**              | с возвращённой в `build` консолью — exit 1, «`npm run build` собирает консоль» |
| `render-check-console`                             | 13/13                                                                          |

Попутно найдено рендером: у консоли не был задан `base`, и по адресу
`/console/` страница отвечала 200, оставаясь ПУСТОЙ — вместо бандла приходил
HTML витрины. Исправлено (`base: '/console/'`), после чего страница
отрисовала 109 операций.
