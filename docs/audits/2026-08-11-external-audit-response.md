## Дефекты, найденные ПРИ исправлении

Правки ломали вещи, и это ловилось прогонами, а не рассуждением:

1. Ведро лимита по адресу уронило локальные прогоны (десятки регистраций с
   одного адреса) — значение для разработки поднято, механизм не ослаблен.
2. Рубеж сессий сначала отвергал ВСЕ сессии сразу после регистрации (секундный
   `iat` против миллисекундной отметки), затем оставлял токен той же секунды
   валидным навсегда, затем не давал войти заново с отозванной cookie. Три
   правки, каждая — по факту прогона.
3. Предел тела AI-шлюза в первой версии не работал: подмена `request._receive`
   внутри http-мидлвари до обработчика не доходит.
4. Гейт SAST печатал блокирующую находку и объявлял себя пройденным: `semgrep`
   без `--error` возвращает 0. Находка была настоящей — внешний вызов без
   таймаута.

## Вердикт

Вердикт внешнего аудита «не допускать в production» остаётся в силе. Закрытые
находки его не отменяют: блокирующими остаются отсутствующие OIDC-поток и
KMS-провайдер (SEC-03, CODE-01, CODE-02), а они требуют внешних систем, а не
кода в этом репозитории.
