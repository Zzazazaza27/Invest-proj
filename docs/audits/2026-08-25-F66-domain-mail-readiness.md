# SESSION AUDIT REPORT — Ф66: готовность домена к почте

Дата: 2026-08-25 · `RULES.md` Шаг 5 · закрывает проверяемую часть задачи ТЗ №2
(SPF, DKIM, DMARC, PTR, порядок полного теста доставки).

## Зачем фаза

Ф65 научила приложение отправлять письма. Доставку это не гарантирует:
письмо с корректного релея всё равно уходит в спам или отвергается, если у
домена нет DMARC и DKIM. Эти записи живут в DNS и в панели VPS-провайдера, то
есть вне кода, — и потому обязаны проверяться отдельно и наблюдаемо, иначе
«почта настроена» выясняется по жалобе «письма не приходят».

## Что зонд показал живьём

Прогон 2026-08-25, домен `vgorkakh.ru`, адрес `193.233.217.210`, релей
`smtp.timeweb.ru:2525`:

```
  OK     MX           10 mx1.timeweb.ru, 20 mx2.timeweb.ru
  OK     SPF          v=spf1 include:_spf.timeweb.ru ~all
  HIGH   DMARC        записи нет — крупные провайдеры складывают такую почту в спам
  MEDIUM DKIM         ключа нет ни для одного из проверенных селекторов
  LOW    PTR          обратной записи нет — при smarthost не мешает
  OK     релей        smtp.timeweb.ru:2525 — 220 smtp.timeweb.ru ESMTP
  OK     релей: TLS   STARTTLS объявлен
  OK     релей: вход  AUTH PLAIN LOGIN
Итог: блокирующих пробелов 1
```

Существенное: **релей отвечает и объявляет ровно то, что нужно транспорту**
из Ф65 — STARTTLS и AUTH PLAIN/LOGIN. Схема smarthost подтверждена не
рассуждением, а диалогом.

## Ограничения

- **Ни одного письма внешнему получателю по-прежнему не отправлено.** Зонд
  проверяет готовность инфраструктуры, а не факт доставки: для него нужны
  учётные данные ящика.
- **DKIM проверяется перебором частых селекторов** (`default`, `mail`, `dkim`,
  `timeweb`). Селектор задаёт провайдер, и «не найдено» здесь означает «не
  найдено среди проверенных», а не «ключа нет вовсе». Точный селектор
  передаётся `--dkim-selector`.
- Проверка выполнена с машины разработчика. С ВПС результат по DNS будет тем
  же (публичные резолверы), но повторить её оттуда перед боевым включением
  стоит.

## Техдолг

- 🔴 **Учётные данные релея и решение по провайдеру** — за владельцем; без них
  задача ТЗ №2 не закрывается полностью.
- 🟡 **DMARC и DKIM опубликовать до первого боевого письма** — иначе первые же
  письма учат почтовые сервисы считать домен спамом, и репутация
  восстанавливается неделями.
- 🟢 Зонд не проверяет длину цепочки `include:` в SPF (предел 10 DNS-запросов).
  У текущей записи один `include`, до предела далеко.
