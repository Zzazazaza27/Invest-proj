# Комплект демонстрационных данных

Восстанавливаемое наполнение платформы: шесть учётных записей
(администратор, основатели, инвесторы), пять проектов с материалами и файлами,
сценарии избранного и поддержки. Сезон, экспертиза, подписки и версии заявок
удалены из комплекта вместе с этими контурами в 2.1-W05.

Комплект нужен не для «чтобы что-то было в базе», а чтобы **полностью
восстановить наполнение** после переустановки приложения, очистки БД или
развёртывания нового окружения.

## Что где лежит

| Путь                          | Что                                                                    |
| ----------------------------- | ---------------------------------------------------------------------- |
| `people.json`                 | Учётные записи: логин, имя, роли                                       |
| `projects.json`               | Проекты: тексты, стадия, статус, листинг, сумма, материалы             |
| `files/`                      | Файлы материалов: 6 PDF и 1 PNG — то, что уходит в объектное хранилище |
| `../../scripts/seed-demo.mjs` | Загрузка, уборка, статус                                               |

Пароля в комплекте **нет**: он берётся из `DEMO_USER_PASSWORD`, а если её нет —
из `DEV_TEST_USER_PASSWORD` в `.env`. Пароль в репозитории — это пароль,
который утёк, даже если он «всего лишь демонстрационный».

## Порядок восстановления после чистой установки

```bash
npm run infra:up            # postgres, redis, nats, minio
npm run db:migrate          # схема
npm run demo:load           # данные комплекта + файлы в хранилище
npm run build && npm run web:up   # фронтенды и единая точка входа
node scripts/dev-core.mjs --detached
```

Порядок важен ровно в двух местах: миграции до загрузки (иначе таблиц нет) и
инфраструктура до всего (иначе некуда писать файлы). Ядро для загрузки **не
нужно** — комплект работает с БД и хранилищем напрямую.

Проверить, что получилось:

```bash
npm run demo:status                  # что загружено
node scripts/smoke-demo.mjs          # 42 проверки, включая восстановление
node scripts/render-check-demo.mjs   # видно ли это человеку в браузере
```

## Команды

| Команда               | Что делает                                                              |
| --------------------- | ----------------------------------------------------------------------- |
| `npm run demo:load`   | Загружает комплект. Идемпотентна: повторный запуск не плодит дубликатов |
| `npm run demo:clean`  | Удаляет **только** данные комплекта, включая файлы из хранилища         |
| `npm run demo:status` | Сколько сущностей комплекта сейчас в системе                            |

## Почему повторный запуск безопасен

Все идентификаторы выводятся из фиксированного пространства имён
`unicorn-launch/demo/v1` и ключа сущности (UUIDv5). Отсюда три следствия:

- **воспроизводимость** — на любой машине идентификаторы одни и те же, ссылки
  в заметках и скриншотах не протухают при пересоздании базы;
- **идемпотентность** — вставка идёт `ON CONFLICT (id) DO NOTHING`, «поиска
  похожей строки» нет, а именно он и порождает вторые копии;
- **точная уборка** — `clean` удаляет строки по этим же идентификаторам, а не
  «всё, что похоже на тестовое»; чужая строка под уборку не попадает по
  построению.

Прогон это проверяет фактом: после уборки общее число проектов в базе
уменьшается **ровно** на число проектов комплекта.

## Почему это не попадёт в production

`seed-demo.mjs` отказывается работать при `NODE_ENV=production` первой же
строкой и не вызывается ни из миграций, ни из сборки, ни из запуска ядра.
Демонстрационные проекты в боевом каталоге — это не мусор, а ложные
инвестиционные предложения.

## Оговорка про журнал событий

Комплект пишет данные в БД напрямую, а не через API. Поэтому в
`audit.events` его действий **нет**: журнал заполняет ядро, и подделывать
хеш-сцепленные записи ради демонстрации было бы хуже, чем их отсутствие.

Практическое следствие: история действий по объектам комплекта пуста, пока
кто-то не сделает первое действие сам. Это честное состояние, а не дефект.
