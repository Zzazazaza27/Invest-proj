## Режим работы по умолчанию: БЫСТРЫЕ ИТЕРАЦИИ

**Установлен владельцем 2026-09-20 и действует до отдельной отмены.** Причина
названа прямо: начался период мелких правок интерфейса, и тратить по 25 минут
на каждую визуальную мелочь неприемлемо.

Режим не отменяет проверок по существу — он отменяет их избыточный объём.

1. **Минимальное изменение под запрос.** Без отдельного большого плана, без
   исследования всего проекта, без попутного рефакторинга и уборки.
2. **Стенд уже работает — пользуйся им.** Собирай только затронутое приложение
   (`npm run build -w apps/<имя>`), не перезапускай окружение без причины.
   Состояние — `npm run stand:status`.
3. **После изменения — посмотреть результат в браузере.** Затронутый экран и
   его поведение. Прогоны запускать только по области влияния; полный набор
   для локальной визуальной правки не нужен.
4. **Перед длинным прогоном — оценить, нужен ли он этой задаче.** У повторной
   сборки и повторного прогона должна быть названная причина, а не привычка.
5. **Несвязанные проблемы — в TODO сейфа** (`02 Ideas and Features/03 TODO.md`), а не в текущую правку. Маленькая
   правка не превращается в новый этап.
6. **Отчёт короткий:** что изменено, где посмотреть, как проверено.
   Документация обновляется соразмерно изменению; один и тот же отчёт не
   дублируется по нескольким файлам.
7. **Сообщить сразу, если правка задевает большее.** Общая архитектура, права
   доступа, данные, платежи — об этом говорится до начала, а не после.
   Необходимые проверки ради скорости не упрощаются, но и молча в большую
   переделку переходить нельзя.

**Когда режим не действует.** Владелец скажет отдельно, что нужно глубокое
изменение функционала, — тогда возвращается подробный процесс из `RULES.md`
(план, полный набор проверок, развёрнутый отчёт).

### Как это выглядит на практике

Обычный цикл мелкой правки: прочитать нужный файл целиком → правка → **одна**
сборка затронутого приложения → посмотреть экран в браузере (в том числе
`console.errors === 0`) → короткий отчёт → коммит.

Прогоны из `scripts/render-check-*.mjs` запускать те, что трогают изменённый
экран. Найти их дешевле всего по `data-*`-атрибутам, которые правка задела:
`grep -rn "data-<атрибут>" scripts/`. Если разметка поменялась — прогон почти
наверняка знает старую и его придётся научить новой; это часть правки, а не
отдельная задача.

## Стенд

Платформа развёрнута локально под nginx, **основной адрес — http://127.0.0.1/**
(витрина в корне, `/login/`, `/lab/`, `/investor/`, `/expert/`, `/admin/`,
`/console/`). Один origin для страниц и API: сессия работает во всех кабинетах,
изображения не упираются в политику встраивания.

| Команда                          | Что делает                                             |
| -------------------------------- | ------------------------------------------------------ |
| `npm run stand:up`               | собрать, поднять, проверить                            |
| `npm run stand:up -- --no-build` | то же без пересборки                                   |
| `npm run stand:status`           | что работает, что нет и почему                         |
| `npm run stand:down`             | остановить; **данные остаются**                        |
| `npm run infra:reset`            | удалить данные — отдельная команда, сама не вызывается |

nginx раздаёт **собранную** статику из `dist`, а не проксирует на dev-серверы.
Отсюда правило: после правки интерфейса нужна сборка затронутого приложения,
иначе на экране останется прежняя версия.

Браузерные прогоны ходят через единый адрес по `FIFTH_ENTRY=web`; без этой
переменной — по dev-портам.

Учётные записи — `.local/приёмка.md` (вне Git): обстановка приёмки `priem-*` и
демонстрационный комплект `demo-*`. Пересобрать файл —
`node scripts/seed-acceptance.mjs`; загрузить комплект —
`node scripts/seed-demo.mjs load`.

## Наборы проверок

Что чем защищено — в реестре `docs/testing/registry.yaml`. Это единый
источник: читаемое представление `docs/testing/registry.md` из него
генерируется (`npm run docs:registry`), а расхождение ловит
`npm run check:registry` в CI.

**Объём проверки — по размеру правки.** Мелкая правка не требует набора
вовсе: смотрим изменённый экран. После большого изменения гоняется блок
затронутой части. Полная регрессия — **только по прямой команде Томаса**.
Общий набор после каждой правки не запускается.

| Команда                           | Когда                                                        |
| --------------------------------- | ------------------------------------------------------------ |
| `npm run suite:block block:<имя>` | после большого изменения — затронутая часть и её зависимости |
| `npm run suite:handoff`           | перед передачей работы владельцу                             |
| `npm run suite:regression`        | полная регрессия — по прямой команде Томаса                  |
| `npm run suite:isolated`          | разрушительные проверки, своё ядро и брокер                  |

Блоки: `доступ`, `вход`, `проект`, `инвестор`, `администрирование`,
`содержимое`, `события`, `надёжность`, `граница`, `безопасность`, `стенд`,
`порядок`. Блоки `эксперт`, `деньги` и `разбор-моделью` сняты вместе с их
контурами в 2.1-W05; `заявка` переименован в `проект`.

Создал или изменил саму проверку — запусти её, иначе неизвестно, работает ли
она.

**Полный CI идёт по понедельникам и перед выпуском, а не на каждый push** —
решение Томаса 05.11. Отправлять в `main` можно свободно: полный CI это не
запускает. Запуск по команде `gh workflow run ci.yml` собирает комплект выпуска,
поэтому вручную он делается только для выпуска.

**Скан секретов — локально перед каждым push, на GitHub раз в неделю** —
решение Томаса 10.11 (минуты Actions). Хук `.githooks/pre-push` запускает
gitleaks в Docker на уходящих коммитах; без Docker push остановлен. Каждый push
всё равно стоит времени — отправлять пачками.

**«CI зелёный» пишется только после просмотра фактического запуска** для
конкретного коммита (`gh run list`, `gh run view <id>`). Локальный зелёный
прогон состояния CI не подтверждает. Запуск не состоялся или ещё идёт — так
и пишется; при падении причины делятся на относящиеся к правке и прежние.

Сверх набора запускается то, что назначила матрица изменений
(`docs/testing/change-matrix.md`) для затронутой области. Правки общей
авторизации, работы с базой и общих пакетов проверяются у ВСЕХ потребителей.

Отчёт пишется в `out/suites/` и не затирает предыдущий. **Пропущенное не
считается пройденным**, а зелёный повтор не отменяет первого отказа. Чего
наборы не обещают — `docs/testing/gaps.md`.

## Элементы интерфейса

Решение владельца 2026-09-24.

- **Новые и изменяемые экраны** по умолчанию собираются из общих компонентов
  `packages/ui` и смысловых цветов скина (`var(--u-…)`), без цветов значением.
- **Локальный элемент для конкретного сценария допустим** — сделать на месте.
- **Новый заметный визуальный приём или повторяющийся элемент** — сначала
  показать владельцу на экране или в каталоге `/admin/ui`, после решения
  добавить в общий набор.
- **Граница ответственности.** Скин задаёт значения. `packages/ui` — вид и
  поведение типовых элементов. Экран — их размещение, ширину и подходящий
  размер. Общие токены отступов — там, где подходят.
- Админка сохраняет свою компоновку и плотность. Старые экраны не
  переписываются массово — переводятся, когда их всё равно правят.
- **Скин платформы** выбирает администратор в каталоге `/admin/ui`
  («Применить для всей платформы»). Новый интерфейс подключает его так же, как
  существующие: `data-skin-pending` в `index.html` и `applyPlatformSkin` в
  `main.tsx`.
- Каталог `/admin/ui` показывает реальные элементы и расхождения. Проверка
  кода и реестр старых нарушений отложены — вернуться, если согласованность
  снова начнёт расползаться.

## Границы, которые не двигаются без слова владельца

Это не стиль работы, а решения по продукту. Они действуют в любом режиме.

- **Платежей и сделок нет.** Денежный контур, биллинг (кроме списка стран
  обслуживания) и инвестиционный процесс удалены в 2.1-W05 (M150);
  возвращаются только новой проработкой, не восстановлением старого.
- **Анализа ИИ нет.** Скоринг, паспорт и AI-шлюз удалены в 2.1-W05; будущий
  анализ — отдельная проработка.
- **Почта наружу — только служебные письма.** Решение Томаса 01.11.2026
  (D-010, F-001): подтверждение почты, восстановление доступа и уведомление
  об интересе к проекту уходят на внешние адреса. Массовых и рекламных
  рассылок нет. Другие служебные события — по согласованию F-001. Доставка
  наружу с VPS пока не подтверждена: это проверка, а не готовое свойство.
- **Сезонов нет.** Удалены в 2.1-W05 целиком; если вернутся — только
  отдельной надстройкой поверх платформы, а не в её структуре.
- **На удалённый стенд ничего не выкладывается** без отдельного указания.
- **Миграции forward-only.** Применённая миграция не правится — только
  следующая.
