### 🔴 Блокирующее

### 🟡 До релиза соответствующей фазы

- **[Ф11]** Реальный OIDC-поток против Keycloak: сейчас работает только
  AUTH_MODE=local, ветка oidc покрыта лишь конфигурационными тестами.
  OIDC зелёным не помечен.
- **[Ф11]** Потребитель событий на стороне Capital: публикация работает, но
  сквозной сценарий «событие → реакция внешней системы» проверяется только
  собственным тестовым потребителем, а не реальной интеграцией.
- **[до production]** Реальный клиент KMS вместо заглушки KMS_MODE=kms.
- **[Ф11]** AI Mentor выключен (`ai.mentor.enabled = false`): ответ пользователю
  текстом требует eval-гейта Langfuse, а Langfuse не развёрнут. В Ф8 не
  включался — гейта по-прежнему нет.
- **[Ф10]** Проверка фронтендов — только в реальном рендере (Playwright), не
  вычиткой кода (`RULES.md` §2).
- **[до гейта A]** Два счёта на сделку не выставляются: начисление
  (`billing.commission_accruals`) создаётся, а `billing.invoices` требует
  PDF-документа в хранилище — генератора PDF пока нет. Подписка активируется
  администратором вручную, каждое действие с основанием в журнале.
- **[до гейта A]** Платёжного провайдера нет: `billing.payments` не заполняется,
  автопродление и просрочка подписок не работают.
- **[до гейта A]** Интеграции с банком номинального счёта нет: первый транш
  подтверждает оператор маршрутом `POST /v1/investments/tranches/confirm` с
  обязательной ссылкой на банковскую операцию и отпечатком выписки. Клиентским
  запросом это невозможно, но автоматической сверки с выпиской ещё нет —
  формат statement/webhook не утверждён (открытый вопрос №3).
- **[до production]** Документы предложения и договора — детерминированный
  текст, а не PDF. Отпечаток sha256 берётся ровно от подписываемого текста,
  поэтому вёрстка не может разойтись с подписью; но юридически ожидается PDF.
- **[Ф11]** Приём предложения и подпись договора через API вживую не пройдены:
  оба маршрута требуют step-up MFA, которого локальный адаптер не выдаёт.
  Проверен сам факт отказа (`step_up_required`); дальнейший путь — фикстурой в
  БД. Полный API-путь закрывается вместе с реальным OIDC.
- **[по фазам]** Сервисные роли `app_billing` и `app_notifications` не сконфигурированы: URL подключения появятся вместе со
  своими фазами. До тех пор `asServiceRole` для них падает с указанием
  недостающей переменной (ADR-006) — это ожидаемое fail-closed поведение.
- **[Ф10]** Управление контентом витрины (тексты лендинга, баннеры) в кабинете
  отсутствует: самой витрины на API ещё нет — она появится в Ф10.
- **[позже]** Содержимое материалов не разбирается: парсера дек нет, а ходить
  по пользовательской ссылке сервером — SSRF. В анализ попадает текст заявки и
  факт наличия материала; `parse_status` для файлов остаётся `queued`.
  Потребует Python-воркера с OCR — вернётся вместе с первой задачей, которой он
  действительно нужен (ADR-007).
- **[позже]** Эмбеддинги паспорта (`embedding VECTOR(1536)`) не заполняются:
  модели эмбеддингов нет. Поиск похожих проектов по вектору не работает и
  таковым не объявляется.
- **[позже]** Реальные LLM-провайдеры (`yandex_gpt`, `gigachat`) описаны в
  политике, но выключены: нет ключей и нет eval-гейта. Подключение обязано
  показать улучшение относительно baseline `v0.1-heuristic`, иначе оно
  бессмысленно.
- **[Ф10]** Рецензент видит карточку проекта, но не его материалы и версии:
  политики `lab.project_materials` и `lab.project_versions` эксперта не
  покрывают. Для Ф8 хватило названия проекта; полноценная работа рецензента
  потребует расширения доступа тем же принципом «по факту назначения».
- **[Ф10]** Золотой билет не погашается: `used_at` не проставляется,
  UPDATE-политики у таблицы нет. Появится вместе с переводом проектов по
  этапам сезона.
- **[Ф10]** Буткемп и финал сезона — только статусы в машине, без своей
  механики отбора и расписания.
- **[Ф10]** Управление шаблонами уведомлений — только миграцией: админского API
  для текстов уведомлений нет.
- **[Ф11]** Замерить `REFRESH MATERIALIZED VIEW CONCURRENTLY
seasons.mv_season_rating` на синтетическом объёме сезона. На единичных данных
  пересчёт мгновенный, но это ничего не доказывает.
- **[Ф11]** Замерить планы ключевых запросов (каталог, реестр договоров) на
  синтетическом объёме. Индексы созданы по спецификации, но `EXPLAIN ANALYZE`
  не прогонялся — заявлять производительность пока нечем.

- **[Ф11]** Описание API содержит ТИПЫ, но не перечень маршрутов и кодов
  ответа: маршруты выводятся из декораторов Nest, сквозной генерации пока нет.
  Неполнота объявлена в самом документе полем `x-schemas-skipped`.
- **[Ф11]** Агрегаты вознаграждения не отдаются в `GET /integration/deals`:
  `billing.commission_accruals` доступны только роли `app_billing`, и
  расширять права интеграционной роли ради них означало бы сломать границу,
  ради которой роли разделены. Нужна проекция, которую наполняет биллинг.
- **[Ф11]** Стрим NATS создаётся операционно, а не приложением: ядро только
  публикует. Манифест стрима под production не описан.
- **[Ф11]** mTLS для Integration API проверяется по заголовку от терминирующего
  прокси; самого прокси в локальном контуре нет, поэтому в dev проверка
  выключена. В production пустой `INTEGRATION_CLIENT_CERT_HEADER` не проходит
  валидацию конфигурации — приложение не стартует.

- **[Ф10]** Кабинет эксперта не написан: сделаны дизайн-система и витрина
  (Ф10a), кабинет основателя (Ф10b), кабинет инвестора (Ф10c). Админский
  кабинет существует с Ф5 и на новые примитивы пока не переведён.
- **[Ф10]** В кабинете инвестора нет экрана верификации (KYC) и step-up MFA:
  оба нужны для участия в предложениях, но регулируемый контур выключен, и
  проверить путь целиком сейчас нечем.
- **[Ф5/Ф10]** `GET /billing/invoices` и `/billing/accruals` на сервере не
  реализованы (404). Методы клиента удалены, чтобы не обещать несуществующий
  контракт; появятся вместе с выставлением счетов.
- **[Ф10]** В кабинете основателя нет загрузки материалов и ссылки на продукт:
  маршруты сервера есть, экран — нет. Роадмап тоже не выведен.
- **[Ф10]** Рендер-проверки есть у витрины и кабинетов основателя и инвестора;
  кабинету эксперта и админке они ещё нужны.

  их не заменяет.
- **Нагрузочное тестирование** до заявления любых SLO.
