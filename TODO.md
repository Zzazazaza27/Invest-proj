### 🟡 До релиза соответствующей фазы

- **[Ф11]** Реальный OIDC-поток против Keycloak: сейчас работает только
  AUTH_MODE=local, ветка oidc покрыта лишь конфигурационными тестами.
  OIDC зелёным не помечен.
- **[Ф9]** Publisher outbox → NATS: события копятся в таблице, это ожидаемое
  промежуточное состояние.
- **[Ф9]** Генерация GET /v1/openapi.json из zod-схем.
- **[до production]** Реальный клиент KMS вместо заглушки KMS_MODE=kms.
- **[Ф7]** `pip-audit` ещё не прогонялся: `apps/ai-gateway/requirements.txt`
  появится в Ф7.
- **[Ф10]** Проверка фронтендов — только в реальном рендере (Playwright), не
  вычиткой кода (`RULES.md` §2).
- **[до гейта A]** Два счёта на сделку не выставляются: начисление
  (`billing.commission_accruals`) создаётся, а `billing.invoices` требует
  PDF-документа в хранилище — генератора PDF пока нет. Подписка активируется
  администратором вручную, каждое действие с основанием в журнале.
- **[до гейта A]** Платёжного провайдера нет: `billing.payments` не заполняется,
  автопродление и просрочка подписок не работают.
- **[до гейта A]** Интеграции с банком номинального счёта нет: первый транш
  подтверждает оператор маршрутом `POST /v1/investments/tranches/confirm` с
  обязательной ссылкой на банковскую операцию и отпечатком выписки. Клиентским
  запросом это невозможно, но автоматической сверки с выпиской ещё нет —
  формат statement/webhook не утверждён (открытый вопрос №3).
- **[до production]** Документы предложения и договора — детерминированный
  текст, а не PDF. Отпечаток sha256 берётся ровно от подписываемого текста,
  поэтому вёрстка не может разойтись с подписью; но юридически ожидается PDF.
- **[Ф11]** Приём предложения и подпись договора через API вживую не пройдены:
  оба маршрута требуют step-up MFA, которого локальный адаптер не выдаёт.
  Проверен сам факт отказа (`step_up_required`); дальнейший путь — фикстурой в
  БД. Полный API-путь закрывается вместе с реальным OIDC.
- **[по фазам]** Сервисные роли `app_billing`, `app_notifications`,
  `app_integration` не сконфигурированы: URL подключения появятся вместе со
  своими фазами. До тех пор `asServiceRole` для них падает с указанием
  недостающей переменной (ADR-006) — это ожидаемое fail-closed поведение.
- **[Ф10]** Управление контентом витрины (тексты лендинга, баннеры) в кабинете
  отсутствует: самой витрины на API ещё нет — она появится в Ф10.
- **[Ф7]** Загруженные материалы не разбираются: `parse_status` остаётся
  `queued` до появления AI-воркеров. Факт загрузки в хранилище проверен живьём,
  извлечение содержимого — нет.
- **[Ф8]** Сезоны реализованы минимально: текущий сезон и переход по статусной
  машине. Рейтинг, буткемп, финал и золотые билеты — в своей фазе.
- **[Ф9]** Присвоение роли `admin` выполняется оператором напрямую в БД:
  админского API управления ролями пока нет.
- **[Ф11]** Замерить планы ключевых запросов (каталог, реестр договоров) на
  синтетическом объёме. Индексы созданы по спецификации, но `EXPLAIN ANALYZE`
  не прогонялся — заявлять производительность пока нечем.

  их не заменяет.
- **Нагрузочное тестирование** до заявления любых SLO.
