# Realm локального контура

`realm-launch.json` — экспорт realm для профиля `idp`. Файл монтируется в
`/opt/keycloak/data/import` и импортируется командой `start-dev --import-realm`.

## Почему файл лежит здесь

До Ф45 `docker-compose.yml` монтировал `./keycloak/realm-launch.json`, которого
в репозитории не было: docker создавал на его месте **каталог**, и профиль
`idp` не поднимался вовсе (HIGH внешнего аудита №2). Теперь монтируется весь
каталог, а файл существует.

## Чего в файле НЕТ и не будет

- **Секрета клиента.** `unicorn-launch-core` — confidential-клиент, его секрет
  задаётся в самом Keycloak при первом запуске и попадает в `.env` как
  `OIDC_CLIENT_SECRET`. Секрет в импортируемом realm означал бы секрет в
  репозитории.
- **Пользователей.** Учётные записи, пароли и ключи подписи живут в БД
  Keycloak (`Database_Launch.md` §2), а не в JSON под контролем версий.
- **Комментариев внутри JSON.** Keycloak отвергает импорт с неизвестными
  полями (`_comment` → `Unrecognized field`, проверено фактом), поэтому
  пояснения — здесь.

## Production

Этот realm — только для локальной разработки: `sslRequired: external`,
redirect-адреса на `localhost`/`127.0.0.1`. Боевой realm настраивается
отдельно вместе с production-инфраструктурой и в репозиторий не попадает.

## БД Keycloak

С Ф45 IdP ходит в кластер под **своей** ролью `keycloak` (владелец только
своей БД), а не под `unicorn_owner` — владельцем всех схем платформы. Роль и
БД создаёт идемпотентный сервис `keycloak-db-init`: init-скрипты Postgres
выполняются только при первой инициализации тома, поэтому на уже поднятом
стенде роли иначе не появилось бы (проверено фактом — Keycloak падал с
`password authentication failed for user "keycloak"`).
