# Опись зоны 5espace.com

Составлена 2026-11-02, во время отказа DNS Beget (инцидент
`docs/incidents/2026-11-02-beget-dns.md`). Самой зоны в Beget сейчас не
видно, и она может вернуться из резервной копии не целиком. Здесь — то, что
известно с нашей стороны: VPS, Caddy, HestiaCP. После восстановления NS у
Beget каждую запись сверить запросом к их NS. Расхождения — в этот файл, а
затем в `infra/dns/zones/5espace.com.zone` для схемы со скрытым первичным.

NS: ns1/ns2.beget.com, ns1/ns2.beget.pro. Вторичных у других компаний нет.

| `5espace.com`, `panel`    | A   | 193.233.217.210                   | 600 |

| `5espace.com`             | MX  | 10 `mail.5espace.com.` — свой VPS | 300 |
| `5espace.com`             | TXT | `v=spf1 ip4:193.233.217.210 ~all` | 300 |

запросе нет. Таблица ниже — прежние предположения: MX и SPF в них устарели.

## Сверить с Beget после восстановления — значения неизвестны

| Имя              | Тип       | Что известно                                                                  |
| ---------------- | --------- | ----------------------------------------------------------------------------- |
| `5espace.com`    | MX        | входящая почта — у Beget (память: «DNS и входящая почта — в Beget»)           |
| `5espace.com`    | TXT (SPF) | отправка — exim на VPS (193.233.217.210); в SPF должны быть VPS и почта Beget |
| `_dmarc`         | TXT       | неизвестно                                                                    |
| прочие TXT       | TXT       | подтверждения сервисов, если есть                                             |
| CAA              | CAA       | неизвестно; Caddy получает сертификаты Let's Encrypt                          |
| TTL всех записей | —         | неизвестно                                                                    |

## Проверка после восстановления

Запрос `ANY` не выгружает зону и может вернуть неполный ответ (RFC 8482).
Порядок:

1. **Выгрузка из панели Beget** — список всех записей зоны (делает Томас или
   Маус через `dns/getData` API). Это основа описи.
2. **Сверка каждого имени и типа** из выгрузки и из таблиц выше — отдельными
   запросами к каждому NS Beget, с VPS (со своей машины исходящие на порт 53
   режутся):

   ```
   for t in SOA NS A AAAA MX TXT CAA; do
     docker run --rm --network host cznic/knot:3.4 kdig @ns1.beget.com 5espace.com $t +noall +answer
   done
   for n in www files panel mail mail._domainkey _dmarc; do
     for t in A AAAA CNAME TXT; do
       docker run --rm --network host cznic/knot:3.4 kdig @ns1.beget.com $n.5espace.com $t +noall +answer
     done
   done
   ```

3. Расхождения между выгрузкой, ответами NS и нашей стороной — разобрать
   до перехода. **Без подтверждённых MX и почтовых TXT (SPF, DKIM, DMARC)
   переключение не проводится.**
