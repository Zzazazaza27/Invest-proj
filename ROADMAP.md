# LaunchBridge — план дальнейшей реализации по направлениям

> **Статус документа: исторический (аудит до Ф0).** Здесь зафиксирован вердикт
> по исходному прототипу-лендингу и первый набросок плана со стеком
> FastAPI + Celery. Реализация пошла другим путём: NestJS-монолит,
> PostgreSQL со схемами и RLS, монорепо (`Architect_Launch.md`, ADR-001).

> **Актуальные источники правды:** дорожная карта — `Architect_Launch.md` §9,

> направлений и постановка задач; конкретные технологии и сроки в них
> **не действуют**.

_Проект: `IT_Platforma` (внутреннее имя `launchbridge-complete-mvp`). Документ описывает путь от текущего лендинга-прототипа до работающей платформы. Стек и решения подобраны под твой рабочий контур: FastAPI + Celery + PostgreSQL + Redis + Docker._

## 0. Где мы сейчас (аудит) и вердикт

**Что реализовано:**

- Одностраничный фронт на React 18 + Vite 6, весь UI в одном `App.jsx` (~13 КБ).
- Полноценный лендинг: hero, «LaunchBridge Show», каталог проектов, блок Shorts, категории, преимущества, финальный CTA, модалки входа/регистрации.
- Аккуратная вёрстка и стили (`styles.css`, ~18 КБ), фирменный фиолетовый `#6547ef`, адаптив, иконки инлайн-SVG.

**Чего нет (и это ядро продукта):**

- Нет бэкенда. `README` упоминает, что API-сервер на `localhost:4000` был отдельно и сейчас не используется.
- Данные захардкожены (`projects`, `shorts`, `categories` — статические массивы). Ничего не создаётся и не сохраняется.
- Формы входа/регистрации — «демонстрационные», без реальной аутентификации.
- Нет роутинга (нет страниц проекта, профиля, кабинета), нет i18n (кнопка RU не работает), поиск/фильтры/категории — визуальные заглушки.
- Нет медиа-пайплайна для Shorts, нет сделок, нет платежей, нет модерации, нет аналитики, нет CI/деплоя.

**Вердикт.** Сейчас это качественный **дизайн-прототип посадочной страницы**, а не MVP платформы. Он отлично годится как витрина для питча, но «дальнейшая реализация» — это по сути постройка продукта с нуля на этом визуальном фундаменте. Хорошая новость: фронт можно переиспользовать почти полностью, ядро работы — бэкенд, аутентификация и транзакционные сценарии. Ниже — план по 13 направлениям и дорожная карта по фазам.

## 1. Целевая архитектура (одним экраном)

```
Браузер (React SPA)
  │  HTTPS / JSON
  ▼
Nginx (TLS, статика, reverse-proxy)
  │
  ▼
FastAPI (REST API, auth, бизнес-логика)
  ├── PostgreSQL      — основное хранилище (пользователи, проекты, сделки)
  ├── Redis           — кэш, сессии/JWT-блэклист, брокер задач, rate-limit
  ├── Celery workers  — видео-транскодинг, письма, индексация, AI-джобы
  ├── MinIO / S3      — файлы, обложки, видео Shorts
  ├── Meilisearch     — полнотекстовый поиск и фильтры каталога
  └── pending_actions — таблица-барьер для необратимых действий (сделки/выплаты)
```

Принцип: монолитный FastAPI-бэкенд на старте (быстрее итерации), выделение сервисов (медиа, поиск, платежи) — только когда нагрузка это оправдает. Всё в Docker Compose, деплой на VPS.

## 2. Модель данных (ядро, для ориентира)

| Сущность | Назначение |
|---|---|
| `user` / `profile` | учётка + роль: `founder`, `investor`, `team`, `moderator`, `admin` |
| `project` | карточка проекта: заголовок, описание, стадия, оценка, статус (ищет инвестора/партнёра/команду и т.д.) |
| `project_media` | обложки, презентация, галерея |
| `short` | короткое видео-питч (≤60 сек) + метаданные, привязка к проекту |
| `category` / `tag` | направления (AI, SaaS, FinTech, Marketplace…) |
| `interest` / `deal` | интерес инвестора → переговоры → сделка; статусная машина |
| `thread` / `message` | переписка founder ↔ investor, deal room |
| `verification` | KYC/проверка проекта и участника, уровень доверия |
| `transaction` | платежи: листинг, premium, success fee, эскроу |
| `pending_actions` | физический барьер для необратимых операций (подтверждение выплат/сделок) |
| `notification` | email / push / in-app |
| `event` | продуктовая аналитика (просмотры, клики, воронка) |

## 3. План по направлениям

Для каждого направления: **Цель → Ключевые задачи → Приоритет → Tech-выбор**. Приоритет: 🔴 критично для MVP · 🟡 важно для v1 · 🟢 масштаб/позже.

### A. Фронтенд-архитектура 🔴
**Цель:** превратить один `App.jsx` в поддерживаемое приложение со страницами и реальными данными.
- Разбить монолит на компоненты и папки (`components/`, `pages/`, `features/`, `api/`, `hooks/`).
- Ввести роутинг: `React Router` — страницы `/`, `/projects`, `/projects/:id`, `/shorts`, `/investors`, `/profile`, `/dashboard`, `/auth`.
- Слой данных: `TanStack Query` (React Query) для запросов к API, вместо статических массивов.
- Формы и валидация: `React Hook Form` + `zod`.
- i18n: `i18next` (RU/EN как минимум) — кнопка языка должна реально работать.
- Дизайн-система: вынести токены (цвета, типографика, spacing) из `styles.css`; решить — оставить чистый CSS или перейти на Tailwind/CSS-модули (рекомендую **Tailwind** для скорости).
- SEO/шеринг: мета-теги, OpenGraph для карточек проектов (later — SSR/prerender через Vite SSR или миграция на Next.js, если органика будет важна).

### B. Бэкенд и API 🔴
**Цель:** поднять API, который отдаёт и принимает реальные данные.
- FastAPI-скелет: структура `app/{api,models,schemas,services,workers,core}`, `pydantic` v2.
- ORM + миграции: `SQLAlchemy 2.0` + `Alembic`.
- CRUD и эндпоинты: проекты, категории, Shorts, профили, интересы/сделки, сообщения.
- Пагинация, сортировка, фильтрация на уровне API.
- Валидация, обработка ошибок, единый формат ответов, OpenAPI-схема (FastAPI даёт из коробки).
- Celery + Redis как брокер для фоновых задач (письма, транскодинг, индексация).
- Тесты: `pytest` на ключевые сценарии.

### C. Аутентификация, роли, профили 🔴
**Цель:** реальные аккаунты и разделение founder/investor.
- Регистрация/вход, хеширование паролей (`argon2`), JWT (access+refresh) или сессии в Redis.
- OAuth-вход (Google/VK) — у тебя уже есть опыт интеграции VK API, переиспользуй.
- Подтверждение email, восстановление пароля.
- Ролевая модель и права (RBAC): founder публикует, investor смотрит/пишет, moderator проверяет.
- Онбординг по роли (разные шаги для основателя и инвестора).
- Профили: публичная страница проекта/основателя, кабинет.

### D. Каталог, поиск, рекомендации 🟡
**Цель:** оживить поиск, фильтры и категории (сейчас — заглушки).
- Реальные фильтры: категория, стадия, размер запроса, статус, гео.
- Полнотекстовый поиск: старт на Postgres FTS, при росте — **Meilisearch** (быстрый, простой, релевантный).
- Лента/сортировка: новизна, популярность, «рекомендовано».
- Рекомендации: на старте — правила (по категориям/интересам), позже — ML-матчинг (см. направление I).
- Сохранённые проекты (bookmark сейчас неактивна) и подписки на категории.

### E. Медиа и Shorts 🟡
**Цель:** превратить статичные плитки Shorts в настоящий видео-формат — это отличительная фича.
- Загрузка видео (multipart / прямой аплоад в S3 по presigned URL).
- Транскодинг через **ffmpeg в Celery-воркере**: нормализация, превью-постер, несколько разрешений (HLS).
- Хранилище: **MinIO** (S3-совместимо, self-hosted) + раздача через CDN/nginx.
- Плеер-лента (вертикальные Shorts, автоплей, свайп), счётчики просмотров.
- Модерация загружаемого контента (см. F).

### F. Сделки, безопасность, доверие (Trust & Safety) 🟡
**Цель:** сделать «Безопасные сделки» из лендинга реальной механикой.
- Статусная машина сделки: интерес → переписка → NDA → условия → закрытие.
- Верификация проектов и участников (уровни доверия, бейджи «проверено»).
- **`pending_actions` как физический барьер** для необратимых операций (подтверждение выплаты/закрытия сделки двойным действием) — переиспользуй свой паттерн из Agentic OS.
- Эскроу/гарантийные сделки (интеграция с провайдером или ручной арбитраж на старте).
- Модерация, жалобы, антифрод, разрешение споров.

### G. Коммуникации и уведомления 🟡
**Цель:** дать основателям и инвесторам общаться внутри платформы.
- Личные сообщения / deal room (WebSocket или polling на старте).
- Email-уведомления (транзакционные: новый интерес, сообщение, статус сделки) — через Celery.
- Push/in-app уведомления.
- Дайджесты (новые проекты по подписке инвестора).

### H. Монетизация и платежи 🟡
**Цель:** заложить, как платформа зарабатывает, и как ходят деньги.
- Модель дохода (рекомендую комбинацию): premium-подписка для инвесторов, платное продвижение/подсветка проектов, success fee с закрытых сделок, платная верификация.
- Платёжные интеграции с учётом мульти-юрисдикции (РФ + Грузия + ОАЭ — твоя рабочая тема): роутинг платежей под регион.
- Биллинг, инвойсы, история транзакций, вебхуки провайдеров.
- Тарифы и лимиты (freemium: N проектов бесплатно и т.д.).

### I. AI-функции 🟢
**Цель:** усилить платформу твоим ключевым преимуществом — AI.
- Матчинг founder ↔ investor по эмбеддингам (интересы, категории, стадия).
- Скоринг/оценка проекта: авто-анализ описания, флаги качества, подсказки по улучшению карточки.
- Авто-генерация черновика карточки проекта из свободного текста/питча.
- Анализ Shorts: авто-субтитры, авто-теги, краткое саммари питча.
- Ассистент-редактор для основателя (переиспользуй failover-цепочку из 3 LLM-провайдеров).

### J. Данные, аналитика, админка 🟡
**Цель:** видеть, что происходит, и управлять платформой.
- Продуктовая аналитика: события (просмотры, клики, воронка регистрации → публикация → сделка).
- Админка/модераторская панель: очередь верификаций, жалобы, управление контентом.
- Дашборды KPI (можно быстро собрать на metabase/superset поверх Postgres).

### K. Инфраструктура, DevOps, безопасность 🔴 (частично уже на v1)
**Цель:** предсказуемый деплой и безопасность.
- `docker-compose` для всего стека (api, worker, db, redis, minio, meili, nginx).
- Окружения `dev`/`staging`/`prod`, `.env`-конфиги, секреты.
- CI/CD (GitHub Actions): линт, тесты, сборка, деплой на VPS.
- Nginx + TLS (Let's Encrypt), бэкапы Postgres/MinIO, мониторинг (uptime, логи, Sentry).
- Базовая безопасность: rate-limit, CORS, защита от брутфорса, валидация загрузок, security-заголовки. (Заметил в проекте `.semgrep` — доведи SAST до рабочего состояния в CI.)

### L. Юридическое и комплаенс 🟡
**Цель:** легально принимать пользователей, данные и деньги.
- Оферта/ToS, политика конфиденциальности, cookie-согласие.
- 152-ФЗ (персональные данные РФ): хранение ПДн, согласия.
- Дисклеймеры по инвестициям (платформа — не инвест-советник; связь проектов и инвесторов, а не привлечение средств от неквал. инвесторов без оговорок).
- Мульти-юрисдикционная структура под платежи (РФ/Грузия/ОАЭ).

### M. GTM, наполнение и рост 🟡
**Цель:** решить проблему «пустого маркетплейса» (двусторонняя ликвидность).
- Сначала наполнить сторону предложения: 30–100 реальных проектов (в т.ч. можно посеять своими продуктами из портфеля).
- Затем привлекать инвесторов/партнёров под уже готовый каталог.
- Контент-канал на Shorts (короткие питчи как виральный формат — у тебя есть опыт с виральными видео и VK).
- SEO под страницы проектов, партнёрства с акселераторами/сообществами.

## 4. Дорожная карта по фазам

| Фаза | Срок (ориентир) | Что входит (направления) | Результат |
|---|---|---|---|
| **Фаза 0 — Фундамент** | ~1–2 недели | A (рефакторинг+роутинг), B (скелет API), K (docker-compose, dev-окружение) | Фронт ходит в API, отдаётся реальный список проектов из БД |
| **Фаза 1 — MVP-транзакции** | ~4–6 недель | C (auth+роли), B (CRUD проектов/интересов), D (поиск/фильтры базово), G (email-уведомления), L (ToS/152-ФЗ), M (посев 30+ проектов) | Пользователь регистрируется, публикует проект, инвестор находит и оставляет интерес → написать основателю |
| **Фаза 2 — Медиа + Доверие** | ~4–6 недель | E (Shorts-видео пайплайн), F (сделки + верификация + pending_actions), G (сообщения/deal room), J (модераторская админка) | Живой формат Shorts, безопасные сделки со статусами, верификация, модерация |
| **Фаза 3 — Деньги + AI + Масштаб** | далее | H (монетизация+платежи), I (AI-матчинг/скоринг), D (Meilisearch/рекомендации), J (аналитика/дашборды), K (CI/CD, мониторинг, бэкапы) | Платформа зарабатывает, умный матчинг, готовность к росту |

## 5. Критический путь (что первым и почему)

Порядок не по «удобству», а по зависимостям и созданию ценности:

1. **Бэкенд + БД + один реальный эндпоинт** (B, K) — без этого всё остальное держится на моках.
2. **Аутентификация и роли** (C) — до неё нельзя ни публиковать, ни писать, ни делать сделки.
3. **CRUD проектов + рефакторинг фронта на API** (A, B) — сердце продукта.
4. **Поиск/фильтры + первый контент** (D, M) — чтобы каталог был не пустым и полезным.
5. **Сообщения/интерес → сделка** (F, G) — момент, где создаётся реальная ценность (founder встречает investor).
6. Дальше — **Shorts-видео, монетизация, AI** как усилители.

Всё, что помечено 🔴, — это Фаза 0–1. Не распыляйся на AI и Shorts-видео, пока не работает базовый цикл «опубликовал → нашли → написали».

## 6. Ближайшие 2 недели — конкретные шаги

- [ ] Завести отдельный репозиторий/папку `backend/`, поднять FastAPI + Postgres + Redis в `docker-compose`.
- [ ] Alembic: первая миграция — таблицы `user`, `project`, `category`, `short`.
- [ ] Эндпоинты `GET /projects`, `GET /projects/{id}`, `GET /categories`, `GET /shorts` (сначала read-only).
- [ ] Залить текущие моковые данные в БД как сид — чтобы фронт сразу ожил на реальном API.
- [ ] Фронт: добавить `React Router` + `TanStack Query`, заменить статические массивы на запросы к API, сделать страницу проекта `/projects/:id`.
- [ ] Auth: `POST /auth/register`, `POST /auth/login`, JWT, защищённый `GET /me`; подключить реальные модалки входа/регистрации.
- [ ] `POST /projects` (создание проекта основателем) + форма публикации с валидацией.
- [ ] Включить i18n-каркас (RU по умолчанию, EN-заглушка) и починить переключатель языка.
- [ ] Настроить `.env`, CORS, базовый rate-limit; довести `.semgrep` до прогона в CI.

Это даёт к концу двух недель работающий цикл: **регистрация → публикация проекта → просмотр каталога и карточки из реальной БД.**

## 7. Риски и как их снять

- **Пустой маркетплейс (нет ликвидности).** Снятие: посев проектов вручную + своими продуктами, инвесторов зовём под готовый каталог (направление M — не откладывать).
- **Расползание скоупа (AI/Shorts/платежи сразу).** Снятие: жёстко держать критический путь §5, 🔴 раньше 🟡/🟢.
- **Юр-риски вокруг инвестиций и ПДн.** Снятие: ранние ToS/дисклеймеры (L) до публичного запуска, позиционирование «связываем», а не «привлекаем средства».
- **Стоимость медиа (видео).** Снятие: MinIO + собственный VPS, ленивый транскодинг, лимиты на размер/длительность Shorts.
- **Модерация и фрод при росте.** Снятие: верификация + `pending_actions` + очередь модерации с самого начала Фазы 2.

---

## 8. Метрики успеха по фазам

- **Фаза 0:** фронт получает данные из API; 0 хардкод-массивов.
- **Фаза 1:** N зарегистрированных, ≥30 опубликованных проектов, первые «интересы» инвесторов, конверсия регистрация → публикация.
- **Фаза 2:** доля верифицированных проектов, число диалогов founder↔investor, первые закрытые сделки.
- **Фаза 3:** MRR/выручка, activation-rate матчинга, retention инвесторов, объём и удержание на Shorts.
